# PE Loop · 셀프 리뷰 PWA

안드로이드 태블릿을 거치해 쓰는 초등 체육 수업용 지연 카메라 MVP입니다. 카메라 영상은 브라우저 안에서 처리하며 서버에 업로드하지 않습니다.

상세 작업·예상 일정·완료 기준은 [구현 계획표](docs/implementation-plan.md)에 정리했습니다. 현재 코드는 실제 태블릿 검증 전인 초안입니다.

0·1·2·3·4단계의 현재 진행 상태는 [작업 상태표](docs/task-status.md), 화면 흐름은 [A01](docs/A01-screen-flows.md), 상태·모듈 설계는 [A02](docs/A02-state-and-modules.md), 기기 지원 기준은 [A03](docs/A03-support-matrix.md)에 기록합니다.

## 현재 기능

- 전면 카메라를 480×270, 무음으로 캡처해 최근 5분의 프레임을 메모리에 순환 보관합니다.
- 교사가 1~60초 지연 시간을 설정하면 해당 시점의 장면을 셀프 리뷰 화면에 보여줍니다. 기본 지연 시간은 20초입니다.
- 학생이 최근 장면의 끝 시점과 5~30초 길이를 골라 클립으로 저장합니다. 기본 길이는 15초입니다. 선택한 시작·끝 시각을 표시하고 영상이 부족하거나 중간이 끊긴 구간은 저장하지 않습니다.
- 학생 이름과 번호를 입력해 클립을 구분합니다. 저장된 WebM 클립은 IndexedDB에 로컬 저장되고 앱을 열거나 목록을 확인할 때 7일 만료를 정리합니다.
- 교사는 첫 실행 시 6자리 PIN을 만듭니다. 수업을 시작할 때 PIN을 입력하고, 저장된 클립 목록을 열 때도 PIN을 입력합니다. 영상과 학생 이름·번호는 PIN에서 파생한 AES-GCM 키로 암호화합니다. 잘못된 PIN이 기존 수업 키를 지우지 않고, 목록 닫기와 명시적 잠금은 별도로 처리합니다.
- PWA 셸은 버전별 서비스 워커 캐시로 오프라인에서 열 수 있습니다. 새 버전은 수업 화면을 강제로 새로고침하지 않고 대기하며, 앱을 완전히 닫았다 다시 열 때 적용됩니다. 카메라와 보안 저장 기능의 초기 설정에는 HTTPS가 필요합니다.
- 가로·세로 태블릿 화면, 48 CSS px 이상의 주요 터치 영역, 짧은 화면의 스크롤 대화상자와 가상 키보드 대응을 적용했습니다. 실제 A9+ 키보드·햇빛·회전 검증은 남아 있습니다.

## 이번 안정화 작업

- 촬영·구간 선택·저장 중 상태를 명시하고 저장 중 중복 클릭, 구간 수정, 닫기를 차단합니다.
- 미리보기와 인코딩용 캔버스를 분리합니다. 선택 화면을 열 때 버퍼를 스냅샷으로 고정해 입력 중 장면이 이동하지 않습니다.
- WebCodecs VP8 인코더와 WebM 작성기로 원본 시각을 10fps 출력 시각에 맞춥니다. 선택한 5·15·30초가 실제 파일에서도 같은 길이가 되며, 출력의 최대 길이는 30초입니다. 이 인코더를 지원하지 않는 기기에는 업데이트·지원 안내를 표시합니다.
- 저장 중에는 명시적으로 취소할 수 있습니다. DB 커밋 중에는 취소 버튼을 비활성화하고, 실패 시 같은 선택과 입력으로 재시도합니다. 이름은 1~24자, 번호는 1~9999 범위의 숫자로 확인합니다.
- 설정한 지연 시간이 쌓일 때까지 남은 시간을 표시합니다. 저장 중 앱이 백그라운드로 이동하면 결과를 저장하지 않고 재시도를 안내합니다.

## 개발 검증

`node --test tests/*.test.cjs`로 버퍼·시각 선택·WebM·PIN·만료 회귀를 확인합니다. Playwright가 설치된 개발 환경에서는 `node tests/browser-layout.cjs`, `node tests/browser-prep.cjs`, `node tests/browser-pwa.cjs`로 태블릿 레이아웃·터치 영역·교사 준비 상태·설치 셸·오프라인·버전 업데이트를 검증합니다. `CHROMIUM_PATH`로 사용할 Chromium 경로를 지정할 수 있습니다. `browser-smoke`와 `browser-clips`의 실제 WebM 패킷 검사에는 `ffprobe`가 필요합니다. 이 검증은 실제 Android 기기 성능이나 설치 검증을 대신하지 않습니다.

## 설치와 사용

정적 파일을 HTTPS가 적용된 웹 서버에 올린 뒤 안드로이드 태블릿의 Chrome에서 엽니다. 카메라 권한을 허용하고 화면의 **앱 설치** 버튼을 누르거나, 버튼이 없으면 Chrome 오른쪽 위 **⋮ → 앱 설치** 또는 **홈 화면에 추가**를 선택합니다. 설치 후에는 홈 화면의 PE Loop 아이콘으로 standalone 실행합니다. 로컬 미리보기는 `localhost`에서 열 수 있습니다. HTTPS 배포 주소와 호스팅 방식은 아직 정해지지 않았습니다.

서비스 워커는 정적 셸 14개만 버전별 캐시(`pe-loop-shell-<version>`)에 저장합니다. 클립·학생 정보·PIN·암호화 키·IndexedDB 데이터는 캐시하지 않습니다. 새 버전이 준비되면 수업 중에는 배너만 표시하고, **나중에**로 닫을 수 있습니다. 새로고침이나 즉시 활성화를 강제하지 않으며, 앱을 완전히 닫았다 다시 열면 브라우저의 기본 수명주기에 따라 새 버전이 적용됩니다. 서버 연결이 끊겨도 이미 캐시된 셸은 열리며, 캐시 준비에 실패하면 안내와 **다시 시도** 버튼을 표시합니다.

수업 중에는 화면이 켜져 있고 앱이 전면에 있어야 5분 버퍼가 안정적으로 유지됩니다. 다른 앱으로 전환하거나 화면을 잠그면 Android가 카메라/프레임 수집을 중단할 수 있습니다.

앱이 화면에서 벗어나거나 카메라 연결이 끊기면 촬영을 중단하고 실시간 버퍼를 비웁니다. 복귀 후 **촬영 다시 시작**을 눌러 새 촬영을 시작합니다. 새 촬영과 이전 촬영 사이의 중단 구간을 이어 붙이지 않습니다. 이미 선택한 클립은 선택 화면을 닫기 전까지 유지되므로 저장 중단 후 같은 구간을 다시 저장할 수 있습니다. 기기가 지원하면 촬영 중 화면 꺼짐 방지도 요청합니다.

실시간 프레임 버퍼는 5분·3,001프레임·80MiB 중 먼저 도달하는 제한을 적용합니다. 선택 중인 영상 스냅샷과 브라우저 자체의 메모리는 이 프레임 예산과 별도입니다. 실제 기기 전체 메모리·발열 검증은 남아 있습니다. 기준 기기는 **갤럭시 탭 A9+**이며, 실제 사용할 모델의 메모리 용량·Android·Chrome 버전은 확보 후 기록합니다.

## 추가 검증

- `node --test tests/*.test.cjs`: 시각 선택과 버퍼 제한 회귀 검증. 40분 시각을 합성한 검사는 실제 40분 실행이나 Android 성능 시험이 아닙니다.
- `node tests/browser-smoke.cjs`: Playwright·Chromium·ffprobe가 있는 개발 환경에서 가상 카메라의 5·15·30초 저장, 출력 파일의 실제 패킷 시각 및 무음 여부 확인.
- `node tests/browser-clips.cjs`: Playwright·Chromium·FFmpeg 환경에서 선택 시각·미리보기 혼입·실제 출력 장면·취소·저장 실패·재시도 검증.
- `node tests/browser-camera.cjs`: 권한·기기 오류, 뒤늦은 카메라 응답 정리, 연결 중단·복귀, 저장 중단 후 재시도 확인. 화면 전환 검사는 결정적인 이벤트 처리 검사이며 Android OS 동작 검증은 아닙니다.
- `node tests/browser-delay.cjs`: 가상 카메라에서 1·20·60초 지연, 초기 대기, 지연 변경, 과거 프레임과 표시 영상의 픽셀 일치 확인. 60초 버퍼가 모일 때까지 실제로 기다립니다.
- `node tests/browser-layout.cjs`: 1280×800·800×1280 레이아웃, 겹침·가로 스크롤, 48px 터치 영역, 대비·글자 크기, 800×480 대화상자와 포커스 가시성 확인.
- `node tests/browser-prep.cjs`: 시작 전 권한 요청 0회, idle→연결→준비→재생→중단→재시도 상태와 지연 표시 확인.
- `node tests/browser-pwa.cjs`: 셸 전체 캐시, 캐시 실패·재시도, 오프라인 재실행, v6→v7 대기 worker, 무관 캐시 유지와 업데이트 전 PIN·클립 보존 확인.

측정 결과와 남은 제약은 [검증 기록](docs/validation-2026-11-05.md)과 [4단계 검증 기록](docs/stage-4-validation.md)에 정리했습니다. 현재 Windows 개발 환경에는 `ffprobe`가 없어 `browser-smoke`·`browser-clips`의 실제 패킷 검사를 완료하지 못했습니다. Playwright는 앱 의존성으로 추가하지 않았습니다.

## 저장 및 개인정보

클립 목록은 현재 태블릿의 IndexedDB에만 존재합니다. PIN은 학생 공유용이 아니라 교사용으로 관리해야 합니다. PIN을 잊으면 암호화된 클립과 이름·번호를 복구할 수 없습니다. PIN 분실 화면에서 새 PIN 두 번과 ‘모두 삭제’ 확인 문구를 입력해 모든 기존 클립을 삭제하고 초기화할 수 있습니다. 클립 삭제와 새 PIN 설정은 한 트랜잭션으로 처리하며, 취소·실패 시 두 변경을 함께 취소합니다. 앱 데이터 삭제, 브라우저 저장 공간 정리 또는 태블릿 교체는 로컬 클립을 제거합니다.

이 MVP는 학생 명단, 계정, 동기화, 클라우드 백업, NEIS 연동을 포함하지 않습니다. PWA 설치와 카메라 동작, WebCodecs VP8 인코딩은 실제 학교 Android 태블릿과 Chrome 버전에서 현장 점검이 필요합니다.

2단계의 구현·검증 범위와 실제 기기에 남은 확인 항목은 [클립 선택·저장 검증](docs/stage-2-validation.md)에 정리했습니다.

## 3단계 데이터 보호

PIN 설정과 암호화된 클립은 IndexedDB 버전 2에 보관합니다. 이전 버전의 PIN 설정과 암호문은 보존 이전하며, localStorage에는 지연 설정 등 비밀이 아닌 값만 둡니다. 목록에서는 손상 파일을 격리하고 고른 영상 하나만 복호화합니다. 닫기·다른 영상 선택 시 플레이어와 Blob URL을 정리합니다.

만료 파일은 목록·재생 전에 정리하고, 실행 중 다음 만료 시각에도 확인합니다. 기기 시계와 OS 실행 상태에 의존하므로 앱이 닫힌 동안 정시 삭제를 보장하지 않습니다. 생성·만료 정보가 손상된 항목은 재생을 막고 교사가 삭제할 수 있도록 표시합니다.

교사 설정에서 사이트 저장 공간의 추정값과 정리 방지 상태를 확인할 수 있습니다. 이는 7일 보관 보장이 아니며 브라우저 데이터 삭제·기기 초기화로 자료를 잃을 수 있습니다. DB 업데이트가 막히면 다른 이전 앱 탭을 닫고 다시 실행해 주세요.

검증 명령:

- `node tests/browser-data.cjs`: PIN 수명·손상 파일·늦은 응답·삭제·만료·저장 공간 오류.
- `node tests/browser-vault-migration.cjs`: 이전 버전 데이터 이전과 PIN 설정 손실·초기 설정 실패·취소.
- `node tests/browser-reset.cjs`: 명시적 초기화·원자적 실패 복구·다른 탭의 오래된 키 거부.

전체 근거와 실제 기기에 남은 항목은 [3단계 검증 기록](docs/stage-3-validation.md)을 확인하세요.

## 4단계 PWA·태블릿 UX

서비스 워커는 `pe-loop-shell-<version>` 이름의 캐시에 앱 셸 14개만 저장합니다. 설치는 모든 셸 파일이 준비되어야 성공하며, 실패하면 부분 캐시를 남기지 않습니다. 활성화 시에는 같은 접두사의 이전 버전 캐시만 삭제하고, 다른 앱 캐시와 IndexedDB는 건드리지 않습니다. `skipWaiting()`과 `clients.claim()`을 사용하지 않으므로 촬영·버퍼링·인코딩·저장 중인 화면을 강제로 전환하지 않습니다.

캐시에는 영상·학생 이름·번호·PIN·암호화 키가 들어가지 않습니다. 외부 폰트·CDN·분석 스크립트도 사용하지 않습니다. 탐색 요청은 현재 활성 버전의 `index.html`에서 응답하고, 캐시가 없고 네트워크도 실패하면 외부 리소스가 없는 오프라인 안내 화면을 보여줍니다.

검증 명령:

- `node tests/browser-layout.cjs`: 가로·세로 레이아웃, 터치 영역, 대비, 짧은 화면 대화상자.
- `node tests/browser-prep.cjs`: 교사 준비 상태와 명시적 카메라 시작.
- `node tests/browser-pwa.cjs`: 셸 캐시, 오프라인, 설치 안내, 버전 업데이트와 데이터 보존.

실제 A9+에서의 설치, 비행기 모드, 가상 키보드, 햇빛 가독성, 업데이트 적용 시점과 HTTPS 배포는 아직 검증하지 않았습니다. 자세한 결과와 남은 항목은 [4단계 검증 기록](docs/stage-4-validation.md)을 확인하세요.
