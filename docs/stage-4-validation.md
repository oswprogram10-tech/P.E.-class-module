# 4단계 — PWA·태블릿 UX 완성

## 현재 판정

E01~E04를 구현하고 개발용 브라우저에서 확인했다. 실제 갤럭시 탭 A9+의 설치·비행기 모드·가상 키보드·햇빛 가독성·업데이트 적용은 **미검증**이며, HTTPS 배포 주소도 아직 정하지 않았다. 0~3단계의 실기기 대기 항목도 그대로 유지한다.

이 문서의 “통과”는 Windows의 Chrome과 가상 카메라, 로컬 HTTP 서버에서의 결과다. Android Chrome의 실제 설치 동작이나 실제 카메라·저장소 동작을 대신하지 않는다.

## E01 — 화면·터치·가독성

- `index.html`의 viewport에 `viewport-fit=cover`와 `interactive-widget=resizes-content`를 사용한다.
- 주요 버튼·탭·아이콘 버튼·입력·범위 슬라이더를 48 CSS px 이상으로 맞췄다. 범위 슬라이더는 트랙 높이 대신 조작 영역 높이를 48px로 둔다.
- 주요 안내·상태 문구의 글자 크기와 색 대비를 높였다. 테스트는 선택한 텍스트에 대해 WCAG 대비 4.5:1 이상과 11.5px 이상을 계산한다.
- 900px 이하에서 준비 목록과 상태가 행 단위로 재배치되고, 620px 이하에서 세로 흐름으로 바뀐다.
- 대화상자는 `max-height: calc(100dvh - 24px)`, 짧은 화면에서는 `calc(100dvh - 8px)`와 내부 스크롤을 사용한다. 닫기 행은 sticky로 유지한다.
- `visualViewport` 크기 변경과 입력 포커스 시 현재 대화상자의 높이를 다시 계산하고, 포커스된 입력을 화면 안으로 스크롤한다.
- 대화상자를 닫으면 키보드용 인라인 높이 제한을 제거해, 다음에 열 때 이전 화면 크기가 남지 않게 한다.
- 헤더·모달·토스트·초기화 화면에 `safe-area-inset-*`를 적용했다.

검증 결과:

| 화면 | 확인 | 결과 |
| --- | --- | --- |
| 1280×800, 교사 PIN 화면 | 가로 스크롤 없음, 영상·액션 카드 겹침 없음, 셸·하단 안내 잘림 없음, 48px 미만 터치 대상 없음, 작은/저대비 텍스트 없음 | 통과 |
| 800×1280 | 같은 항목 | 통과 |
| 800×480, PIN·학생 입력 대화상자 | 대화상자가 화면 안에 들어오고 포커스된 입력이 보임 | 통과 |

가상 키보드는 헤드리스 브라우저에서 직접 띄울 수 없다. 위 결과는 viewport 축소와 포커스 스크롤을 이용한 근사 검사이며, 실제 Android 키보드가 제출·취소 버튼을 가리지 않는지는 실기기 확인이 필요하다.

## E02 — 교사 수업 준비

- 학생 화면에 세 가지 준비 항목을 고정 표시한다: 태블릿 거치, 2~3걸음 거리에서 전신이 보이게 서기, 현재 지연 시간.
- 상태 문구는 기존 촬영·버퍼·저장 상태에서 파생한다. 별도 상태 머신을 추가하지 않았다.

| 상태 | 표시 |
| --- | --- |
| idle | 카메라 시작 전 · 시작 버튼을 눌러야 권한을 요청한다는 안내 |
| starting | 카메라 연결 중 · Chrome 권한 창 안내 |
| warming | 지연 영상 준비 중 · 설정 시간까지 남은 초 |
| live | 지연 영상 재생 가능 · 최근 버퍼와 설정 지연 |
| interrupted | 촬영 중단 · 중단 이유와 명시적 재시작 안내 |
| saving | 클립 저장 중 · 화면 유지 안내 |

- 카메라 권한은 사용자가 `카메라 시작`을 누를 때만 요청한다. 테스트에서 시작 전 `getUserMedia` 호출 0회, 누른 뒤 1회를 확인했다.
- 기존 스트림을 그대로 재사용하며 준비 화면을 위해 새 스트림을 만들지 않는다.
- 지연 시간을 바꾼 직후 이전 장면의 늦은 디코딩이 화면을 덮지 않도록 그리기 세대(`delayedDrawGeneration`)를 추가했다. 지연 변경·준비 중 전환·촬영 종료에서 세대를 올리고, 이전 세대의 그리기 결과는 버린다.
- PIN·설정 저장·클립 저장 흐름은 변경하지 않았다. 기존 `browser-data`, `browser-reset`, `browser-vault-migration` 검사가 그대로 통과했다.

검증 결과: idle → connecting → warming → live → interrupted → 명시적 재시도 전환을 확인했다. 준비 중에는 `has-video`가 없고, 지연이 충분히 쌓인 뒤에만 영상이 표시된다.

### 교사 준비 1분 측정 방법

실기기에서 다음 순서로 3회 측정한다. 목표는 앱 아이콘을 누른 뒤 지연 영상이 실제로 보일 때까지 60초 이내다.

1. 홈 화면의 PE Loop 아이콘을 누르는 순간 스톱워치를 시작한다.
2. PIN 입력, 지연 시간 설정, 카메라 시작, 태블릿 위치 조정까지 수행한다.
3. 설정한 지연 시간만큼 영상이 쌓여 지연 장면이 표시되는 순간 멈춘다.
4. 설치 상태, PIN 입력 시간, 권한 창 대기 시간, 영상 준비 대기 시간, 총시간을 기록한다.

| 회차 | 설치 상태 | PIN | 지연 설정 | 권한 대기 | 영상 준비 | 총시간 | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 |  |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |

아직 측정하지 않았다. 개발 환경의 자동화 시간으로 교사의 실제 준비 시간을 대신하지 않는다.

## E03 — 설치·오프라인

- `manifest.webmanifest`는 `display: standalone`, `display_override`, `orientation: any`, 192·512 아이콘(maskable), 교육·스포츠 카테고리를 사용한다.
- `beforeinstallprompt`가 있으면 `앱 설치` 버튼을 보여주고, 없으면 Chrome 오른쪽 위 ⋮ 메뉴에서 **앱 설치** 또는 **홈 화면에 추가**를 선택하라는 안내를 항상 표시한다.
- 설치 수락·거절·`appinstalled`·standalone 실행 상태에 따라 안내 문구를 바꾼다.
- 서비스 워커는 다음 앱 셸만 캐시한다.

```text
./  ./index.html  ./styles.css  ./app.js  ./local-vault.js
./clip-repository.js  ./webm-muxer.js  ./clip-exporter.js
./timeline.js  ./frame-buffer.js  ./manifest.webmanifest
./icon.svg  ./icon-192.png  ./icon-512.png
```

- 탐색 요청은 현재 활성 버전 캐시의 `index.html`에서 먼저 응답한다. 캐시가 없을 때만 네트워크를 시도하고, 실패하면 외부 리소스가 없는 인라인 오프라인 HTML을 반환한다.
- 정적 파일은 같은 버전 캐시에서 먼저 찾고, 없으면 네트워크로 넘긴다. 네트워크 응답을 즉석에서 캐시에 섞지 않아 HTML·JS 버전 혼합을 막는다.
- 캐시에는 정적 셸만 들어간다. 클립 영상·학생 이름·번호·PIN·암호화 키·IndexedDB 내용은 Cache API에 넣지 않는다.
- 외부 폰트·CDN·분석 스크립트를 추가하지 않았다. 폰트는 `system-ui` 계열이며, 외부 URL 참조가 없다.

| --- | --- |
| 첫 설치 후 캐시 URL이 앱 셸 14개와 정확히 일치 | 통과 |
| 앱이 만든 다른 캐시 없음 | 통과 |
| 설치 안내에 `앱 설치`/`홈 화면에 추가` 문구 표시 | 통과 |
| 서버 연결을 끊은 뒤 새로고침해도 앱 셸 로드 | 통과 |
| 오프라인에서 PIN 입력·교사 화면 접근 | 통과 |
| 오프라인에서 가상 카메라로 5초 암호화 클립 저장 | 통과 (길이 5초, 암호문 존재) |
| 셸 파일 하나를 500으로 실패시킴 | 오프라인 준비 실패 안내와 재시도 버튼 표시, 통과 |
| 실패 원인 제거 후 재시도 | 전체 셸 캐시 복구, 통과 |

설치 가능성 자체는 헤드리스 브라우저에서 실제 홈 화면 설치로 확인하지 않았다. manifest·셸·HTTPS 조건을 갖췄다는 것과 Chrome Android가 실제로 설치 배너를 띄우는 것은 별개다.

## E04 — 버전 업데이트

- 캐시 이름은 `pe-loop-shell-<version>`이며 현재 `pe-loop-shell-v6`이다.
- 설치 단계는 `cache.addAll`이 모두 성공해야 끝난다. 하나라도 실패하면 해당 버전 캐시를 삭제하고 설치를 실패시킨다.
- 활성화 단계는 `pe-loop-shell-` 접두사가 붙은 이전 버전 캐시만 삭제한다. 다른 앱의 캐시와 IndexedDB는 건드리지 않는다.
- `skipWaiting()`과 `clients.claim()`을 호출하지 않는다. 새 worker는 열린 화면을 가로채지 않고 대기한다.
- 새 worker가 `installed`이고 기존 controller가 있으면 `새 버전이 준비됐어요` 배너를 보여준다. 배너의 `나중에`는 안내만 닫으며, 새로고침·활성화를 실행하지 않는다.
- `controllerchange`에서도 토스트만 표시하고 페이지를 새로고침하지 않는다. 촬영·버퍼링·인코딩·저장 중인 화면을 강제로 바꾸지 않는다.
- 새 버전은 브라우저의 기본 수명주기에 따라 앱을 완전히 닫았다 다시 열 때 적용된다.

검증 결과 (테스트 서버가 `v6`을 `v7`로 교체):

| 확인 | 결과 |
| --- | --- |
| 새 worker가 `waiting`/`installed` 상태로 대기 | 통과 |
| 업데이트 배너 표시, 페이지 변수 유지(자동 새로고침 없음) | 통과 |
| 기존 controller 유지 | 통과 |
| `v6`와 `v7` 캐시가 함께 존재 | 통과 |
| 무관한 `unrelated-app-cache` 유지 | 통과 |
| 앱을 닫고 다시 연 뒤 `v7`만 활성, `v6` 삭제 | 통과 |
| 무관한 캐시 유지, 셸 14개 완전 | 통과 |
| 업데이트 전에 저장한 암호화 클립 1개와 PIN 설정 리비전 유지 | 통과 |
| 업데이트 후 오프라인에서 새 클립 저장, 기존 클립 암호문 유지(총 2개) | 통과 |

업데이트 전에 만든 클립의 ID와 암호문이 그대로 남았고, PIN 설정 리비전도 유지됐다. 서비스 워커가 IndexedDB를 건드리지 않고 셸 캐시만 교체하기 때문이다. 실제 Android에서 Chrome이 앱을 “완전히 닫았다 다시 열기”로 간주하는 시점, 녹화 중 업데이트 배너가 성능에 주는 영향은 실기기 확인이 필요하다.

### 지연 픽셀 검사의 보정

`tests/browser-delay.cjs`는 선택한 소스 프레임과 화면 캔버스의 픽셀을 비교한다. 60초 사례에서 채널당 최대 차이 1이 21,160바이트에서 나타났다. 프레임 나이는 59.98~60.12초로 정확했고, 이웃 프레임과는 최대 131까지 차이가 났다. 같은 프레임을 서로 다른 캔버스 경로로 그릴 때 생기는 래스터 반올림 차이로 판단해, 테스트 허용치를 채널당 2로 두고 최대 차이를 기록하도록 바꿨다. 제품의 프레임 선택 로직은 바꾸지 않았다.

## 실제 기기에서 남은 확인

- 갤럭시 탭 A9+ Chrome에서 설치 배너·⋮ 메뉴 설치·standalone 실행·아이콘 표시.
- 비행기 모드에서 앱을 완전히 닫았다 다시 열어 셸·카메라·PIN·IndexedDB·클립 저장·교사 목록 재생이 동작하는지.
- 실제 가상 키보드가 PIN·학생 입력 대화상자의 제출·취소 버튼을 가리지 않는지. 가로·세로, 800×480 포함.
- 안전 영역(노치·시스템 바), 회전 중 촬영·대화상자, 짧은 화면에서의 스크롤.
- 햇빛 아래 화면 가독성과 실제 글자 크기, 48px 터치 영역의 체감 조작성.
- 촬영·저장 중 새 버전 배포 시 배너만 표시되고 수업 화면이 유지되는지, 앱 완전 종료 후 새 버전이 적용되는지.
- 업데이트 후 저장 클립·PIN·7일 만료가 유지되는지.
- 실제 카메라의 지연·화질·발열·메모리와 40분 연속 사용. 이는 1·5단계 항목과 함께 확인한다.
- HTTPS 배포 주소와 서비스 워커 범위·캐시 헤더. 호스팅 방식이 정해지지 않아 배포·설치는 아직 검증하지 않았다.

## 변경하지 않은 것

- 암호화·PIN·만료·IndexedDB 스키마와 저장 데이터.
- 기존 카메라 스트림 재사용과 명시적 시작 정책.
- 외부 분석·로그인·클라우드 전송.
- 앱 런타임 의존성. 테스트 도구는 앱에 포함하지 않았다.
- 배포·커밋·푸시. 이번 작업은 작업 트리 변경으로만 남겨 두었다.
