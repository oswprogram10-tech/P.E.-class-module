# 3단계 — PIN과 로컬 데이터 보호

## 현재 판정과 사용자 결정

D01~D04의 구현 및 개발용 브라우저 검증을 수행했다. 실제 갤럭시 탭 A9+의 저장 정책·용량·권한·장시간 동작은 미검증이며, 0·1단계의 실기기 대기는 유지한다.

사용자 결정: PIN을 잊었을 때 **삭제 내용을 명확히 확인한 뒤 모든 로컬 클립을 삭제하고 새 PIN을 만드는 초기화**를 제공한다. 기존 클립을 복구하거나 기존 PIN을 찾아주는 기능은 아니다.

## 작업별 변경

| 작업 | 구현 | 검증 |
| --- | --- | --- |

## 키와 화면의 수명

| 동작 | 교사 목록 접근 | 수업용 키 | 저장 클립 |
| --- | --- | --- | --- |
| 최초 PIN 설정 성공 | 허용 | 메모리에 채택 | 새 파일 저장 가능 |
| 정상 PIN 확인 | 허용 | 검증한 키 채택 | 변경하지 않음 |
| 틀린 PIN | 차단 | 이미 정상인 수업 키 보존 | 변경하지 않음 |
| 교사 창 닫기 | 다시 잠금 | 학생 저장을 위해 유지 | 변경하지 않음 |
| 명시적 ‘잠그기’ | 차단 | 해제 | 암호화 파일 유지 |
| 수업 촬영 종료·앱 종료 | 차단 | 해제 | 완료된 암호화 파일 유지 |
| 화면 이탈 | 교사 창과 재생 정리 | 선택 클립 재시도용 수업 키 유지 | 미완료 저장 중단 |
| 확인한 초기화 | 다시 잠금 | 새 PIN 키 채택 | 모든 기존 로컬 클립 삭제 |

PIN 평문과 CryptoKey는 영구 저장하지 않는다. 파생 키는 비추출 Web Crypto 키다. 수업 중에는 메모리에 보유하며, 창 닫기와 키 해제는 별도 동작이다. 브라우저·기기 데이터 정리로 로컬 자료가 사라지면 서버 복구는 제공하지 않는다.

## 저장소와 호환

- `local-vault.js`: PBKDF2/SHA-256 250,000회, AES-GCM, PIN 검증, 영상·이름·번호의 암호화와 복호화.
- `clip-repository.js`: IndexedDB 버전 2의 `clips`와 `meta` 저장소, 트랜잭션, 만료·삭제·요약 조회, PIN 설정 리비전 확인.
- `meta`의 `vault`에는 salt·암호화된 검증 문자열·KDF 정보·리비전을 보관한다. PIN 평문이나 키를 저장하지 않는다.
- localStorage에는 지연 설정과 비밀이 아닌 리비전 알림만 사용한다. 기존 localStorage PIN 설정은 v1→v2 이전 후 제거한다. 제거에 실패해도 v2의 PIN 설정을 우선 사용한다.
- v1 데이터베이스에서 이전 중임을 기록해 기존 암호문을 다시 암호화하지 않고 설정만 옮긴다. 이미 v2인 저장소에서 PIN 설정이 사라진 경우 오래된 localStorage 값으로 자동 덮어쓰지 않는다.
- PIN 설정이 없는 기존 클립에는 새 PIN을 조용히 적용하지 않는다. 기존 파일을 보존하고 초기화 안내를 제공한다.
- 목록 조회는 영상 암호문 전체를 배열로 보관하지 않고 작은 메타데이터 요약을 먼저 만든다. 영상은 누른 항목 하나만 읽고, 다른 영상 선택·창 닫기·탭 변경 시 재생과 Blob URL을 정리한다.
- 초기화나 다른 탭의 변경 후 저장할 때는 같은 DB 트랜잭션에서 PIN 설정 리비전을 확인한다. 알림 전달이 늦더라도 이전 리비전으로 파일을 추가할 수 없다.

## 7일 보관과 삭제 규칙

1. 정상 클립은 생성 시각+7일과 기록된 만료 시각 중 이른 값을 사용한다. 불일치한 만료 필드가 7일을 연장하지 않는다.
2. 만료 시각과 같거나 늦은 시점에는 재생 대상에서 제외하고 삭제한다.
3. 앱 실행·목록 접근·재생 직전·복호화 후에 만료를 확인한다. 앱 실행 중에는 다음 만료에 맞춰 재확인하고, 주기 검사와 화면 복귀 검사도 수행한다.
4. 이미 재생 중인 영상이 만료되면 목록 갱신과 함께 플레이어·URL을 해제한다.
5. 앱이 닫히거나 OS가 정지시킨 동안 정확한 시각의 삭제는 보장하지 않는다. 다음 실행 시 정리한다. 기기의 날짜·시계 설정에 의존한다.
6. 생성·만료 정보가 손상되어 만료를 판정할 수 없는 항목은 재생하지 않고 ‘읽을 수 없는 클립’으로 표시한다. 임의로 날짜를 추정해 삭제하지 않으며 교사가 확인 후 삭제할 수 있다.
7. 수동 삭제는 확인 후 트랜잭션 완료를 기다린다. 취소·오류는 성공으로 표시하지 않고 기존 파일을 유지한다.

## PIN 분실 초기화

`PIN 분실 · 기기 데이터 초기화`에서 삭제할 자료와 복구 불가를 안내한다. 새 6자리 PIN을 두 번 입력하고, 확인 문구 **‘모두 삭제’**가 정확히 일치해야 실행할 수 있다.

클립 전체 삭제와 새 PIN 설정을 `clips`·`meta`의 단일 readwrite 트랜잭션으로 처리한다. 실패하면 두 변경을 함께 되돌린다. 사용자가 취소하거나 잘못된 확인 문구를 입력하면 삭제하지 않는다. 성공 후 새 PIN은 재실행에서도 유효하고 이전 PIN은 검증되지 않는다. 같은 사이트의 다른 앱 탭에는 변경을 알리고 이전 키로 저장을 시도해도 저장소에서 거부한다.

이 초기화는 기기의 이 앱 저장소에 대한 논리적 삭제다. 운영체제의 복구 불가능한 물리적 삭제나 다른 기기의 데이터 삭제를 뜻하지 않는다.

## 공간과 오류 안내

사이트 전체 사용량·할당량은 브라우저가 제공한 추정값이다. 앱 영상만의 정확한 사용량이나 예약 가능한 공간이 아니다. 잔여 추정 공간이 작으면 정리를 안내하되, 실제 쓰기 성공 여부는 DB 트랜잭션 결과로 판단한다.

자동 정리 방지는 교사의 명시적 버튼 조작으로 요청한다. 거부·미지원 시에도 앱은 안내 후 사용할 수 있다. 허용돼도 브라우저 데이터 삭제·기기 초기화·사용자 삭제를 막거나 7일 보관을 보장하지 않는다.

저장 공간 조회가 실패하거나 응답 순서가 뒤바뀌면 오래된 결과가 최신 안내를 덮어쓰지 않게 한다. 지연 설정 쓰기가 실패하면 실제 적용값과 UI를 이전 값으로 유지한다. PIN 설정은 DB에 저장된 뒤에만 메모리 키로 채택한다.

## 실행한 검증

| 실행 | 결과 |
| --- | --- |
| Node 단위 검사 전체 | 13개 통과: 버퍼·시각·WebM·PIN·변조·만료 정책 |
| `tests/browser-data.cjs` | 오입력 후 키 유지, 손상 항목 격리, 늦은 PIN·목록·영상 결과 무효화, URL 정리, 삭제 실패·취소·재시도, 만료 경계·재생 중 만료, 저장 공간·설정 오류 통과 |
| `tests/browser-vault-migration.cjs` | v1 PIN·암호문 보존 이전, PIN 없는 기존 클립 보호, v2 설정 손실 시 오래된 설정 채택 거부, 최초 PIN 저장 실패·취소·재시도 통과 |
| `tests/browser-reset.cjs` | 초기화 문구·취소, 트랜잭션 실패 롤백, 새 PIN 재실행, 다른 탭의 오래된 리비전 저장 거부 통과 |
| 기존 클립·카메라 회귀 | 선택 장면·취소·저장 실패 재시도, 촬영 중단·복귀, 실제 5·15·30초 무음 WebM 저장 통과 |

개발 환경은 Linux Chromium 155.0.8059.79 및 Node 24.22.1이다. 가상 이름·영상과 격리된 브라우저 저장소만 사용한다. 7일 경계는 제어된 시각과 짧은 실제 만료로 검사했으며 실제로 일주일을 기다린 검사는 아니다. 일부 저장소·용량·복호화 오류를 의도적으로 주입했다.

## 남은 검증

갤럭시 탭 A9+의 실제 저장 할당량, 자동 정리 방지 허용 여부, Web Crypto·IndexedDB·업데이트 호환, 화면 잠금·OS 정지 후 복귀, 장시간 메모리는 대기다. PWA 서비스 워커의 버전 전환과 수업 중 업데이트 유예는 4단계에서 구현·개발 검증했으며, 실제 기기 적용은 [4단계 검증 기록](stage-4-validation.md)에 남겼다.
