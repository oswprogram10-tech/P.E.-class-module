# 이 세션의 목표와 구현 순서

설정일: 2026-11-05 (한국 시간)

## 목표와 기준

사용자 요청에 따라, 첨부 문서 「초등체육 에듀테크 및 앱 명세서」와 현재 앱을 비교해 제안한 다섯 단계를 이 세션의 작업 목표로 지정한다. 현재 PE Loop의 지연 카메라·암호화 저장을 안정화한 뒤, 학생의 복습·성찰과 교사의 수업·평가 지원으로 순차 확장한다.

이 문서는 향후 이 세션의 작업 순서·완료 판정 기준이다. 목표 등록은 기능 구현 완료를 의미하지 않는다. PDF의 제안 전체를 즉시 실행하라는 지시로 취급하지 않으며, 문서의 성능·효과 수치는 검증할 목표로 다룬다.

- 기존 첫 출시의 요구사항·작업 ID는 [구현 계획표](implementation-plan.md)를 유지한다. 확장 작업의 순서는 이 문서를 따른다.
- 이미 구현된 기능의 근거와 실기기 대기는 [작업 상태표](task-status.md), [2단계 검증](stage-2-validation.md), [3단계 검증](stage-3-validation.md)을 따른다. 오래된 진행 기록보다 실제 코드와 최신 검증 근거를 우선한다.
- 기준 코드: `f1ba4c2`. 기존 1~60초 지연, 최대 5분 버퍼, 5~30초 무음 클립, PIN·암호화·7일 만료 기능을 보존한다.
- 이전 환경 검증에서 단위 테스트 13개와 브라우저 테스트 7개가 통과했다. 이는 Linux Chromium·가상 카메라의 결과이며 Android 검증이 아니다.
- 이 문서 등록 시점에는 S1~S5의 신규 작업에 착수하지 않았다.

각 단계는 아래 세부 번호 순서로 진행한다. 단계마다 구현 → 관련 자동 검증 → 결과·미확인 항목 기록 → 다음 작업 선택을 반복한다. 완료·부분 완료·실패·외부 조건 대기를 구분하고, 검증 명령과 결과를 남긴다. 필요한 검증이 통과한 뒤에는 이유 없이 같은 검사를 반복하지 않는다.

실기기·계정·공식 기준 자료 등 외부 조건이 없는 작업은 계속 진행한다. 외부 조건 대기가 있다고 전체 개발을 멈추지는 않지만, 미충족 조건을 완료로 바꾸거나 첫 출시가 검증됐다고 주장하지 않는다. 실제 기기 확인이 당분간 어렵다는 기존 기록을 존중하고 같은 정보를 반복 요청하지 않는다.

## 남은 작업의 토큰 효율별 배분

작업 크기보다 위험과 독립 검증의 가치에 따라 팀 규모를 고른다. Sol은 항상 범위·통합·완료 판정을 맡는다. 각 구현 파일의 소유자는 한 명으로 고정하고, 전체 회귀 검사는 통합 뒤 한 번 실행한다.

| 방식 | 언제 쓰는가 | 역할·검증 |
| --- | --- | --- |
| Sol 단독 | 범위가 작고 되돌리기 쉬운 UI·문서·수동 흐름, 또는 하드웨어·공식 자료를 기다리는 조사 | Sol이 조사·구현·관련 테스트를 끝낸다. 다른 모델의 중복 코드 읽기와 전체 테스트 재실행은 생략한다. |
| Sol + Terra | 여러 파일을 가로지르거나 데이터 경계·공식 규칙·오프라인 복구처럼 집중 검사가 필요한 작업 | Sol은 계약·통합, Terra는 격리된 구현 또는 독립 경계 테스트 한 가지를 맡는다. 병렬 작업은 파일과 산출물이 분리될 때만 한다. |
| Sol + Terra + Luna | 정확도·학생 정보·평가 규칙처럼 잘못된 완료 판정의 비용이 큰 묶음 | Terra는 구현/측정 도구, Luna는 미리 정한 위험 질문에만 독립 검증을 한다. Luna에게 전체 회귀를 다시 돌리게 하지 않고, 검증 결과 뒤에 필요한 테스트만 한 번 재실행한다. |
| 외부 조건 대기 | 실제 Android·학교·배포·허용된 공식 자료·BLE 기기가 필수인 작업 | 준비 문서와 로컬 선행 작업은 Sol 단독으로 진행한다. 자료나 기기가 없으면 병렬 작업으로 완료를 가장하지 않고 대기 상태를 유지한다. |

현재 남은 순서의 기본 배분은 다음과 같다. 조건이 달라지거나 코드가 PIN·공유 저장소·원격 전송 경계를 바꾸면 Sol이 작업 시작 전에 팀 규모를 다시 정한다.

| 남은 작업 | 기본 배분 | 효율을 위한 경계 |
| --- | --- | --- |
| S1.6 실기기·현장·배포 확인, S2 실기기 확인 | 외부 조건 대기, Sol이 체크리스트 정리 | 기기나 배포 접근이 없으면 실제 검사는 표시하지 않는다. 가상 검사를 반복해 대체하지 않는다. |
| S3 영속 서버·실배포 | Sol + Terra | 서버 저장·인증·개인정보 경계가 달라질 때만 독립 구현/보안 확인을 붙인다. 접근 조건 전에는 로컬 자료 정리만 한다. |
| S4.6 정확도·자원 사용 | Sol + Terra, Luna는 평가 방법만 독립 검토 | 합성 harness와 측정 기준은 로컬에서 준비한다. 실제 정확도 결론은 동의된 실제 검증 자료와 기기 측정이 있을 때만 낸다. |
| S5.1 PAPS 수기 기록 | Sol 단독 | 입력·수정 이력의 관련 저장 테스트만 추가한다. 기존 전체 스위트는 통합 시 한 번 실행한다. |
| S5.2 공식 기준·등급 계산 | Sol + Terra | 교육부령 제354호 별표 4의 현재 5종목 × 남녀 × 초3~고3 기준 등록, 직접 선택형 등급 미리보기, 기준 범위 암호화 보존까지 검증했다. 법령에 없는 백분위·종합점수는 계속 미제공으로 둔다. |
| S5.3 운동 콘텐츠·15분 루틴 | Sol 단독 MVP | 적은 수의 출처·사용권한이 확인된 항목부터 구현한다. 콘텐츠 500개 수집은 별도 자료 작업으로 나누며 병렬 생성하지 않는다. |
| S5.4 성취기준·교사 루브릭 | Sol + Terra | Sol이 출처와 버전을 연결하고 Terra가 점수 경계·수정/승인 흐름을 확인한다. |
| S5.5 학생 기록 기반 문구 초안·출력 | Sol + Terra, Luna는 개인정보·내보내기 경계만 독립 검토 | 교사 편집·승인형 수동 초안을 먼저 구현한다. 생성형 AI·외부 전송은 서비스·인증·비용·데이터 범위가 정해지기 전까지 분리한다. |
| S5.6 웨어러블·교구 | PWA/Android 호스트 구현은 Sol 단독, 실제 기기 검증은 Sol + Terra | Wi-Fi 복구 시 휴대폰 자동 재연결 정책을 선택했다. Android API 35 debug APK·단위 검사·Lint가 통과했다. 휴대폰 자동 재시도, 주소 변경 탐색, companion 앱과 실기기 검증이 남았다. |
| S5.7 QR 미션·오프라인 재개 | Sol + Terra | Sol은 기본 흐름, Terra는 재개·중복 제출·복구 같은 실패 경계만 맡는다. GPS는 권한·정확도·학교 안전 조건이 확보될 때 별도 착수한다. |
| S5.8 전술판·AI 회고 | 수동 전술판은 Sol 단독; AI 제안은 Sol + Terra, Luna는 근거·편향 검토 | 실제 팀 기록과 검증 근거 없이 추천 기능을 병렬 구현하지 않는다. |
| S5.9 플랫폼 검증 | Sol 단독 자동화, 기기별 검증은 해당 기기 확보 후 | 한 브라우저에서 같은 테스트를 여러 모델이 반복하지 않는다. 플랫폼별 결과만 추가 기록한다. |

세부 위임은 한 번에 한 개의 독립 산출물과 한 개의 수락 조건으로 제한한다. 작성자는 관련 단위 검사를 수행하고, 통합 뒤 Sol이 영향받은 회귀 묶음을 한 번 실행한다. 독립 검증자는 실패 가능성이 큰 경계만 확인한다. 코드가 바뀌지 않았고 동일 환경의 검사가 이미 통과했다면 재실행하지 않는다.

| S2.6 | 1~300초 지연과 5분 버퍼의 실효성 검토·구현 | 60초를 넘는 설정·대기·변경 처리, 버퍼 부족 안내. 메모리 예산 내 실제 유지 범위를 측정하고 300초 목표의 달성 여부를 명시 |

검증: 타임코드·합성 영상으로 선택 시각, 프레임 이동, 출력 장면, 반투명 비교, 저장 중 조작·취소·실패 재시도를 확인한다. 300초는 설정 상한만 늘려 완료 처리하지 않는다. 현재 480×270·약 10fps·80MiB 버퍼 한도에서 유지가 안 되면 압축 방식 등 대안을 측정하고 지원 범위를 결정한다.

S2의 성찰 기록은 현재 로컬 보관 정책을 따른다. 장기 포트폴리오의 보관 정책과 기기 간 제출은 S3에서 별도로 연결한다. 외부 시범 영상 URL·교과서 QR 연결은 사용 가능한 콘텐츠·이용 조건을 확인한 뒤 추가한다.

생성형 AI가 필요한 S5.5·S5.8의 자동 생성은 서비스·인증·비용·전송 데이터 범위를 정한 뒤 연결한다. 그 전에도 수동 작성·편집·출력 흐름은 개발할 수 있다. PAPS 백분위는 등급과 별개로 공식 산출 근거를 확보해야 한다. 심박 알림은 검토된 기준과 오류 처리가 필요한 보조 정보이며 안전 보장을 뜻하지 않는다.

첨부 명세서의 1초 산출·업무 80% 절감·500개 콘텐츠 등은 검증 전의 목표/주장으로 취급한다. 성능·절감·효과 수치로 제품 안내에 쓰려면 별도 측정 근거가 필요하다.

VR 센서·타교 메타버스 스포츠클럽은 문서의 추가 확장 항목으로 추적하되, 지원 장치/플랫폼과 실제 수업 시나리오가 없는 상태에서 S5 기본 기능의 완료 조건에 포함하지 않는다.

## 공통 완료 기준과 다음 행동

- 회귀 보존: 선택 장면과 출력의 일치, 무음·최대 30초 제한, 암호화·PIN·보관/삭제·실패 복구를 유지한다. 정밀 선택에 맞춰 검사와 UI 제약을 함께 갱신한다.
- 데이터 보호: 실제 학생 영상·이름·PIN·키를 개발 로그나 진단 서비스로 전송하지 않는다. 테스트는 가상 데이터와 격리된 저장소를 기본으로 한다.
- 오프라인: 각 모듈의 로컬 기능과 외부 연결 기능을 구분하고 준비·연결·대기·실패 상태를 사용자에게 표시한다.
- 결과 기록: 구현한 범위, 실제 실행한 검사, 실패·미실행·대기 조건, 다음 세부 작업을 함께 갱신한다.
- 범위 변경: 원문 목표를 조용히 축소하거나 현재 합의와 충돌하는 정책을 추정해 확정하지 않는다. 필요한 제품 결정은 해당 단계의 구체적인 대안과 함께 정리한다.
- 일정: 기존 첫 출시 추정 기간을 S1~S5 전체의 일정으로 재사용하지 않는다. 각 단계의 기술·자료·기기 조건을 확인한 뒤 산정한다.

## S1 실행 기록 — 2026-11-05

S1.1~S1.3의 서비스 워커 업데이트 대기·안전한 종료/재실행 적용, 캐시 버전 분리, 오프라인 준비 안내와 전체 저장·재생 흐름을 구현하고 개발용 브라우저에서 확인했다. S1.4의 48px 터치·좁은 화면·낮은 입력 화면을 개선했으며 S1.5의 안내 문서와 자동 모의 준비 측정을 완료했다. 기존 Node 13개, 기존 브라우저 7종과 신규 PWA·화면 2종 검사를 통과했다. 근거와 초기 v5 전환의 한계는 [S1 검증 기록](stage-1-validation.md), 실제 운영은 [교사·배포 안내](S1-release-guide.md)를 따른다.

S1 전체는 부분 완료다. 실제 Android 회전·키보드·설치·40분 촬영과 교사 1분 준비 측정, 외부 HTTPS 배포·복귀는 외부 조건 대기로 남긴다. 자동화·Linux 가상 카메라 결과로 대체하지 않는다. 이 S1 기록 시점에는 S2에 착수하지 않았으며, 이후 S2 실행은 아래 기록을 따른다.

## S2 실행 기록 — 2026-11-05

사용자의 후속 착수 요청에 따라 S2.1~S2.6의 로컬 구현과 개발용 검증을 진행했다. 실제 표시 장면 기준의 고정 선택, 프레임 시작·끝 조절과 소수 초 무음 출력, 교사 재생·파일 내보내기, 로컬 시범 영상 비교, 암호화 성찰, 1~300초 지연과 부족 안내를 구현했다. 실제 310초 가상 촬영에서 300초 지연을 확인했으며, 메모리·장면 조건 없이 모든 기기의 300초 보관을 보장하지 않는다.

검증 범위·측정값과 한계는 [S2 검증 기록](stage-S2-validation.md), 사용 흐름은 [복습·비교·성찰 안내](S2-review-guide.md)를 따른다. S1의 실제 기기·현장·배포 대기는 유지한다. S3에는 착수하지 않았다.

이 S2 기록 당시의 다음 순서는 S3.1이었다. 이후 요청에 따른 최신 상태는 아래 S3 기록을 따른다.


## S3 실행 기록 — 2026-11-06 (한국 시간)

사용자의 다음 단계 요청에 따라 S3.1~S3.7의 로컬 학급 기록·교사 콘솔·직접 선택 제출·성찰·오프라인 대기열·승인형 텍스트 피드백을 구현했다. 별도 PIN/IndexedDB를 가진 두 Chromium context와 실제 loopback HTTP 허브에서 가상 카메라 WebM의 저장·선택 제출·교사 재생을 확인했다. 기존 이름/번호 클립은 미배정이며 수동 이관 UI는 없다.

허브는 RAM에 평문 선택 자료를 보관하는 개발 도구이며 실제 다기기/LAN/HTTPS/영속 암호화 서버는 완료하지 않았다. 로컬 초기화는 이미 허브가 받은 자료를 지우지 않는다. [S3 사용·운영 계약](S3-data-and-sync.md)과 [S3 검증 기록](stage-S3-validation.md)을 따른다. 실제 Android·현장·배포 대기는 계속 유지한다.

이 S3 기록 당시의 다음 기능 단계는 S4.1이었다. 이후 첫 개발 묶음 요청에 따른 최신 상태는 아래 S4 기록을 따른다. S3 운영 범위의 외부대기는 별도로 유지한다.

## S4 첫 개발 묶음 실행 기록 — 2026-11-06 (한국 시간)

사용자가 요청한 S4.1~S4.2의 선택형 전신 확인 준비·실행 코드, worker·별도 자산 캐시·무결성·오래된 결과 폐기, 관절 신뢰도·전신 배치 규칙과 선택 음성 안내를 구현했다. 기본 촬영·지연·클립·학급 기능을 유지한다. 공식 Lite float16 v1 모델을 설치하고 공식 모델 카드의 모델 계열 Apache-2.0 표기를 확인했으며, 실제 worker 추론·기본 카메라 동시 측정·offline 브라우저 재실행을 개발환경에서 검증했다. 단위 39개와 이번 독립 실행 관련 브라우저 7종이 통과했다. 과거의 19종 전체를 이번에 재실행한 것은 아니며, 합성/fake worker 검사는 실모델 결과와 구분한다.

이전 제한 환경에서 `storage.googleapis.com`이 허용되지 않았고 기존 프록시 요청이 HTTP 403으로 실패했던 것은 당시의 역사적 상태다. 현재 실행 환경은 최신 관찰이 유효하고 제한 네트워크 정책이 적용된 상태이며, 공식 모델 호스트 허용 후 Sol이 모델을 설치했다. 이번 팀은 환경 설정을 변경하거나 게시하지 않았다. 공식 카드의 라이선스 근거와 개별 archive 증거 한계는 [자산 기록](pose-assets.json)에 남겼다.

[사용·설치 안내](S4-foundation-guide.md)와 [검증 기록](stage-S4-foundation-validation.md)에 이용·검사 근거와 한계를 기록했다. S4.1~S4.2 개발환경 잔여 검증은 완료했으나, 실제 Android·학교 수업, 전체 메모리·발열·40분 실행·현장 정확도는 외부 조건 대기다. 이 묶음 당시에는 S4.3에 착수하지 않았으며 이후 명시적 요청에 따른 실행은 아래 기록을 따른다.

## S4.3 농구 동작 감지 — 2026-11-06

사용자의 다음 작업 요청으로 S4.3만 구현했다. 영상 비율을 보정한 어깨–팔꿈치–손목의 2D 내각, 귀·어깨 대비 손목 높이와 몸통 길이로 정규화한 위치를 사용한다. READY·SHOOT에는 각각 연속 프레임과 시간 조건을 적용하고, 팔을 내린 뒤 새 준비를 해야 다음 동작을 감지한다. 왼팔·오른팔과 세 단계 민감도는 교사 PIN 안에서 저장하며 실패 시 이전 설정을 유지한다. 전신 신뢰도·프레임 지연·기하 변화·선택 학생/수업 맥락·설정·카메라/화면 전환 때 상태를 초기화한다. 기하 변화 검사는 사람의 동일성을 인식하는 기능이 아니다.

단위 49개와 기존 관련 브라우저 11종 및 신규 농구 UI 1종이 통과했다. 이번에 재실행한 브라우저는 총 12종이며 최종 근거는 [S4.3 검증 기록](stage-S4-shot-validation.md), 사용법·실험 임계값과 한계는 [농구 동작 안내](S4-shot-guide.md)를 따른다. 실제 모델의 정지 사진 추론과 합성 동작 시퀀스를 구분하며 실제 슛 감지 정확도를 주장하지 않는다. Android·학교 환경·장시간·전체 메모리·발열 확인은 계속 대기다.

현재 결과는 팔을 구부려 준비한 뒤 위로 펴는 동작의 감지이며 골 성공·기술 정확성·성적 판정이 아니다. 이 S4.3 기록 당시에는 S4.4~S4.5를 구현하지 않았으며, 이후 명시적 요청에 따른 S4.4 실행은 아래 기록을 따른다.

## S4.4 선택 피드백·순간 이미지 — 2026-11-06

동작 감지 이벤트에 짧은 시각 강조·효과음·최신 임시 이미지 1장을 선택적으로 표시한다. 세 옵션은 매 실행 기본 꺼짐이며 영속 설정으로 저장하지 않는다. 이미지 픽셀은 worker에 보낸 입력 bitmap의 복제이고, 입력 시각과 캡션의 팔·각도는 이벤트에서 복사한다. 비동기 결과가 돌아온 현재 카메라나 지연 화면을 대신 캡처하지 않는다. 복제·변환 중 설정/맥락/촬영 세대가 바뀌면 폐기하며 중단·초기화·페이지 이탈에서 URL·이미지·효과를 정리한다.

단위 49개와 기존 관련 브라우저 10종·신규 3종, 총 13개 실행 파일이 통과했다. 합성 입력의 프레임 일치·표시 수명과 실제 worker의 온라인/오프라인 연결을 독립 재확인해 S4.4 개발 검증을 완료했다. 세부 명령·결과·이벤트 stub 구분은 [검증 기록](stage-S4-feedback-validation.md), 사용과 보관 한계는 [피드백 안내](S4-feedback-guide.md)를 따른다. 실제 정지 사진 추론과 제어된 테스트 이벤트는 실제 슛 정확도의 근거가 아니다.

영속 시도/각도/관절 로그·학급 제출 연결은 S4.5 범위로 남긴다. 원본 영상이나 순간 이미지를 자동으로 전송·영속 저장하지 않는다. 실제 Android·학교 환경·장시간·전체 메모리·발열·스포츠 정확도는 계속 미확인이다.

## S4.5 학생·수업별 동작 이력 — 2026-11-06

교사가 현재 실행에서 명시적으로 켠 경우에 한해 실제 READY→SHOOT 이벤트 한 건의 입력 시각, 팔, 민감도, 2D 팔꿈치 각도, 손목/몸통 비율, 적용 기준, 전신 신뢰도 요약과 모델 버전을 기록한다. 저장 전 학급·학생·수업·기기 바인딩과 이벤트 시각을 다시 확인한다. 원시 관절 좌표, 이름, 영상·이미지는 저장하지 않는다.

기록은 기존 PIN 암호화 `meta/classroom`에 저장하며 부모 데이터 만료와 최대 7일, 기기당 2,000건 상한을 적용한다. 교사 PIN에서 범위별 조회·삭제를 제공하고, 같은 연결의 유효한 클립만 별도 선택으로 연결할 수 있다. 클립·학급·학생·수업·기기 삭제와 만료에 따라 종속 기록도 정리한다. 동작 기록과 클립 연결은 허브 대기열에 넣지 않는다.

단위 59개와 S4.5 관련 브라우저 검사가 통과했다. 브라우저에서 저장·조회·삭제와 명시적 클립 연결을 확인했으며 입력 동작은 합성 시퀀스다. 저장 취소는 실제 IndexedDB에서 확인했고, 할당량 오류는 주입해 확인했다. 실제 모델이 실제 농구 슛을 기록하는 정확도, 브라우저 실제 저장소가 꽉 찬 상황, Android·학교 환경·발열·40분 실행은 미확인이다. 검사 근거와 한계는 [S4.5 검증 기록](stage-S4-history-validation.md), 교사 사용·보관 안내는 [S4.5 사용 안내](S4-history-guide.md)를 따른다. S4.6이 다음 순서다.


## S4.6 합성 평가·로컬 자원 계측 준비 — 2026-11-06

새 standalone harness로 정의된 7개 합성 사례의 READY→SHOOT 사건을 reference 구간에 일대일 매칭한다. TP 3·FP 1·FN 2, precision 0.75·recall 0.6이며 방향·조건별 micro 집계와 분모 0의 null을 제공한다. 유사 팔 올리기 FP와 가림/추적 간격 FN을 포함하며 실제 농구 정확도를 의미하지 않는다. Node 규칙 반복의 CPU·RSS/heap 계측과 기존 실제 모델의 짧은 정지 사진/가상 카메라 근거를 분리했다.

단위 64개 통과. 평가 방법은 Luna가 읽기 전용으로 검토하고 매칭 6,400조합을 독립 확인했다. [S4.6 검증 기록](stage-S4-evaluation-validation.md)과 [평가 절차](S4-evaluation-protocol.md)에 재현·경계를 기록했다. 이 기록 시점에는 동의된 실제 영상·교사 검토와 촬영 방향별 정확도, 기기 검증이 대기여서 S4.6 전체 완료로 표시하지 않았다. 이후 사용자의 범위 지정에 따라 아래 후속 절에서 로컬 종목 확장을 구현했다. 실제 스포츠 정확도와 교사 검토, Android·학교 환경·발열·40분 검사는 여전히 미실행이다. S5에는 착수하지 않았다.


## S4.6 후속 — 실험용 종목·프로필 확장 (2026-11-06)

사용자가 Android·학교 환경·발열·40분 연속 사용을 제외하고 나머지 검토와 종목 확장을 명시 요청했다. 기존 S4.6 fixture/source hash·평가 재현과 방법론을 검토했고 기존 산출물을 재적용하거나 덮어쓰지 않았다. 배구는 250ms 유지의 머리 위 팔 스윙 연습 cue로 별도 구현하고 세션 한정 종목 선택을 연결했다. 농구 기본 설정을 보존하며 배구 cue를 농구 시도 이력·피드백에 보내지 않는다.

승인된 동일 출처·SHA-256 프로필로 PoseRuntime을 연결했다. 기존 공식 Lite만 있으며 대체 weights 부재로 custom 모델은 프로필/로더 확장 인터페이스까지만 구현했다. 임의 URL·파일 업로드·직접 weights는 지원하지 않는다. 배구 감지 정확도·공 접촉·기술 평가·교사 검증 완료를 뜻하지 않는다. 상세 범위는 [확장 안내](S4-sport-extension-guide.md), 검사 결과는 [확장 검증](stage-S4-sport-extension-validation.md)을 따른다. 제외된 실제 검사는 계속 대기며 S5에는 착수하지 않았다. 게시·배포·commit·push하지 않았다.

## S5.6 — 웨어러블 PWA 브리지 선행 구현 (2026-11-06)

Galaxy Watch/Apple Watch의 2022-11-06 이후 출시 모델을 목표로 PWA 심박수 브리지 계약과 수업 세션 UI를 추가했다. 학생·보호자 동의를 각각 확인하고 초기 v1 브리지는 교사 WebView에서 네이티브 권한 요청을 하는 형태였다. 학생/학급 ID를 네이티브 브리지에 보내지 않고 익명 일회성 토큰만 전달한다. 시각이 5초 넘게 갱신되지 않거나 연결이 끊기면 값을 숨기고 공백을 표시하며 교사 재연결 동작을 제공한다. 원시 심박 표본은 PIN 저장소에 저장하지 않는다. 두 동의 중 하나가 해제되거나 PIN 잠금/페이지 이탈 시 네이티브 세션을 종료한다.

일반 PWA에는 시계 직접 연결 기능이 없으며 실동작에는 제조사 공식 API를 쓰는 Android/Wear OS·iOS/watchOS 네이티브 앱이 별도로 필요하다. 이후 환경이 게시되어 Apple HealthKit/WatchConnectivity, Wear OS Health Services, Samsung Health Sensor SDK의 공식 API 문서를 확인했다. 모델별 출시일·최소 OS 표와 실제 기기 호환은 아직 미검증이다. 사용자는 학생별 페어링 휴대폰에서 같은 로컬 Wi-Fi를 통해 Android 교사 태블릿의 네이티브 수신 앱으로 보내는 경로를 선택했다. 초대 QR, TLS 지문 고정, 일회성 자격, 메모리 전용 전달 계약을 [S5.6 LAN 릴레이 계약](S5.6-lan-relay-contract.md)에 정리했다. 당시 미결정이던 로컬 Wi-Fi 단절 뒤 재연결은 후속 답변에서 휴대폰 자동 재연결로 결정했다. 가상 브리지 단위 9개와 Chromium 흐름, 전체 단위 119개 및 관련 PWA/학급/PAPS 브라우저 회귀가 통과했다. OS 권한 거부 때도 수업을 제한하지 않고 심박 측정값과 기록을 빈 상태로 두도록 확정했다. 자세한 범위는 [S5.6 API 조사](stage-S5.6-vendor-api-research.md)와 [웨어러블 검증](stage-S5.6-wearable-validation.md)에 기록했다.

2026-11-07 후속 구현에서 4년 출시일 하한을 2022-11-07로 갱신하고 브리지를 v2로 바꿔 교사 PWA가 학생·보호자 동의 후 한시적 QR 초대를 만들고, 워치 권한 요청은 학생 휴대폰 companion에서 처리하도록 했다. Android 태블릿 호스트에는 WebViewAssetLoader 앱 셸, Web Message 브리지, TLS WebSocket 릴레이와 최초 연결 뒤 RAM 전용 재접속 자격 발급/검증을 추가했다. 사용자가 Wi-Fi 복구 시 자동 재연결을 선택해 PWA 상태 재개와 가상 흐름을 구현했다. 이어 Android SDK Platform 35로 debug APK를 빌드하고 JVM 검사 1/1·Lint 0 오류/0 경고 및 APK 서명을 확인했다. 휴대폰 자동 재시도와 학생 iOS/Android/watchOS/Wear OS companion, LAN·실기기 연결 검증은 남아 있다.
