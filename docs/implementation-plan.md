# PE Loop 구현 계획표

작성일: 2026-11-05 (한국 시간)

현재 0·1·2·3단계의 완료·대기 판정은 [작업 상태표](task-status.md)에서 확인한다. 설계 완료와 구현·실기기 검증 완료를 구분한다.

## 1. 목표와 계획 기준

첫 출시 목표는 안드로이드 태블릿을 거치한 상태에서 학생이 동작을 수행하고, 지연 영상을 확인한 뒤 원하는 구간을 기기에 저장할 수 있는 PWA다.

현재 저장소에는 화면, 카메라 프레임 버퍼, 클립 생성, 로컬 암호화 저장, PIN, 서비스 워커의 코드 초안이 있다. 실제 Android 기기에서의 기능·성능·설치 검증은 아직 수행하지 않았다. 아래의 ‘완료 기준’과 성능 수치는 앞으로 확인할 목표이며 현재 달성한 결과가 아니다.

예상 기간은 개발자 1명이 이 작업에 집중하고, 검증용 태블릿 2대와 HTTPS 테스트 주소를 확보한다는 가정이다. 본개발 19~27작업일, 약 4~6주를 예상한다. 기기 수급·호스팅 계정 접근·학교 수업 일정 대기는 별도다. 1단계 성능 검토 후 영상 처리 구조를 크게 바꿔야 하면 일정을 다시 산정한다.

## 2. 확정 요구사항과 기본값

| 항목 | 확정 내용 | 비고 |
| --- | --- | --- |
| 주 사용자·기기 | 초등학생 모둠, 거치된 Android 태블릿 | 교사는 수업 설정과 클립 목록 관리 |
| 제공 방식 | Chrome에서 열고 홈 화면에 추가하는 PWA | HTTPS 배포 필요 |
| 지연 재생 | 교사가 1~60초 조절 | 20초 기본값은 현재 코드의 제안값 |
| 임시 영상 | 직전 5분을 순환 보관 | 저장하지 않은 영상은 서버·영구 저장소로 보내지 않음 |
| 저장 구간 | 학생이 골라 최대 30초 저장 | 5초 단위 선택, 기본 15초는 현재 코드의 제안값 |
| 소리 | 영상만 사용 | 마이크 권한을 요청하지 않음 |
| 보관 위치 | 해당 태블릿의 앱 내 클립 목록 | 계정·서버 업로드 없음 |
| 학생 정보 | 저장할 때 이름과 번호를 매번 입력 | 학생 명단 기능 없음 |
| 목록 보호 | 교사 PIN으로 접근 | PIN 6자리는 현재 코드의 제안값 |
| 자동 삭제 | 저장 후 7일이 지난 클립 삭제 | PWA가 닫혀 있을 때 정시 삭제를 보장할 수 없어, 앱 재실행·목록 접근·실행 중 주기 점검으로 만료 항목 삭제 |

브라우저의 저장 공간 정리나 기기 초기화로 클립이 7일보다 일찍 사라질 수 있다. ‘7일’은 만료 기준이며 백업이나 보관 보장 기간이 아니다. 이 동작은 교사용 안내에서 명확히 설명한다.

## 3. 전체 일정

P0는 다음 단계로 넘어가기 전에 해결할 필수 작업, P1은 첫 출시 전 필요한 작업이다. P2는 현장 사용 결과에 따라 선택하는 개선이다.

| 단계 | 작업 ID | 예상 기간 | 핵심 산출물 | 진입 조건 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- | --- | --- | --- |
| 0. 설계와 기준 확정 | A01~A03 | 1~2일 | 화면 흐름·상태 전이·기기 지원표 초안 | 현재 코드와 합의 요구사항 | 수업 시작부터 삭제까지 흐름과 예외 처리가 정의됨 |
| 1. 카메라·지연 영상 안정화 | B01~B04 | 3~4일 | 안정적인 5분 순환 버퍼와 지연 재생 | 0단계 | 기준 기기에서 40분 연속 실행 중 종료·무한 메모리 증가가 없음 |
| 2. 클립 선택·저장 완성 | C01~C04 | 4~5일 | 선택 장면과 일치하는 무음 클립 | 1단계 | 미리 본 구간과 저장 파일이 일치하고 최대 30초 제한이 지켜짐 |
| 3. PIN·로컬 데이터 보호 | D01~D04 | 3~4일 | 암호화 저장·안전한 잠금·만료 삭제 | 2단계 | PIN·삭제·저장 실패·앱 재시작 시나리오 통과 |
| 4. PWA·태블릿 UX 완성 | E01~E04 | 3~4일 | 설치·오프라인·업데이트·터치 UI | 1~3단계 | 설치 후 오프라인에서도 기본 수업 흐름이 동작함 |
| 5. 실제 기기·수업 검증 | F01~F03 | 4~6일 | 기기별 결과표·모의 수업·파일럿 개선 | 4단계, 기기·수업 접근 확보 | 출시 차단 결함 해결 및 현장 준비 시간 확인 |
| 6. 첫 버전 배포 | G01~G02 | 1~2일 | HTTPS 배포본·설치 및 교사용 안내 | 5단계, 배포 위치 확정 | 배포 주소에서 설치·재실행·저장·목록·업데이트 확인 |

권장 배치: 1주 차는 0~1단계, 2주 차는 2단계, 3주 차는 3단계, 4주 차는 4단계, 5~6주 차는 기기·수업 검증과 배포에 사용한다. 실제 진행 상황에 따라 단계가 주 경계를 넘을 수 있다.

현재 방식은 480×270 JPEG 프레임을 약 10fps로 보관한다. 이를 출시 화질로 확정하지 않는다. 표준 화질 후보 640×360·15fps와 현재 저부하 방식을 비교하고, 5분 유지·발열·배터리·동작 식별성을 함께 본다. 기준 기기에서 5분 유지가 어렵다면 압축 영상 버퍼 등 대안을 검토하고 처리 구조와 일정을 재결정한다.

PIN은 6자리 숫자를 사용한다. 사용자 결정에 따라 분실 시 명확한 삭제 확인 후 모든 로컬 클립을 지우고 새 PIN을 설정하는 초기화를 제공한다. 암호화 키를 바꾸려면 기존 파일의 재암호화 또는 삭제 정책까지 함께 설계해야 하므로, 단순한 PIN 값 교체로 처리하지 않는다.

아래 기능은 원문 명세서의 제안에서 가져온 후속 후보다. 현재 사용자와 합의한 첫 출시 범위에 포함되지 않으며, 구현 순서·기능 범위·일정은 별도 결정이 필요하다.

## 8. 앞으로 순서대로 결정할 사항

사용자와의 대화에서는 아래 항목을 한 번에 하나씩 확인한다. 1~2번은 기기 검증·배포를 진행하는 데 필요하고, 나머지는 해당 기능 구현 시점에 확인한다. 이미 합의한 요구사항은 반복해서 묻지 않는다.

1. 실제 사용할 태블릿 모델·Android 버전과 검증 기기 확보 여부.
2. HTTPS 호스팅 위치와 접근 가능 여부. 확인 전까지 로컬 구현은 진행 가능.
3. 교사 PIN의 자릿수, 변경·분실 시 처리 방식.
4. 전면·후면 카메라 선택 및 좌우 반전 필요 여부.
5. 저장 구간을 5초 단위로 고르는 현재 초안이 수업에 충분한지.
6. 수업 파일럿을 진행할 교사·모둠과 가능한 일정.

## 9. 바로 다음에 진행할 작업

첫 개발 묶음은 A01~A02와 B02·C02다. 화면 상태와 모듈을 정리하고, 초기 지연 대기 및 미리보기·인코딩 충돌을 먼저 해결한다. 동시에 기기 정보를 확인해 B03 성능 측정 조건을 준비한다. 기능을 추가하기 전에 ‘본 장면이 그대로 저장된다’는 핵심 동작부터 확보한다.

### 첫 개발 묶음 진행 기록

- B02: 초기 지연 대기와 남은 시간 표시 구현. 가상 카메라 브라우저에서 대기 후 재생 전환 확인.
- C01~C02: 선택 버퍼 스냅샷 및 미리보기·인코딩 캔버스 분리 구현. 선택 시간이 입력 중 이동하지 않는 것 확인.
- C03: 원본 타임스탬프·경과 시간 기반 인코딩 구현. 5초 구간 생성 검증. 15·30초와 저사양 기기 오차 측정은 남아 있음.
- C04: 저장 중 중복 클릭·수정·닫기 차단 및 백그라운드 이동 시 저장 중단 구현.
- A01~A02: 촬영 시작·촬영·선택·저장·대기 상태와 시간 선택 로직 분리 착수. 전체 모듈 분리와 화면 중단 복구 설계는 남아 있음.
- 실제 Android 태블릿의 화질·성능·40분 연속 사용은 아직 검증하지 않음.

### 두 번째 개발 묶음 진행 기록

- 기준 기기: 사용자 선택에 따라 갤럭시 탭 A9+로 설정. 실제 기기·Android·Chrome 버전·RAM 구성은 확인 전이다.
- B01: 카메라 권한 거부·장치 없음·장치 사용 중 오류를 구분하고 재시도 흐름을 구현·검증했다.
- B03: 프레임 버퍼 모듈 분리, 5분·바이트·프레임 제한 및 합성 시각의 40분 회귀 검사를 추가했다. 실제 40분 성능 검증은 완료하지 않았다.
- B04: 연결·화면 이탈·정지 시 중단, 버퍼 단절, 사용자 명시 재시작 및 지연된 스트림 정리를 구현·검증했다.
- C03: 가상 카메라의 5·15·30초 클립을 실제 WebM 패킷 시각으로 확인했다. 30초 선택의 출력은 30.060초로, 엄밀한 파일 길이 30초 상한은 남은 제약이다.
- 결과·범위·측정 수치는 [검증 기록](validation-2026-11-05.md)에 남겼다.

### 2단계 진행 기록

C01~C04 구현 및 개발용 브라우저 검증을 완료했다. 파일 길이 5·15·30초, 미리보기·출력 구간 일치, 입력 검증·취소·중복 요청·실패 후 재시도를 확인했다. 실제 Android 확인은 남아 있다. 상세 근거와 제약은 [2단계 검증 기록](stage-2-validation.md)을 따른다.

### 3단계 진행 기록

D01~D04의 구현과 개발용 브라우저 검증을 수행했다. PIN·수업 키·목록 접근을 구분하고, v1 데이터 이전과 v2 설정 손실을 구별한다. 목록의 늦은 응답·손상 항목, 만료 경계·재생 중 만료, 공간 부족·저장 실패·초기화 원자성 및 다른 탭의 오래된 키 차단을 확인했다. [3단계 검증 기록](stage-3-validation.md)을 따른다. 실제 Android 저장 정책·성능은 미확인이다.
