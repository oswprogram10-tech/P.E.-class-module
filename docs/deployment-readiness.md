# 배포 준비표 — 호스팅 중립 체크리스트

상태: **G01 대기**. 이 문서는 실제 배포 실행 기록이 아니라, 호스팅 위치와 계정이 정해진 뒤 확인할 **준비표**다.

- HTTPS 호스팅 위치·주소·계정은 **아직 정해지지 않았다.**
- 실제 사이트를 공개·배포하지 않았다.
- F01 실기기 검증과 F03 수업 파일럿은 **대기** 중이다.
- 따라서 G01과 6단계 전체는 **완료가 아니다.**

배포 주소가 정해지면 `{{HTTPS_BASE_URL}}` 자리표시자를 실제 HTTPS 주소로 바꾸고, 아래 항목을 순서대로 확인해 결과를 마지막 표에 기록한다.

## 0. 선행 조건

- [ ] 배포 위치(호스트·경로)와 계정 접근 권한이 확정됐다.
- [ ] HTTPS 인증서와 도메인(또는 제공되는 HTTPS 주소)이 준비됐다.
- [ ] 배포 담당자와 롤백 담당자가 정해졌다.
- [ ] 이전 배포본을 복원할 수 있도록 현재 파일 묶음과 버전을 보관했다.
- [ ] 실제 학생 영상·이름·번호가 아닌 검증용 데이터로 점검할 계획이다.
- [ ] F01 실기기 검증과 F03 수업 파일럿 결과를 확인했다. 미완료라면 배포를 보류하고 사유를 기록한다.

## 1. HTTPS와 정적 파일

- [ ] `{{HTTPS_BASE_URL}}`이 유효한 인증서로 HTTPS 접속된다. HTTP로 접속하면 HTTPS로 이동하거나 접속을 거부한다.
- [ ] 혼합 콘텐츠가 없다. 외부 폰트·CDN·분석 스크립트를 사용하지 않는다.
- [ ] 다음 정적 파일 **전체**를 같은 배포 단위로 올렸다.
  - `index.html`
  - `styles.css`
  - `app.js`, `local-vault.js`, `clip-repository.js`, `webm-muxer.js`, `clip-exporter.js`, `timeline.js`, `frame-buffer.js`
  - `manifest.webmanifest`
  - `icon.svg`, `icon-192.png`, `icon-512.png`
  - `sw.js`
- [ ] 앱 셸 14개가 `sw.js`의 `APP_SHELL` 목록과 일치한다. `sw.js` 자체는 서비스 워커 파일로 별도 제공되며 앱 셸 캐시 목록에는 포함되지 않는다. 파일을 추가·삭제하면 목록과 `CACHE_VERSION`도 함께 갱신한다.
- [ ] 서버가 하위 경로에 배포하더라도 `./` 기준 상대 경로가 유지된다. `index.html`·`manifest.webmanifest`·`sw.js`의 경로를 임의로 절대 경로로 바꾸지 않는다.
- [ ] `manifest.webmanifest`가 `application/manifest+json`으로 제공된다.
- [ ] `.js`는 JavaScript, `.css`는 CSS, `.svg`는 `image/svg+xml`, `.png`는 `image/png`로 제공된다.
- [ ] `sw.js`가 캐시에 오래 남지 않도록 재검증되게 제공된다. 앱은 `updateViaCache: 'none'`으로 등록하지만, 서버가 오래된 `sw.js`를 고정 제공하면 업데이트를 감지하지 못한다.
- [ ] `index.html`이 디렉터리 요청(`/` 또는 배포 하위 경로의 디렉터리 요청)에서 정상 제공된다. `start_url`과 `scope`는 `./`다.
- [ ] 서비스 워커 범위가 앱 경로 전체를 포함하되 불필요하게 넓은 경로를 제어하지 않도록, `sw.js` 위치와 배포 경로를 함께 확인한다.

## 2. 설치·매니페스트

- [ ] 매니페스트의 `id`, `start_url`, `scope`가 실제 배포 경로와 맞는다.
- [ ] `name`, `short_name`, `theme_color`, `background_color`, `display`가 의도한 값이다.
- [ ] 192×192·512×512 PNG 아이콘과 SVG 아이콘이 모두 200으로 제공된다.
- [ ] Chrome에서 **앱 설치** 버튼 또는 **⋮ → 앱 설치/홈 화면에 추가**가 동작한다.
- [ ] 설치된 앱이 standalone으로 열리고, 주소 표시줄 없이 앱 화면이 표시된다.

> 실제 Android 기기에서의 설치 동작은 아직 검증하지 않았다. 이 항목은 배포 후 실기기에서 확인한다.

## 3. 서비스 워커와 Cache API

- [ ] 첫 온라인 실행에서 서비스 워커가 설치·활성화되고, 앱 셸 캐시가 만들어진다.
- [ ] Cache Storage에 `pe-loop-shell-<version>` 캐시가 있고, 항목이 앱 셸 14개와 일치한다.
- [ ] 캐시에 **PIN, 암호화 키, 클립, 학생 이름·번호, IndexedDB 데이터가 없다.**
- [ ] 클립과 PIN 설정은 IndexedDB에만 있으며, Cache API와 분리되어 있다.
- [ ] 셸 파일 하나가 404·오류면 부분 캐시를 남기지 않고 설치가 실패하며, 앱이 **다시 시도**를 안내한다.
- [ ] 활성화 시 같은 `pe-loop-shell-` 접두사의 이전 버전 캐시만 삭제되고, 다른 앱 캐시와 IndexedDB는 유지된다.
- [ ] `skipWaiting()`·`clients.claim()`으로 열린 수업 화면을 강제 전환하지 않는다.
- [ ] 탐색 요청은 현재 버전의 `index.html`로 응답하고, 캐시와 네트워크가 모두 실패하면 외부 리소스 없는 오프라인 안내를 표시한다.

## 4. 배포 버전과 롤백

배포마다 다음을 기록한다.

- 배포 일시
- 배포한 커밋 또는 파일 묶음 식별자
- `sw.js`의 `CACHE_VERSION`
- 배포 주소와 경로
- 확인한 기기·Chrome 버전

절차:

1. 앱 셸 파일이 하나라도 바뀌면 `sw.js`의 `CACHE_VERSION`을 올린다. 파일만 바꾸고 `sw.js`를 그대로 두면 업데이트가 감지되지 않을 수 있다.
2. 이전 버전으로 되돌릴 때는 이전 파일 묶음 전체를 기준으로 하되, `sw.js`의 `CACHE_VERSION`만 새 고유 값으로 바꾼 롤백 배포본을 만든다. 일부 파일만 섞어 배포하지 않는다.
3. 롤백도 **새 배포**로 취급한다. 이전 캐시 이름을 그대로 재사용하지 않는다.
4. 롤백 후 `sw.js`가 새로 제공되는지 확인한다. 캐시를 수동으로 지우거나 사이트 데이터를 삭제하지 않는다. 활성화 단계가 같은 접두사의 이전 셸 캐시를 정리한다.
5. 롤백 후 PIN과 기존 클립이 유지되는지 확인한다. IndexedDB는 서비스 워커 캐시 정리와 별개다.
6. 문제가 된 배포본은 원인 분석을 위해 보관한다.

> 캐시를 수동 삭제하거나 브라우저 사이트 데이터를 지우면 PIN과 클립이 사라질 수 있다. 롤백은 파일 배포와 서비스 워커 버전 갱신으로 처리한다.

## 5. 배포 후 Android Chrome 확인

일반 탭과 설치 PWA에서 각각 확인한다.

- [ ] `{{HTTPS_BASE_URL}}`을 Android Chrome 일반 탭으로 연다. 첫 화면이 끝까지 로드된다.
- [ ] 카메라 권한이 앱을 연 즉시가 아니라 **카메라 시작**을 누른 뒤에만 요청된다.
- [ ] 교사 PIN을 설정·입력하고 카메라를 시작할 수 있다.
- [ ] 설정한 지연 시간만큼 버퍼가 쌓인 뒤 지연 영상이 재생된다.
- [ ] 검증용 이름·번호로 5초 클립을 저장하고, 목록에서 재생·삭제할 수 있다.
- [ ] **잠그기** 후 다시 PIN을 요구한다.
- [ ] 앱을 완전히 닫았다 다시 열어도 PIN과 클립이 유지된다.
- [ ] 홈 화면에 설치하고 standalone으로 연다. 같은 흐름이 동작한다.
- [ ] 앱 셸이 준비된 뒤 비행기 모드로 전환하고 앱을 다시 연다. 이미 캐시된 화면이 열리고 PIN·클립이 유지된다.
- [ ] 비행기 모드에서 카메라 시작·지연 재생·클립 저장이 가능한지 확인한다.
- [ ] 새 버전을 배포했을 때 **새 버전이 준비됐어요** 배너가 표시되고, **나중에**로 닫을 수 있다.
- [ ] 앱을 완전히 닫았다 다시 열면 새 버전이 적용되고 PIN·클립이 유지된다.
- [ ] 롤백 배포 후 앱을 완전히 닫았다 다시 열어 이전 버전이 적용되고 PIN·클립이 유지된다.
