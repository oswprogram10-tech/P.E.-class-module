# S5.6 학생 휴대폰-교사 태블릿 릴레이 계약

기록일: 2026-11-06, Android 호스트 APK 및 companion: 2026-11-07, Apple Swift source scaffold: 2026-11-07. 사용자가 선택한 학생별 페어링 휴대폰 → 같은 로컬 Wi-Fi → Android 교사 태블릿 네이티브 수신 앱 경로를 구체화한다. 사용자는 Wi-Fi 복구 뒤 휴대폰이 자동 재연결하는 방식을 선택했다. Android 세 모듈의 JVM 테스트·debug APK 조립과 Lint 결과, Apple 소스 미검증 범위는 [웨어러블 검증 기록](stage-S5.6-wearable-validation.md)에 있다. Android APK 설치, Apple Xcode 빌드/서명, 실제 기기 연결은 남아 있다.

## 구성 요소와 책임

| 구성 요소 | 책임 |
| --- | --- |
| 교사 PWA (태블릿 WebView) | 학생을 화면에서 선택하고 학생·보호자 동의를 확인한다. 선택된 학생과 익명 참가자 토큰의 연결은 이 화면 메모리 안에만 둔다. 심박 최신값만 표시하고 표본 기록은 만들지 않는다. |
| 교사 태블릿 네이티브 호스트 | Android 앱이 한시적 연결 초대를 만들고 TLS WebSocket으로 학생 휴대폰 연결을 받도록 구현했다. PWA와 출처 제한 Web Message 브리지로 통신하며, 허용된 심박 표본만 전달한다. 활성 연결 정보와 최신 표본은 RAM에서 관리한다. API 35 debug APK 빌드·단위 검사·Lint는 통과했으며 설치·실기기 검증은 남아 있다. |
| 학생 Android 휴대폰 앱 | QR을 스캔하고 사설 LAN 호스트에 TLS 공개키 지문 고정 WebSocket으로 연결한다. RAM 전용 재접속 자격, DNS-SD 탐색, 자동 백오프 재시도, 학생·보호자 동의 확인을 구현했다. Wear Data Layer를 통해 워치 세션을 시작·중지하고 심박 표본을 릴레이한다. 실기기 연결은 미검증이다. |
| Galaxy Watch 앱 | Wear OS Health Services `ExerciseClient`가 `WORKOUT` 운동 유형에서 `HEART_RATE_BPM`을 지원하는지 매번 확인한다. 사용자가 워치 OS 권한을 허용했고 휴대폰이 현재 수업 토큰을 보낸 경우에만 표본을 휴대폰으로 전달한다. 앱은 GPS·다른 건강 항목·운동 기록 파일을 저장하지 않는다. 모델 카탈로그는 잠정 후보이며 실기기 검증 전 지원 인증이 아니다. |
| Apple Watch / iPhone 앱 | HealthKit 운동 세션과 WatchConnectivity 경로의 Swift source scaffold를 추가했다. Swift 빌드·서명·실기기 검증은 Xcode가 없어 아직 하지 않았다. |

기존 `wearable-bridge.js` v1은 교사 WebView에 직접 연결된 네이티브 앱이 권한 요청과 워치 읽기를 모두 수행하는 형태였다. 이를 선택된 분산 구조에 맞춰 v2로 바꿔, 교사 WebView는 학생·보호자 동의 확인 후 초대 QR 생성·표본 수신·종료를 요청하고 학생 페어링 휴대폰이 권한 요청과 워치 접근을 맡는다. Android 호스트는 최초 연결에 QR 일회성 자격을 쓰고, TLS 연결이 성공하면 휴대폰에 RAM 전용 재접속 자격을 전달한다. 학생 Android/Wear OS 앱의 로컬 구현은 있지만 APK 설치, Wi-Fi 복구, 실기기 전송은 아직 검증되지 않았다.

## 연결 흐름

1. 교사가 학생을 선택하고 이 수업에서 학생 본인과 보호자의 심박 수집 동의를 확인한다. 두 동의가 모두 확인되지 않으면 초대를 만들지 않는다.
2. PWA는 학생 ID나 이름을 넣지 않은 무작위 참가자 토큰을 생성해 네이티브 호스트에 넘긴다. Android 호스트 소스는 현재 연결을 위한 일회성 QR 초대를 반환한다.
3. 초대 payload는 `PELOOP_PAIR_V1.<base64url(UTF-8 JSON)>` 형식으로 만든다. JSON 필드는 정확히 `v`, `host`, `port`, `sessionId`, `ticket`, `fingerprint`, `expiresAt` 일곱 개다. `host`는 사설 IPv4, `sessionId`는 임시 UUID, `ticket`은 256-bit CSPRNG 일회용 값, `fingerprint`는 TLS 인증서 공개키 SHA-256 64자리 hex, `expiresAt`은 태블릿 기준 현재 시각부터 최대 2분 뒤다. `sessionId`로 LAN DNS-SD 서비스를 찾아 IP가 바뀌어도 현재 연결을 확인한다. 학생·학급 식별자, 심박값, 장기 토큰과 추가 필드는 거부한다. 초대는 2분 안에 사용되거나 한 번 연결되면 폐기한다.
4. 학생 companion이 초대를 스캔하고 태블릿 TLS 공개키 지문을 확인한 뒤 보안 WebSocket 연결을 연다. 태블릿은 일회성 자격이 유효하고 미사용인지 확인하고 `session-ready` 응답에 `sessionId`, RAM 전용 재접속 자격, `serverTime`을 포함한다. 복귀 연결의 `session-resumed`에는 `sessionId`와 `serverTime`을 포함한다. 휴대폰은 응답의 태블릿 시각을 기준으로 심박 측정 시각을 변환해 보낸다. 공용 Wi-Fi라는 이유만으로 평문 HTTP를 쓰지 않는다.
5. 휴대폰 companion에서 워치 연결과 필요한 OS 심박 권한을 확인한다. 권한을 얻지 못하거나 표본이 생기지 않아도 수업은 계속되며 심박값/기록은 비워 둔다. Apple HealthKit은 읽기 거부 자체를 앱에서 구별할 수 없으므로 공통 사용자 메시지는 “측정값 없음”으로 둔다.
6. 휴대폰은 심박수와 측정 시각만 보안 연결로 보낸다. 태블릿 호스트는 표본을 PWA의 현재 화면에 전달한다. 이름·학생 ID·학급 ID·기기 일련번호는 LAN 메시지에 넣지 않는다.
7. Wi-Fi 연결이 끊기면 기존 표본은 즉시 숨기고 기록 공백을 연다. 학생 Android 앱은 QR의 기존 주소로 접속을 시도하고 실패하면 `sessionId`와 TLS 지문이 일치하는 DNS-SD 서비스를 탐색한다. 주소가 변경되면 새 주소·포트를 사용한다. 태블릿이 `session-resumed`를 응답하면 휴대폰은 매 연결마다 새로 발급한 휘발성 워치 세션 토큰으로 측정을 다시 시작하고 새 표본만 전송한다. 로컬 탐색 실패 시 교사에게 새 QR을 요청하라고 안내한다. 이 흐름은 소스에 구현했지만 Wi-Fi 복구 시험은 미실시다.
8. PWA는 활성 화면 메모리에만 참가자 토큰과 화면의 선택 학생 사이 대응을 둔다. 5초 동안 새 표본이 없으면 이전 수치를 숨긴다. 연결 종료나 수업 세션 종료 때 값, 토큰, 초대 및 세션 상태를 지운다.

## 전송 및 보관 경계

- 전송은 로컬 네트워크의 TLS 1.2 이상 WebSocket을 사용하고, 학생 companion은 QR에 포함된 태블릿 공개키 지문을 고정(pin)해 다른 로컬 장치의 서버를 거부한다. PWA는 QR 형식·필드 목록·사설 IPv4·포트·토큰/지문 형식·2분 만료를 검사한다. 키/인증서 갱신 시 새 초대 QR에서 새 지문을 전달한다.
- QR의 `ticket`은 최초 연결 한 번에만 쓴다. 최초 TLS 인증 응답이 돌려주는 256-bit `resumeToken`은 휴대폰 앱 메모리에서만 유지하고, Wi-Fi 복구 후 같은 TLS 지문·주소·포트의 연결에 Bearer 자격으로 제출한다. 학생·학급 ID나 장기 계정 토큰을 쓰지 않는다. 교사가 재페어링하거나 세션을 종료하면 재접속 자격을 폐기한다.
- 표본은 RAM 안에서 화면에 필요한 최신 값만 유지한다. 파일, 데이터베이스, IndexedDB, Service Worker 캐시, 기존 학급 저장소, `server/classroom-hub.js`, 오프라인 재전송 큐, 로그, 분석 이벤트에는 기록하지 않는다.
- 네트워크 단절 구간에 만들어진 측정값은 재전송하지 않는다. 이 규칙은 사용자가 지정한 “기록 공백”을 지킨다. 자동 재연결은 세션을 새로 만들지 않고 기존 TLS 호스트로 복귀시킨다. Android 호스트는 QR의 `sessionId`와 공개키 지문을 TXT 레코드에 실어 `_peloop-wearable._tcp.` DNS-SD 서비스를 재광고하고, 학생 Android 앱은 이 정보를 확인해 탐색·재접속한다. 표본마다 연결별 휘발성 토큰을 검증해 이전 연결에서 늦게 도착한 메시지는 거부한다. 이 경계는 단위 수준만 검사했으며 실제 네트워크 끊김은 미검증이다.
- 연결이 끝나면 서버 소켓과 초대 자격을 즉시 닫고 메모리 참조를 제거한다. 호스트 프로세스 종료도 활성 초대와 세션을 모두 폐기한다.
- `server/classroom-hub.js`는 loopback 전용이고 기존 학급 제출을 RAM에 보관하므로 LAN 릴레이로 재사용하거나 LAN 인터페이스에 노출하지 않는다.

## 구현 단계

1. **완료:** PWA/호스트 브리지 v2, 연결 QR UI, 가짜 네이티브 호스트를 구현했다. 동의 게이트, 초대 흐름, 휴대폰 권한 실패 시 공백, 값 숨김/QR 재연결, 메모리 전용 상태를 단위·브라우저 검사로 확인했다.
2. **구현·APK 빌드 완료:** Android 태블릿 호스트에 신뢰된 WebView, 출처 제한 Web Message 브리지, TLS 수신기, 일회용 티켓·2분 만료, RAM 전용 세션과 심박 프레임 검사 및 재접속 자격 발급/검증을 추가했다. API 35 debug APK, JVM 단위 검사, Lint(0 오류·0 경고)가 통과했다. 설치·실기기 확인은 남아 있다.
3. **Android/Wear OS 로컬 구현 완료:** 학생 휴대폰 QR 스캔·동의 확인·TLS 지문 검사·재접속/탐색과 Wear Data Layer를 연결했다. Wear 앱은 워치 권한과 Health Services capability를 확인한 뒤 심박 항목만 보낸다. 단위 테스트와 APK 조립/Lint 결과는 검증 기록에 있다.
4. **Swift source scaffold 완료·플랫폼 빌드 대기:** iOS 앱은 QR 스캔, 학생/보호자 동의, TLS 지문 고정, Bonjour 탐색, 휘발성 재접속·심박 전달을 구현하는 소스를 추가했다. watchOS 쪽은 HealthKit workout session과 토큰으로 묶은 WatchConnectivity 메시지를 추가했다. macOS/Xcode 빌드·서명·실기기 확인 전에는 동작 완료로 간주하지 않는다.
5. Android 태블릿·학생 휴대폰·Galaxy Watch의 세 APK를 설치하고 Apple 앱을 Xcode로 생성·서명해 최초 QR, 권한 거부, 센서 부재, 연결 끊김, 태블릿 IP 변경, 재연결 공백을 기기에서 검증한다. 두 앱 생태계의 실기기 시험은 각각 수행한다.
6. [기기 적격성 표](S5.6-device-support-matrix.md)에 잠정 모델 후보와 API·출시일 기준을 기록했다. 공식 모델 ID·출시일·최소 OS 전체 대조와 모델별 실제 시험 전까지 검증된 지원 모델은 없다.

## 남은 기술 제약

- Android SDK/Gradle은 이번 검증에서 `/tmp` 임시 경로에 구성했으며, Android APK 컴파일·서명을 확인했다. Xcode/iOS 빌드 환경은 없고 iOS/watchOS 빌드·서명은 확인하지 않았다.
- 실제 기기·OS 조합, WatchConnectivity 지연, Wear OS 화면 꺼짐/ambient, 학교 Wi-Fi의 클라이언트 격리 여부는 아직 검증하지 않았다.
- 자동 복구에는 실행 중인 휴대폰 companion이 필요하다. Android 호스트는 Wi-Fi 주소 변경 시 TLS 수신기를 새 주소에 다시 묶고 DNS-SD 서비스를 재광고하며 학생 Android 앱은 서비스 탐색·재접속·QR 안내를 구현했다. APK 설치 및 실제 네트워크 확인은 대기 중이다.
- 학생별 한 번에 한 개 연결이라는 현재 화면 흐름에 맞춰 기술한 초안이다. 동시 다학생 측정은 이 계약의 범위에 포함하지 않는다.
