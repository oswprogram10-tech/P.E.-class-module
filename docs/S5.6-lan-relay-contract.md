# S5.6 학생 휴대폰-교사 태블릿 릴레이 계약

기록일: 2026-11-06, PWA v2·Android 호스트 소스 및 APK 갱신: 2026-11-07. 사용자가 선택한 학생별 페어링 휴대폰 → 같은 로컬 Wi-Fi → Android 교사 태블릿 네이티브 수신 앱 경로를 구체화한다. 사용자는 Wi-Fi 복구 뒤 휴대폰이 자동 재연결하는 방식을 선택했다. Android API 35 debug APK 빌드, JVM 검사, Lint(0 오류·0 경고)는 통과했다. 실기기 검증과 학생 companion은 남아 있으며 자세한 결과는 [웨어러블 검증 기록](stage-S5.6-wearable-validation.md)에 있다.

## 구성 요소와 책임

| 구성 요소 | 책임 |
| --- | --- |
| 교사 PWA (태블릿 WebView) | 학생을 화면에서 선택하고 학생·보호자 동의를 확인한다. 선택된 학생과 익명 참가자 토큰의 연결은 이 화면 메모리 안에만 둔다. 심박 최신값만 표시하고 표본 기록은 만들지 않는다. |
| 교사 태블릿 네이티브 호스트 | Android 앱이 한시적 연결 초대를 만들고 TLS WebSocket으로 학생 휴대폰 연결을 받도록 구현했다. PWA와 출처 제한 Web Message 브리지로 통신하며, 허용된 심박 표본만 전달한다. 활성 연결 정보와 최신 표본은 RAM에서 관리한다. API 35 debug APK 빌드·단위 검사·Lint는 통과했으며 설치·실기기 검증은 남아 있다. |
| 학생 페어링 휴대폰 앱 | QR 초대를 읽고 대상 워치에 맞는 제조사/OS 경로로 심박 측정을 시작한다. 필요한 OS 권한은 이 휴대폰에서 요청한다. 받은 표본을 태블릿으로 전달한다. |
| Apple Watch / Galaxy Watch 앱 | Apple Watch는 HealthKit 운동 세션과 WatchConnectivity, Galaxy Watch는 Wear OS Health Services `ExerciseClient`를 우선 사용한다. 워치에서 읽은 데이터는 연결된 학생 휴대폰 앱으로만 전달한다. |

기존 `wearable-bridge.js` v1은 교사 WebView에 직접 연결된 네이티브 앱이 권한 요청과 워치 읽기를 모두 수행하는 형태였다. 이를 선택된 분산 구조에 맞춰 v2로 바꿔, 교사 WebView는 동의 확인 후 초대 QR 생성·표본 수신·종료를 요청하고 학생 휴대폰 companion이 권한 요청과 워치 접근을 맡게 했다. Android 호스트는 최초 연결에 QR 일회성 자격을 쓰고, TLS 연결이 성공하면 휴대폰에 RAM 전용 재접속 자격을 전달한다. 호스트 소스는 이를 검증할 준비가 되었지만 휴대폰 companion은 아직 없어 실제 자동 재접속은 구현·검증되지 않았다.

## 연결 흐름

1. 교사가 학생을 선택하고 이 수업에서 학생 본인과 보호자의 심박 수집 동의를 확인한다. 두 동의가 모두 확인되지 않으면 초대를 만들지 않는다.
2. PWA는 학생 ID나 이름을 넣지 않은 무작위 참가자 토큰을 생성해 네이티브 호스트에 넘긴다. Android 호스트 소스는 현재 연결을 위한 일회성 QR 초대를 반환한다.
3. 초대 payload는 `PELOOP_PAIR_V1.<base64url(UTF-8 JSON)>` 형식으로 만든다. JSON 필드는 정확히 `v`, `host`, `port`, `sessionId`, `ticket`, `fingerprint`, `expiresAt` 일곱 개다. `host`는 사설 IPv4, `sessionId`는 임시 UUID, `ticket`은 256-bit CSPRNG 일회용 값, `fingerprint`는 TLS 인증서 공개키 SHA-256 64자리 hex, `expiresAt`은 태블릿 기준 현재 시각부터 최대 2분 뒤다. `sessionId`로 LAN DNS-SD 서비스를 찾아 IP가 바뀌어도 현재 연결을 확인한다. 학생·학급 식별자, 심박값, 장기 토큰과 추가 필드는 거부한다. 초대는 2분 안에 사용되거나 한 번 연결되면 폐기한다.
4. 학생 companion이 초대를 스캔하고 태블릿 TLS 공개키 지문을 확인한 뒤 보안 WebSocket 연결을 연다. 태블릿은 일회성 자격이 유효하고 미사용인지 확인하고 `session-ready` 응답에 재접속 자격을 포함한다. 공용 Wi-Fi라는 이유만으로 평문 HTTP를 쓰지 않는다.
5. 휴대폰 companion에서 워치 연결과 필요한 OS 심박 권한을 확인한다. 권한을 얻지 못하거나 표본이 생기지 않아도 수업은 계속되며 심박값/기록은 비워 둔다. Apple HealthKit은 읽기 거부 자체를 앱에서 구별할 수 없으므로 공통 사용자 메시지는 “측정값 없음”으로 둔다.
6. 휴대폰은 심박수와 측정 시각만 보안 연결로 보낸다. 태블릿 호스트는 표본을 PWA의 현재 화면에 전달한다. 이름·학생 ID·학급 ID·기기 일련번호는 LAN 메시지에 넣지 않는다.
7. Wi-Fi 연결이 끊기면 기존 표본은 즉시 숨기고 기록 공백을 연다. 학생 휴대폰 companion은 재접속 자격과 QR의 주소·포트로 먼저 재시도하고, 주소가 바뀐 경우 QR의 `sessionId`로 DNS-SD 서비스를 찾아 현재 주소·포트를 얻는다. 태블릿이 `session-resumed`를 응답하면 휴대폰은 워치 준비 정보를 다시 보내고 새 표본부터 전송한다. 로컬 탐색이 실패하면 휴대폰에서 교사에게 새 QR을 요청하라고 안내한다. 공백 구간 값은 재전송하지 않는다.
8. PWA는 활성 화면 메모리에만 참가자 토큰과 화면의 선택 학생 사이 대응을 둔다. 5초 동안 새 표본이 없으면 이전 수치를 숨긴다. 연결 종료나 수업 세션 종료 때 값, 토큰, 초대 및 세션 상태를 지운다.

## 전송 및 보관 경계

- 전송은 로컬 네트워크의 TLS 1.2 이상 WebSocket을 사용하고, 학생 companion은 QR에 포함된 태블릿 공개키 지문을 고정(pin)해 다른 로컬 장치의 서버를 거부한다. PWA는 QR 형식·필드 목록·사설 IPv4·포트·토큰/지문 형식·2분 만료를 검사한다. 키/인증서 갱신 시 새 초대 QR에서 새 지문을 전달한다.
- QR의 `ticket`은 최초 연결 한 번에만 쓴다. 최초 TLS 인증 응답이 돌려주는 256-bit `resumeToken`은 휴대폰 앱 메모리에서만 유지하고, Wi-Fi 복구 후 같은 TLS 지문·주소·포트의 연결에 Bearer 자격으로 제출한다. 학생·학급 ID나 장기 계정 토큰을 쓰지 않는다. 교사가 재페어링하거나 세션을 종료하면 재접속 자격을 폐기한다.
- 표본은 RAM 안에서 화면에 필요한 최신 값만 유지한다. 파일, 데이터베이스, IndexedDB, Service Worker 캐시, 기존 학급 저장소, `server/classroom-hub.js`, 오프라인 재전송 큐, 로그, 분석 이벤트에는 기록하지 않는다.
- 네트워크 단절 구간에 만들어진 측정값은 재전송하지 않는다. 이 규칙은 사용자가 지정한 “기록 공백”을 지킨다. 자동 재연결은 세션을 새로 만들지 않고 기존 TLS 호스트로 복귀시킨다. Android 호스트는 QR의 `sessionId`와 공개키 지문을 TXT 레코드에 실어 `_peloop-wearable._tcp.` DNS-SD 서비스를 재광고한다. 휴대폰의 서비스 탐색과 공백 뒤 재접속은 아직 구현되지 않았다.
- 연결이 끝나면 서버 소켓과 초대 자격을 즉시 닫고 메모리 참조를 제거한다. 호스트 프로세스 종료도 활성 초대와 세션을 모두 폐기한다.
- `server/classroom-hub.js`는 loopback 전용이고 기존 학급 제출을 RAM에 보관하므로 LAN 릴레이로 재사용하거나 LAN 인터페이스에 노출하지 않는다.

## 구현 단계

1. **완료:** PWA/호스트 브리지 v2, 연결 QR UI, 가짜 네이티브 호스트를 구현했다. 동의 게이트, 초대 흐름, 휴대폰 권한 실패 시 공백, 값 숨김/QR 재연결, 메모리 전용 상태를 단위·브라우저 검사로 확인했다.
2. **구현·APK 빌드 완료:** Android 태블릿 호스트에 신뢰된 WebView, 출처 제한 Web Message 브리지, TLS 수신기, 일회용 티켓·2분 만료, RAM 전용 세션과 심박 프레임 검사 및 재접속 자격 발급/검증을 추가했다. API 35 debug APK, JVM 단위 검사, Lint(0 오류·0 경고)가 통과했다. 설치·실기기 확인은 남아 있다.
3. 학생 iOS/watchOS와 Android/Wear OS companion에서 초대 스캔, 장치 권한, 표본 전달을 연결한다.
4. Android/iOS 학생 companion에서 재접속 자격을 메모리에 유지하고 백오프 재시도를 연결한다. 실제 호스트 앱과 Wi-Fi 라우터에서 단절·복구를 확인한다.
5. 모델 식별자·출시일·최소 OS 지원표와 OS 권한 실패·기기/네트워크 끊김 검증을 추가한다. 실제 기기 연결은 별도 시험한다.

## 남은 기술 제약

- Android SDK/Gradle은 이번 검증에서 `/tmp` 임시 경로에 구성했으며, Android APK 컴파일·서명을 확인했다. Xcode/iOS 빌드 환경은 없고 iOS/watchOS 빌드·서명은 확인하지 않았다.
- 실제 기기·OS 조합, WatchConnectivity 지연, Wear OS 화면 꺼짐/ambient, 학교 Wi-Fi의 클라이언트 격리 여부는 아직 검증하지 않았다.
- 자동 복구에는 재접속 중인 휴대폰 companion이 필요하다. Android 호스트 소스는 Wi-Fi 주소 변경 시 TLS 수신기를 새 주소에 다시 묶고 DNS-SD 서비스를 재광고하도록 작성했다. companion의 서비스 탐색·재접속과 발견 실패 후 새 QR 안내는 아직 구현·검증되지 않았다.
- 학생별 한 번에 한 개 연결이라는 현재 화면 흐름에 맞춰 기술한 초안이다. 동시 다학생 측정은 이 계약의 범위에 포함하지 않는다.
