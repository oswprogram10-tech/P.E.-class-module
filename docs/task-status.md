## 현재 단계 판정

- 0단계: A01·A02의 설계 산출물 완료. A03의 실제 기기 확인이 남아 **전체 완료 아님**.
- 1단계: 개발용 구현·브라우저 검증 근거는 확보했으나 B03의 40분 실기기 완료 조건을 충족하지 않아 **전체 완료 아님**.
- 2단계: C01~C04 구현·개발용 브라우저 검증 완료. A9+의 WebCodecs·저장 성능 확인이 남아 **전체 완료 아님**.
- 3단계: D01~D04 구현·개발용 브라우저 검증 완료. A9+의 저장 정책·용량·복호화 확인이 남아 **전체 완료 아님**.
- 4단계: E01~E04 구현과 개발용 브라우저 검증을 마쳤다. 실제 A9+ 설치·비행기 모드·가상 키보드·업데이트 적용·HTTPS 배포가 남아 **전체 완료 아님**.
- 5단계: F02 합성 영상 회귀 검증은 통과했다. `browser-clips.cjs`는 최신 클립을 `createdAt` 기준으로 선택하도록 유지하고, seeked 선등록·`video.seeking`/`currentTime` 확인·rVFC·정수 초 경계 회피 표본으로 프레임 검사를 보강한 뒤 5회 연속 5/5 통과했다. 제품 코드는 변경하지 않았다. F01 실기기와 F03 수업 파일럿은 기기·수업 접근과 학교 안내·동의 절차 확인 전이라 **대기**이며, 5단계 전체는 **완료 아님**.
- 사용자가 ‘실기기 확인은 당분간 어려움’으로 답했으므로 같은 정보 제공이나 검증을 다시 요청하며 진행을 멈추지 않는다. 확보 전에는 지원 버전·성능 결과를 미확인으로 유지한다.

## B02 추가 측정

환경: Linux Chromium 155.0.8059.79, 가상 카메라. 설정별 표시 프레임의 시각 차이를 8회 표본으로 확인했다. 실제 Android나 광학 입력 지연 측정을 뜻하지 않는다.

| 설정 | 최소 프레임 나이 | 최대 프레임 나이 | 선택 소스와 표시 픽셀 | 판정 |
| --- | ---: | ---: | --- | --- |
| 1초 | 1.0018초 | 1.1390초 | 일치 | 목표 ±0.5초 이내 |
| 20초 | 19.9613초 | 20.1303초 | 일치 | 목표 ±0.5초 이내 |
| 60초 | 60.0231초 | 60.1299초 | 일치 | 목표 ±0.5초 이내 |

1→20→60→1초 변경을 실행했다. 버퍼가 부족한 긴 지연으로 바꾸면 대기 화면으로 전환하고, 충분한 짧은 지연으로 바꾸면 재생으로 복귀했다. 소스 프레임과 표시 캔버스의 픽셀 일치를 확인했다.

## 5단계 추가 상태

| ID | 자동화·개발 검증 | 실제 기기·수업 | 근거 |
| --- | --- | --- | --- |
| F01 | 결과표만 준비 | **대기**: A9+·저사양 기기 미확보, HTTPS 주소 미정 | [5단계 검증](stage-5-validation.md), [B03·B04 절차](B03-B04-device-check.md) |
| F02 | **통과**: 1·20·60초 지연, 5·15·30초 선택·저장 장면, 중복 저장, 잘못된 PIN, 7일 경계, 저장소·트랜잭션 실패, 손상 클립 격리. seek 안정화 후 `browser-clips.cjs` 5회 연속 5/5 통과 | Android WebCodecs·성능 대기 | `browser-delay.cjs`, `browser-clips.cjs`, `browser-data.cjs`, `browser-reset.cjs` |
| F03 | 기록표만 준비 | **대기**: 파일럿 교사·모둠·일정, 학교 안내·동의 절차 미확인 | [5단계 검증](stage-5-validation.md) |

- F02는 합성 가상 카메라와 격리된 브라우저 컨텍스트에서 확인했다. 실제 학생 영상·이름·번호는 사용하지 않았다.
- `browser-clips.cjs`는 새로 저장한 클립을 IndexedDB `getAll()` 순서의 마지막 항목으로 가정하지 않고, `createdAt`이 가장 최근인 레코드로 선택한다.
- 프레임 검사는 `currentTime` 설정 전에 `seeked` 처리기를 등록하고, `video.seeking === false`·`currentTime` 목표 도달을 확인한 뒤 rVFC로 프레임 표시를 기다린다. 표본은 정수 초 경계에서 0.5초 떨어진 내부 시점을 사용한다. 픽셀 허용치는 넓히지 않았다.
- 검토 환경(Linux Chromium 155)의 간헐적 이전 프레임 읽기는 제품 코드가 아니라 테스트의 비동기 seek·합성 타이밍 경합으로 판단했다. 이 환경(Windows Chrome 156)에서 수정 후 5회 연속 실행해 모두 통과했으며, Linux Chromium 155에서의 반복 결과는 아직 없다.
- `ffprobe`/FFmpeg가 없어 `browser-smoke.cjs`의 WebM 패킷 끝 시각·오디오 트랙 부재 검사는 이번 환경에서 실행하지 못했다. Chrome 재생 기반 길이·장면 검사만 통과로 기록했다.
- F01·F03은 결과표와 기록표만 준비했으며, 측정값이나 파일럿 결과를 만들어 기록하지 않았다.
- F02 통과로 F01의 실기기 결과나 F03의 현장 결과를 대신하지 않는다. 5단계 전체는 완료가 아니다.
