## 후속 S3 — 학급·수업·학생 기록 (2026-11-06 한국 시간)

S3.1~S3.7의 로컬 기능과 동일 호스트 개발 허브 연계를 구현했다. PIN 암호화 공통 ID/명단·수업·모둠·기기, 직접 선택 제출·성찰·교사 관찰·이력, QR 참여·모드, offline queue·재전송/삭제, 교사 승인형 텍스트 피드백을 제공한다. 기존 이름/번호 클립의 임의 배정과 수동 이관은 하지 않는다.

실제 HTTP 권한·멱등성·부분실패와 별도 PIN/DB 브라우저의 실제 가상카메라 WebM 제출/교사 재생을 확인했다. 단위 검사 27개·브라우저 17종(기존 회귀 13, 신규 S3 4)이 통과했다. 근거는 [S3 검증](stage-S3-validation.md), 보관/삭제/서버 실행은 [S3 사용·운영 계약](S3-data-and-sync.md)을 따른다.

S3 전체 운영은 부분 완료다. 허브는 loopback/RAM 평문 개발 도구로 실제 기기·LAN/HTTPS·영속 암호화 서버 배포 대기가 남는다. PIN 초기화는 원격 제출을 삭제하지 않는다. S1/S2 실제 기기 대기를 유지한다. 이 S3 기록 당시 S4는 미착수였으며 최신 상태는 아래 기록을 따른다.

순수 상태 모듈과 PoseUI 연결, 화면 비율을 반영한 2D 팔꿈치 각도와 몸통 길이로 정규화한 손목 위치, 좌우·민감도 교사 설정을 구현했다. 각 상태의 연속 프레임/시간 조건·히스테리시스·팔 내림 후 재준비로 중복 감지를 막는다. 전신 확인 실패·오래된 결과·추적 기하 변화·설정/수업 맥락·카메라/화면 중단 시 새 준비부터 시작한다. 설정은 허용된 세 필드만 저장하고 지연 설정·PIN 이전/초기화 동작을 보존한다. 셸은 v11이다.

단위 49개와 기존 관련 브라우저 11종 및 신규 동작 UI 1종이 통과해 S4.3 개발 구현·검증을 완료했다. 당시 재실행한 브라우저는 총 12종이다. [사용 안내](S4-shot-guide.md)와 [검증 기록](stage-S4-shot-validation.md)에 근거와 제한을 기록한다. 실제 농구·학생·촬영 방향별 정확도, Android·학교 환경·40분·전체 메모리·발열은 미확인이다. 상태와 각도는 메모리와 화면에만 두며 새 시도/좌표 이력을 저장하거나 원본을 전송하지 않는다. 골 성공·슛의 정확성·성적을 판정하지 않는다. 이 묶음 당시 미착수였던 S4.4의 후속 실행은 아래 기록을 따른다.

## S4.4 — 시각·효과음 피드백과 순간 이미지 (2026-11-06)

기본 꺼짐인 세션 한정 시각 강조·효과음·순간 이미지 옵션, 추론 입력 bitmap/시각에 맞춘 프레임 보존, 이벤트 당시 팔·각도 캡션, 최신 1장 제한과 URL/오디오 정리를 구현했다. 설정·맥락·촬영 세대 변화와 늦은 비동기 완료를 검사하고, 선택 기능의 실패를 기본 카메라와 분리한다. PIN 초기화 성공과 페이지 이탈에서는 세 옵션도 꺼진 기본값으로 돌아간다. 셸은 v12다.

단위 49개와 기존 관련 브라우저 10종·신규 3종, 총 13개 실행 파일이 통과했다. 입력 프레임 lifecycle과 실제 worker/오프라인 연결도 독립 재실행해 S4.4 개발 검증을 완료했다. [피드백 사용 안내](S4-feedback-guide.md)와 [검증 기록](stage-S4-feedback-validation.md)에 정확한 검사 파일과 증거 범위를 기록한다. S4.5 영속 시도/관절 로그와 자동 제출은 추가하지 않았다. 실제 Android·학교 환경·장시간·전체 메모리·발열·스포츠 정확도는 미확인이다.

## S4.5 — 학생·수업별 최소 동작 이력 (2026-11-06)

교사가 켠 때에만 실제 동작 이벤트의 최소 근거 요약을 S3 PIN 암호화 학급 저장소에 기록한다. 현재 바인딩의 학급·학생·수업·기기 ID, 입력 시각, 선택 팔·민감도·2D 팔꿈치 각도·손목/몸통 비율, 신뢰도 요약·감지 기준·모델 버전을 저장한다. 이름·PIN·이미지·전체 관절 좌표와 네트워크 전송은 포함하지 않는다. 기록은 최대 7일이며 부모 자료 만료·삭제와 연결 클립 만료에 맞춰 삭제한다. 교사 PIN 이력 조회·개별 삭제와 명시적 같은 범위 클립 연결을 제공한다.

`node --test tests/*.test.cjs`의 59개 단위 검사와 브라우저 17종이 통과했다. `node tests/browser-shot-history.cjs`에서 기본 꺼짐·PIN 암호화 저장·조회·삭제·같은 범위 클립 직접 연결·빈 outbox를 확인했고, 기록 동작은 합성 시퀀스로 공급했다. `node tests/browser-shot-history-failures.cjs`에서 실제 IndexedDB의 put 전 취소, 주입한 quota 오류 뒤 fake camera 프레임 지속, 암호화 대기 중 중단을 확인했다. 실 저장소 용량 초과, 실제 농구 슛 정확도와 Android·학교 환경·40분·발열은 미확인이다. 근거는 [S4.5 사용 안내](S4-history-guide.md)와 [검증 기록](stage-S4-history-validation.md)를 따른다. 다음은 S4.6 정확도·자원 사용 검증이다.


## S4.6 — 정확도 평가·자원 계측의 로컬 준비 (2026-11-06)

합성/정의 fixture 7개를 순수 규칙에 넣는 standalone harness, 일대일 사건 매칭·TP/FP/FN·precision/recall·방향/조건별 micro 집계, Node CPU·RSS/heap 측정을 추가했다. 합성 결과 TP 3·FP 1·FN 2 (0.75/0.6)는 현장 정확도가 아니다. 단위 전체 64개와 Luna의 매칭 6,400 조합 검사가 통과했다. production 앱·셸 변경이 없어 기존 브라우저 전체는 이번에 재실행하지 않았다.

상태는 **로컬 준비 완료, 실제 검증 대기**다. 기존 real-model JSON을 보존하며 Android·발열·40분·동의된 실제 자료·교사 검토는 미실행으로 유지한다. 세부 명령·수치·sandbox 제약은 [검증 기록](stage-S4-evaluation-validation.md), 실제 자료/기기 검증 방법은 [평가 절차](S4-evaluation-protocol.md)를 따른다. 게시·배포·commit·push하지 않았다.


## S4.6 후속 — 배구 연습 cue·모델 프로필 (2026-11-06)

실험용 로컬 개발 기능 구현: 배구 머리 위 팔 동작의 독립 type/ruleVersion, 세션 한정 종목·팔·사용 선택, 종목 변경 시 준비/추가 피드백/이력 중단, 농구 이력 분리. 모델 프로필 로더는 기존 공식 Lite의 동일 출처·SHA pins만 허용한다. 대체 licensed weights가 없어 대체 모델 통합은 미실행이고 확장 인터페이스만 제공한다. 기존 S4.6 농구 합성 평가를 배구 정확도로 인용하지 않는다.

단위 71개 통과. 구체 브라우저 결과와 남은 범위는 [종목 확장 검증](stage-S4-sport-extension-validation.md)에 기록한다. 실제 스포츠 정확도·교사 검토는 미확인이고 Android·학교 환경·발열·40분 연속 사용은 사용자 지시로 이번 범위에서 제외·대기다. 기존 dirty 변경·농구 저장 설정을 보존하고 게시하지 않았다.


## S5.1 — PAPS 수기 기록·수정 이력 (2026-11-06~07)

`measurements`에 학년도·S3 학생 ID·측정일·종목·원값/단위·입력/수정 시각·기준 버전을 별도로 저장한다. 교사 PIN 암호화 로컬 저장만 사용하고 기존 7일 클립 정리와 분리했다. 5개 기초 수기 항목, 단위·기술 범위·소수 자릿수 검사, 6개 결측 사유, 동명이인 ID 구분, 연속 학생 입력, 변경 이력, 기록별/학급별 삭제를 제공한다. 수정은 이전 값·새 값·시각·교사 역할을 이력에 남기며 학생 ID와 학년도는 고정한다. 학년도 만료와 측정값 삭제 때 이력도 함께 정리한다. 기록은 학년도 기준 최대 세 학년도 보관하며 학생·학급 식별 정보도 연결 기록과 같은 시한 동안 암호화 유지한다. PIN 초기화 취소·실패는 클립·측정값·수정 이력을 보존하고 성공은 새 PIN과 함께 모두 삭제하는 것을 확인했다. 기준 버전은 미지정이고 PAPS 점수·등급·백분위·건강 판정은 계산하지 않는다.

단위 모델·보관 검사와 측정 입력, 초기화, 학급 흐름/개인정보, PWA 브라우저 검사를 통과했다. 새 흐름에서 동명이인 연속 입력, 결측, 이전/새 값 이력, 암호문 저장, 개별·학급 삭제, PIN reset rollback/성공 및 이전 탭 키 거부를 확인했다. 전체 회귀는 재실행하지 않았다. S5.1은 개발 구현·검증 완료이며 다음은 공식 기준 출처가 필요한 S5.2다. 명령과 범위는 [S5.1 검증 기록](stage-S5.1-validation.md), 보관 계약과 전체 순서는 [S5 계획](S5-implementation-plan.md)에 정리했다.

## S5.2.1~5.2.2 — 공식 종목 기준·등급 조회 및 교사 화면 연결 (2026-11-06)

교육부령 제354호 별표 4에서 앱 입력 다섯 종목의 2026학년도 남녀·초3~고3 기준 100개를 정적 데이터로 등록했다. 별표 3 기록법에 따라 제자리멀리뛰기 입력 정밀도는 0.1cm다. 교사 화면에서 학년과 평가표 구분을 직접 선택하면 별표 4 개별 종목 등급을 미리 본다. 이름·학급명으로 선택값을 추정하지 않으며 다음 학생으로 넘어갈 때 초기화한다. 저장된 기록에는 적용 학년·평가표 구분·기준 버전을 원자료와 함께 PIN 암호화 저장하고, 수정 시 이전·새 범위도 이력에 남긴다.

점수·백분위·BMI·건강 진단·종합등급은 구현하지 않았다. 별표 5의 전체 점수 요소와 BMI가 현 앱 입력을 넘어가며 법령에서 백분위 산식을 확인하지 못했다. 실제 NEIS 출력과 학교 현장 검증도 미실시다. 출처와 경계 조건은 [S5.2 출처 기록](S5.2-criteria-sources.md), 시험 결과는 [S5.2 검증 기록](stage-S5.2-validation.md)에 정리했다.

`node --test tests/paps-criteria.test.cjs tests/classroom-measurements.test.cjs tests/classroom-model.test.cjs`, `node tests/browser-classroom-measurements.cjs`, `node tests/browser-pwa.cjs`, 구문 검사와 `git diff --check`를 통과했다. 변경 사항을 게시하지 않았다.

## S5.2.3~S5.9 — 보고·수기 평가·로컬 확장 (2026-11-06)

S5.2.3 PAPS 학생 추이/학급 등급 분포와 선택형 안전 CSV를 구현했다. 보고 범위는 저장된 학년·평가표·기준 버전과 일치해야 한다. S5.3에는 여섯 개의 자체 텍스트 활동과 교사 안전/학급 적합성 체크를 요구하는 3+6+6분 루틴을 연결했다. S5.4·S5.5는 교사 자체 루브릭 버전·근거 연결·수정 이력·승인, 승인 평가만을 선택하는 수기 문안 및 로컬 임시 CSV를 제공한다. 평가 근거가 수정되면 연결된 문안 승인을 해제한다. AI 문안/NEIS 출력은 제공하지 않는다.

S5.7은 미션 제목·순서 활동·선택 퀴즈를 만들고 미션 UUID만 담은 QR을 생성한다. 학생 응답은 익명 UUID로 PIN 암호화 로컬 저장하며 pause/resume/restart, 순서 확인, 같은 응답 ID 재시도를 처리한다. camera `BarcodeDetector`가 없거나 사용 불가하면 ID 직접 입력이 대체 경로다. S5.8은 SVG 익명 전술판·좌표 입력·이동/패스/공수 표식·전후 스냅샷·회고·복제·초기화를 제공한다. 두 기능 모두 위치·외부 서버·AI를 사용하지 않는다.

`node --test tests/*.test.cjs` 125개가 통과했다. `node tests/browser-wearable-bridge.cjs`와 `node tests/browser-classroom-tools.cjs`도 통과했다. 앞서 PAPS 보고/측정 및 PWA 브라우저 통합에서 QR 미션/익명 응답 단위 삭제, 전술판 복제·선택, 학급 삭제 정리도 확인했다. 지원 범위와 현장 미검증 항목은 [S5.3~S5.9 검증 기록](stage-S5.3-S5.9-validation.md)과 [지원 환경표](S5-support-matrix.md)에 있다. 웨어러블 모델별 구현, 공식 교육과정 템플릿, 공식 NEIS 샘플은 별도 근거/운영 조건을 기다린다. Android·학교 현장·발열·실제 40분 연속 검증은 이전 사용자 지시에 따라 이번 작업에서 제외했다. 게시하지 않았다.

## S5.6 웨어러블 PWA·Android 태블릿 호스트 소스 — 부분 구현 (2026-11-06~07)

2026-11-07 현재 4년 이내 출시인 2022-11-07 이후 Apple Watch/Galaxy Watch 대상의 PWA WebView 브리지 v2와 심박 전용 수업 세션 화면을 구현했다. 학생·보호자 동의가 없으면 초대 QR을 만들지 않으며, 익명 토큰 외 학생 식별자를 네이티브 브리지에 보내지 않는다. OS 권한은 학생 휴대폰 companion이 담당하는 구조로 옮겼다. 초대 QR 생성, 워치 준비 이벤트, 심박 표본, 휴대폰 권한 불가 이벤트의 가짜 호스트 연결을 구현했다. 심박 데이터는 화면 메모리만 사용하고 세션 종료·동의 철회·잠금/이탈 때 제거한다. 5초 이상 새 값이 없거나 연결이 끊기면 값을 숨긴다.

`node tests/wearable-bridge.test.cjs` 15개 단위 사례와 `node tests/browser-wearable-bridge.cjs` 가상 브리지 흐름이 통과했다. 사설 LAN·TLS 지문 형식·2분 만료 QR, 동의 게이트, 익명 토큰, 권한 불가·초대 만료 후 빈 기록, 워치 연결 공백/수동 재연결, Wi-Fi 복구 이벤트 뒤 새 표본만 재개, PIN 잠금 종료, 저장소 비기록을 확인했다.
