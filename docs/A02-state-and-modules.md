# A02 — 상태와 모듈 설계

상태: 설계 문서 완료. 전체 모듈 분리 구현은 후속 작업이다. 사용자 화면 계약은 [A01](A01-screen-flows.md)을 따른다.

## 독립적으로 관리할 상태

카메라·선택 창·교사 접근·키 상태를 단일 문자열에 모두 넣지 않는다. 예를 들어 카메라가 중단돼도 이미 선택한 클립은 저장할 수 있고, 목록을 닫아도 학생의 저장에 필요한 키는 유지될 수 있다.

| 상태 축 | 값 | 소유자 |
| --- | --- | --- |
| 카메라 | idle / starting / warming / live / interrupted | CameraController, ReplayController |
| 클립 작업 | closed / selecting / encoding / encrypting / committing / failed | ClipWorkflow |
| 교사 화면 | closed / pinSetup / pinCheck / settings / library / deleteConfirm | TeacherUI |
| 수업 키 | absent / available | SecureSession |
| 앱 표시 | visible / hidden / leaving | AppCoordinator |

현재 `studioState`는 UI 표시용 요약으로 유지할 수 있다. 보안 판단과 비동기 취소 조건을 이 값 하나에 의존하지 않는다. 실제 상태는 위 축의 소유자가 관리하고 요약 상태는 그 값에서 파생한다.

## 요약 상태별 허용 동작

| 요약 상태 | 허용 | 차단·제약 | 전이 조건 |
| --- | --- | --- | --- |
| 준비 | 교사 PIN 진입, 키가 있으면 카메라 시작 | 스트림 없이 새 구간 선택 불가 | 카메라 요청 → 시작 중 |
| 시작 중 | 권한 허용, 화면 이탈 시 요청 무효화 | 중복 카메라 요청·새 선택 차단 | 스트림 확보 → 지연 대기, 오류 → 준비/중단 |
| 지연 대기 | 교사 지연 변경, 촬영 종료 | 아직 없는 과거 영상 재생 금지 | 설정 시간 충족 → 촬영, 중단 → 중단 상태 |
| 촬영 | 지연 재생, 새 구간 선택, 촬영 종료, 교사 PIN 진입 | PIN 없이 교사 데이터 표시 금지 | 선택 → 구간 선택, 종료 → 준비, 오류 → 중단 |
| 구간 선택 | 끝 시점·길이·학생 입력, 미리보기, 닫기, 검증 후 저장 | 이름·번호 또는 유효 구간 없으면 저장 불가 | 저장 → 저장 중, 닫기 → 촬영/중단 |
| 저장 중 | 진행 표시, 중단 감지 | 수정·중복 저장·앱 내 닫기 금지 | 커밋 성공 → 선택 닫기, 오류 → 편집 가능한 실패 상태 |
| 잠금 | PIN 입력, 기존 키가 있는 수업의 촬영·학생 저장 | 목록·설정 접근 차단 | PIN 성공 → 교사 화면, 오입력 → 잠금 유지 |
| 중단 | 사유 표시, 명시 재시작, 유효한 기존 선택 저장 | 자동 재시작·중단 전후 영상 연결 금지 | 재시작 → 지연 대기, 수업 종료 → 준비 |

## 이벤트와 데이터 수명

| 이벤트 | 상태 변화·처리 | 남는 데이터 | 폐기되는 데이터 |
| --- | --- | --- | --- |
| PIN 검증 성공 | 후보 키를 검증 후 수업 키로 채택, 교사 UI 접근 허용 | 완료된 클립·설정 | PIN 입력 문자열은 필요 종료 후 비움 |
| PIN 검증 실패 | 후보 키 폐기, 기존 수업 키는 보존 | 기존 클립·설정·정상 수업 키 | 실패한 후보 키 |
| 교사 창 닫기 | 교사 UI 잠금, 촬영과 학생 저장 계속 | 수업 키·클립·실시간 버퍼 | 복호화 목록·URL·학생 정보 DOM |
| 명시적 잠그기 | 교사 UI와 수업 키 잠금 | 암호화된 클립·설정 | 수업 키·복호화 미리보기 |
| 새 카메라 요청 | 요청 세대 증가, 이전 응답 무효화 | 클립·설정·수업 키 | 이전 요청이 늦게 반환한 스트림 |
| 촬영 종료 | 스트림 종료, 수업 종료 | 암호화된 클립·설정 | 실시간 버퍼·선택·수업 키·화면 꺼짐 방지 락 |
| 촬영 중단·화면 이탈 | 요청 무효화, 실시간 버퍼 초기화, 저장 작업 중단 표시 | 암호화된 클립·설정·수업 키·이미 고른 선택 | 실시간 버퍼·활성 스트림·불완전 인코딩 결과 |
| 선택 닫기 | 학생 입력 초기화 | 실시간 촬영·완료된 클립 | 선택 스냅샷·미리보기 타이머 |
| 저장 커밋 성공 | 성공 표시 후 선택 닫기 | 암호화 영상·암호화 학생 정보·만료 정보 | 임시 클립·선택 스냅샷 |
| 저장 실패 | 오류 표시, 편집·재시도 가능 | 원래 클립·유효 선택 | 실패한 임시 영상·추가 스트림 |
| 앱 종료 | 실행 중 자원 해제 | 완료된 DB 기록·설정 | 메모리 키·버퍼·선택·복호화 URL |

키를 PIN으로부터 다시 파생할 수 있어도 PIN 평문이나 파생 키를 localStorage에 저장하지 않는다. 삭제 확인 취소는 저장소에 쓰지 않는다. 클립 생성·암호화가 끝나기 전에는 DB에 부분 기록을 만들지 않는다.

## 모듈별 책임과 인터페이스

| 모듈 | 책임·제안 인터페이스 | 금지할 의존 | 현재 위치·분리 순서 |
| --- | --- | --- | --- |
| AppCoordinator | 사용자 이벤트 연결, 표시 상태 파생, 화면 이탈 처리 | 영상 바이트 처리·PIN 암호화 직접 수행 | 현재 `app.js`. 다른 모듈을 추출하며 조정자 역할로 축소 |
| CameraController | start / stop / interrupt, 스트림·권한 오류·요청 세대·화면 락 관리 | DB·학생 정보·교사 목록 접근 | 현재 `app.js`. B01·B04 검증을 유지하며 첫 추출 후보 |
| FrameBuffer | add / clear / snapshot / duration, 시각·바이트·프레임 상한 | DOM·PIN·네트워크 | `frame-buffer.js`로 분리됨 |
| ReplayController | 설정 지연, 초기 대기, 표시 프레임 선택, 디코딩 세대 확인 | 기록 파일 생성·저장 | 현재 `app.js`, B02에서 시간 계산을 별도 검증 |
| Timeline | 주어진 시각의 프레임 검색 | DOM·장치·키 | `timeline.js`로 분리됨 |
| ClipSelection | 고정된 참조 시각·스냅샷·선택 구간, 유효성 판단 | 실시간 버퍼를 직접 변경 | 현재 `app.js`, C01에서 추출 |
| ClipExporter | export(frames, start, duration, signal), 전용 캔버스·WebCodecs·진행 이벤트·자원 해제 | 학생 이름·PIN·DB | `clip-exporter.js`로 분리. WebM 작성기는 `webm-muxer.js` |
| ClipWorkflow | 입력 검증 → 인코딩 → 암호화 → 커밋, 중복 저장 방지 | 키를 영구 저장 | 현재 `saveSelectedClip`, C04·D01에서 분리 |
| SecureSession | setup / verify / getSessionKey / lock, 후보 키 검증, 암호화·복호화 | 카메라 스트림 직접 종료·목록 DOM 수정 | `local-vault.js`로 암호화 분리, 세션·접근 수명은 `app.js`에서 관리 |
| ClipRepository | put / list / delete / expire, IndexedDB 트랜잭션·만료 처리 | PIN 입력·DOM·영상 디코딩 | `clip-repository.js`로 분리 |
| TeacherLibrary | 접근 확인 후 목록 표시, 한 항목씩 복호화·재생, 닫기 취소 토큰 | PIN 없이 전체 데이터 표시 | `loadLibrary`에서 목록·미디어 세대와 단일 영상 복호화 구현 |
| OfflineManager | 앱 셸 캐시·버전 활성화·업데이트 유예 | 영상·학생 데이터 캐시 | `sw.js`에 구현·E03~E04 개발 검증 완료, A9+ 적용 대기 |

모듈은 기능 검증을 유지하며 한 번에 하나씩 추출한다. A02 완료는 위 책임·경계·상태 계약의 확정이며 파일 분리 작업 전체의 완료가 아니다.

## 비동기 작업의 취소 규칙

1. 카메라: 요청·촬영 세대가 다르면 스트림을 즉시 종료하고 프레임을 추가하지 않는다.
2. 지연 화면: 디코딩 시작과 종료 사이 카메라 세대가 바뀌면 그 이미지를 표시하지 않는다.
3. 선택 미리보기: 선택 토큰이 바뀌거나 창이 닫히면 다음 타이머를 중단한다. 디코딩 완료 후에도 토큰을 재확인한다.
4. 인코딩: 전용 캔버스를 사용한다. 화면 이탈·카메라 중단·앱 종료 신호는 미완료 결과를 성공 처리하지 않게 한다.
5. 교사 목록: 창·탭·접근 세대가 바뀌면 뒤늦은 복호화 결과의 DOM 추가를 막고 생성 URL을 폐기한다.
6. 저장: 트랜잭션 완료 이후에만 성공을 표시한다. DB 커밋 후에는 단순한 UI 닫기 오류를 ‘저장 실패’로 바꿔 중복 저장을 유도하지 않는다.

1·2·4는 현재 구현이 있고 자동 회귀 검증 범위를 계속 확장한다. 3의 디코딩 후 재확인과 6의 저장·UI 완료 분리는 2단계에서 구현했다. 5의 목록·미디어 취소 세대 제어는 3단계에서 구현했다.

## A02 완료 근거

준비·촬영·선택·저장·잠금·중단의 허용 동작과 전이, 스트림·키·버퍼·선택·DB의 소유자와 수명, 분리할 모듈과 비동기 취소 계약을 정의했다. 아직 구현되지 않은 계약은 단계별 작업에 연결했다.
