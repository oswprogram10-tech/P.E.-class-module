# 교사 첫 사용 설정과 기기·현장 점검

2026-11-12 사용자 요청으로 40분 연속 사용·발열·학교 현장 확인을 개발 환경의 제외 항목에서 **교사가 실제 기기를 처음 사용할 때 진행하는 앱 내 점검**으로 전환했다. 점검 기능 구현과 실제 기기에서 교사가 완료한 결과는 별개다. 기존 기록의 미실행 결과를 완료로 바꾸지 않는다.

## 수업에 맞게 설정하기

첫 화면의 **교사 첫 사용 설정**을 누르고 교사 PIN을 만든다. 첫 PIN을 교사 메뉴에서 만들어도 같은 안내가 열린다. 기존 PIN을 쓰는 교사는 **첫 사용 설정** 탭이나 **수업 설정**의 안내 버튼에서 언제든 다시 열 수 있다. 수업에 사용할 기능만 골라 필요한 값을 기존 설정 화면에서 저장한다.

| 설정 | 교사가 할 수 있는 일 |
| --- | --- |
| 지연 재생 | 수업에 맞는 지연 시간을 선택한다. |
| 학급·수업 | 학급을 만든 다음 수업·명단·모둠을 등록한다. 학급 단위 기능은 먼저 학급을 만들거나 선택한다. |
| PAPS·평가 | 학년도와 학년을 고르고 체력요소별 검사 종목을 설정한다. 교사 루브릭과 성취기준을 연결하고 필요하면 세특 문안을 작성한다. |
| QR·GPS | 테스트 미션으로 QR 카메라와 GPS 권한·도착 확인을 시험하고 실제 이동 경로는 현장에서 확인한다. |
| 교사 기기에 정보 저장 · 학교 서버 운영 | 원본 클립·명단·교사 관찰을 교사 기기에 보관한다. 학교 운영자가 준비한 HTTPS 주소와 연결 정보로 선택 자료 제출과 익명 전술판 기기 간 공유를 시험한다. |

설정 화면을 여는 동작만으로 카메라·위치·공유 서버 연결이나 모델 설치를 시작하지 않는다. 교사가 여는 기능별 화면에서 필요한 권한과 연결을 선택한다. 40분 점검을 미뤄도 수업 기능을 사용할 수 있다.

**첫 출시에서 미구현인 기능**에서 웨어러블 정식 연동, PAPS 공식 BMI·종합점수·백분위 및 나이스 연동, 동작 분석·검토된 운동 콘텐츠, AI 전술 제안의 정식 지원 상태를 확인할 수 있다. 기존 시범 화면은 이 메뉴에서 열 수 있다. [학교 1차 출시 안내](release-runbook.md)

## 기기·현장 점검 진행 방법

1. 실제 수업 장소에서 **교사 첫 사용 설정** 아래의 **처음 사용하는 기기·학교 환경 점검**으로 이동한다.
2. 기기 모델명을 입력하고 학생 대신 교사 시연·테스트 자료를 쓸 것을 확인한다. 시작 전 발열을 관찰한 뒤 **40분 점검 시작**을 누른다. 앱이 교사 창을 닫고 첫 카메라 프레임이 들어온 뒤부터 시간을 잰다. 정상 수업 기능은 점검 완료 전에도 사용할 수 있다.
3. 앱을 전면에 유지하며 연속 촬영한다. 약 10분마다 교사 메뉴에서 **현재 발열 상태 기록**을 누른다. 클립 저장·목록 재생은 앱 안에서 시험할 수 있다. 너무 뜨겁거나 온도 경고·성능 저하가 있으면 발열 문제를 기록하고 중단한다.
4. 카메라 중단, 앱 전환·화면 잠금, 새로고침·앱 종료, 오래된 프레임 또는 긴 앱 응답 중단은 연속 시험 중단으로 남는다. 여러 번의 짧은 촬영을 합쳐 40분 완료로 처리하지 않는다. 새 시험은 0분부터 시작하고 학교 환경 항목도 새로 확인한다.
5. **40분 촬영 완료 · 교사 확인 필요**가 되면 종료 후 발열을 한 번 더 기록한다. 학교의 거치·동선, 조명·거리, 회전·키보드·터치, 테스트 클립 저장·PIN 재생, 사용 장소 접속·오프라인 재실행을 직접 확인한다. 앱 재실행·오프라인 시험은 연속 촬영 전후에 별도로 진행한다. 완료한 40분 결과는 재실행해도 남는다.
6. **교사 확인 결과 저장**을 누른다. 연속 촬영 완료 + 시작/종료 발열 관찰 + 모든 학교 환경 항목 확인이 있어야 완료다. 문제 있음은 재점검 필요, 나머지는 미확인으로 남긴다. **나중에 점검**을 고르면 이후 실행에도 안내가 남는다.

QR·GPS 미션 또는 전술판 공유를 수업에 사용한다면 [확장 기능 기기 점검표](S5-support-matrix.md#s59-학교-기기-확인)도 진행한다.

## 기록과 한계

- 기록은 이 기기·브라우저의 `pe-loop-device-check-v1` localStorage에만 저장한다. 기기 모델, 브라우저 식별 문자열, 시각·연속 촬영 시간, 발열 관찰, 체크리스트, 최대 버퍼 프레임 수·바이트·시각 범위만 보관한다. 학생·학교 이름, 영상·관절 좌표는 포함하지 않는다. 교사 PIN을 초기화해도 기기 자체 점검 기록은 유지한다.
- 발열은 교사 관찰이다. 브라우저에서 실제 기기 온도를 읽거나 수치 온도를 추정하지 않는다. 버퍼 사용량은 전체 프로세스·GPU·인코더 메모리가 아니다. 전문 장비 계측과 모델별 제품 지원 인증을 대체하지 않는다. 필요하면 [B03·B04 상세 절차](B03-B04-device-check.md)를 함께 사용한다.
- 실행 중 10초 간격과 상태 전환 때 진행을 저장한다. 종료된 촬영 시간을 새 실행에 이어 붙이지 않는다. 마지막 점검 한 건만 유지하며 새 점검 시작 시 이전 결과를 교체한다. 기기·브라우저·장소가 바뀌면 교사가 재점검한다.
- 결과 저장 실패는 화면에 표시한다. 사이트 데이터 삭제·브라우저 변경·기기 교체 시 결과도 사라진다. 여러 창의 점검 기록 변경을 감지하면 이 창의 연속 시험을 이어가지 않는다. 점검은 창 하나에서 진행한다.

## 개발 검증

- `node --test tests/*.test.cjs`: 기존 회귀와 연속 시간·중단·발열·수동 확인 완료 조건·복원 검사.
- `node tests/browser-device-check.cjs`: 첫 PIN에서 설정 열기, 학급 생성 전후 실제 설정으로 이동, 나중에 점검, 카메라 중단/재실행, 결과 저장·복원·저장 오류.
- 40분 경계의 자동 검사는 합성 단조 시각을 사용한다. 실제 40분 연속 사용·기기 온도·학교 현장 통과 결과가 아니다.

2026-11-12 실행 결과: 전체 단위 150/150 통과. Chromium의 `browser-device-check`, `browser-pwa`, `browser-layout`, `browser-camera`, `browser-reset` 5종 통과. 첫 PIN 생성 경로, 360px 화면 조작, 교사 발열 문제 기록 시 촬영 종료, 저장 공간 오류를 확인했다. HTML ID 중복·로컬 자산·Android 패키징 목록·PWA 신규 캐시 자산과 `git diff --check`도 통과했다. Android APK는 이번에 재빌드하지 않았다.
