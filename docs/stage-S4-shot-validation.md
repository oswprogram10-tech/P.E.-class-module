# S4.3 농구 동작 감지 검증 기록

기록일: 2026-11-06. S4.3만 현재 요청에 따라 구현·검증했다. S4.1~S4.2의 기초 모델 검증은 별도 [역사적 기록](stage-S4-foundation-validation.md)에 보존했다. 이 문서는 개발 환경의 회귀·브라우저 증거를 기록하며, S4 전체 완료나 실제 스포츠 정확도를 뜻하지 않는다.

## 검증 범위와 결과

- `node --test tests/*.test.cjs`: 49 통과, 실패 0, 건너뜀 0. 기존 39개와 신규 농구 상태 모듈 10개다. 설정 저장·초기화는 아래 브라우저 통합 검사에서 확인했다.
- 이번에 재실행한 기존 관련 브라우저 11종 모두 통과: migration, reset, data, layout, camera, clips, smoke, pwa, pose-ui, pose-runtime, pose-real. 이전 브라우저 19종 전체를 이번에 재실행한 것은 아니다.
- `node tests/browser-shot-ui.cjs`: 독립 UI 통합 검증 통과. PIN 접근, 설정 유효성·저장 실패 복구·지연 설정과의 보존·오염 설정의 안전한 기본값·초기화를 확인했다. 서비스 워커 통제 상태에서 오프라인 reload 뒤 실제 worker 추론이 계속 응답하는 것도 확인했다.
- 새 UI 검사는 합성 전신 관절 시퀀스로 READY→SHOOT, 한 번의 유지 중 중복 방지, 팔 내림 재준비, 낮은 신뢰도·추적 손실·1초 초과 공백·수업 맥락 변경·클립 선택·설정/팔 변경·문서 숨김 이벤트·카메라 중단/재시작 때 초기화를 검사했다. 화면 숨김은 이벤트를 주입한 검사이며 실제 OS 전환 검증은 아니다. 상태와 각도는 저장되지 않고 클립 수도 늘지 않는 것을 확인했다.
- 별도 real-model fixture 단계에서는 기존 테스트 이미지 한 장을 실제 PoseRuntime worker에 넣어 33개 관절과 원본 폭·높이를 얻었다. 이 결과를 순수 농구 detector에 전달해 전신 gate 통과와 유한한 팔꿈치 각도를 확인했으며, 정지 프레임 하나에서 shot event가 나오지 않았다. 이미지는 저장소 루트 Apache-2.0 표시 아래 있는 fixture지만 개별 이미지 고지는 확인하지 못했으며 개발 검사에만 사용했다.

실제 모델 fixture 검사와 합성 동작 시퀀스는 서로 다른 증거다. 첫 검사는 모델 결과가 각도 계산기까지 이어지는지만 보며 실제 사람 동작의 READY/SHOOT 전이를 검증하지 않는다. 두 번째 검사는 제어된 합성 관절로 상태 기계·UI 연결을 검사하며 실제 카메라 영상이나 실제 슛 정확도를 검증하지 않는다. fake-camera worker 결과도 사람 검출 성공의 증거로 세지 않는다.

## 구현 기준

선택한 팔의 화면 비율 보정 2D 팔꿈치 내각과 손목 높이를 몸통 길이로 정규화해 준비/펴기 상태를 추정한다. `BasketballShot.LEVELS` 개발 기준은 민감도 low/normal/high에 대해 READY 각도 130°/140°/150°, SHOOT 각도 165°/160°/155°이며, 손목 높이 비율 조건도 민감도별로 조정된다. 단계 전환은 최소 2 프레임과 250ms 유지가 필요하다. 샘플링 간격 기본값은 약 333ms다. READY 이후 SHOOT는 팔을 내리는 재준비 전까지 중복 이벤트를 만들지 않는다. 프레임 간격 1,000ms 초과, 가림·저신뢰, 잘못된 시각/치수, 몸통 기하 또는 맥락 변화는 상태를 초기화한다.

설정은 교사 PIN 내부에서 켜며 기본값은 비활성·오른팔·기본 민감도다. 저장 실패나 유효하지 않은 입력에서 직전 설정을 보존하고, 지연 값 변경도 농구 설정을 보존한다. PIN 초기화는 기본 비활성 설정을 복원한다. 설정은 `{enabled, side, sensitivity}`만 기존 `pe-loop-settings-v1`에 둔다. 새 angle/event/landmark/시도 이력 저장은 없다. 클래스·학생·수업·기기 바인딩은 메모리상의 맥락 변경 감지용이며 생체 식별이나 동일인 판정이 아니다.

## 해석 한계와 미확인 사항

임계값과 유지 시간은 첫 개발 기준으로 조정한 휴리스틱이다. 브라우저의 합성 시퀀스 PASS는 학교 연령 학생의 슛 동작 인식, 골 여부, 기술의 정확성, 교육 효과 또는 성적 산출을 증명하지 않는다. 한 장의 fixture는 동작 데이터를 포함하지 않는다. 실제 Android 기기·학교 카메라와 조명·거리·가림 조건, 40분 연속 사용, 전체 메모리·발열은 측정하지 않았다. 이 범위는 S4.3 개발 검증으로 한정하며 S4.4 자동 효과/캡처나 S4.5 영속 로그/학급 연결을 포함하지 않는다.
