# A01 — 화면과 사용자 흐름

상태: 설계 문서 완료. 각 기능의 구현·검증 완료를 의미하지 않는다.

## 범위와 공통 규칙

Android Chrome PWA, 거치형 태블릿, 무음 카메라, 교사 조절 지연 1~60초, 최근 5분 탐색, 최대 30초 선택, 로컬 클립 목록, 이름·번호 수동 입력, PIN, 7일 만료가 범위다. 기준 기기는 갤럭시 탭 A9+다.

기본 지연 20초·클립 길이 15초·선택 간격 5초·PIN 6자리는 현재 구현 기본값이다. PIN 분실 시 기존 클립 복구를 제공하지 않는다. 사용자가 확인한 정책에 따라 삭제 경고·확인 문구·새 PIN 입력 후 모든 기존 클립을 삭제하는 초기화를 제공한다. 기존 파일을 유지하는 PIN 변경은 별도 정책·기능이다.

- 저장 성공은 IndexedDB 쓰기 트랜잭션 완료 이후에만 표시한다.
- 학생 이름·번호·원본 영상·클립을 외부 서버로 전송하지 않는다.
- 목록을 열 때는 교사 PIN을 요구한다. 목록을 닫고 수업으로 돌아가는 것과 수업용 암호화 키를 해제하는 ‘잠그기’를 구분한다.
- 저장하지 않은 선택 취소는 영구 저장소에 아무것도 추가하지 않는다.
- 앱 내 닫기와 브라우저 뒤로 가기를 구분한다. 브라우저가 앱을 종료하는 것을 완전히 차단한다고 보장하지 않는다.
- 설계와 현재 동작이 다른 항목은 마지막 표의 구현 과제로 추적한다.

## 수업의 정상 흐름

1. 교사가 앱을 열고 PIN을 설정하거나 기존 PIN을 입력한다.
2. 교사가 지연 시간을 설정하고 교사 창을 닫는다.
3. 카메라를 시작한다. 카메라 권한은 영상만 요청한다.
4. 설정 시간만큼 영상이 모이는 동안 남은 대기 시간을 보여준다.
5. 지연 영상을 재생한다. 학생은 동작 수행 후 화면에서 확인한다.
6. 학생이 ‘마음에 드는 장면 저장’을 눌러 탐색 범위를 고정한다.
7. 끝 시점과 길이를 정하고 미리 본 뒤 이름과 번호를 입력한다.
8. 저장을 누르면 편집을 잠그고 진행률을 표시한다.
9. 영상과 학생 정보를 암호화해 저장한다. 성공하면 선택 창을 닫고 촬영 화면으로 돌아간다.
10. 교사는 PIN을 입력해 목록을 확인한다. 수업을 종료하면 카메라와 임시 버퍼, 수업용 키를 해제한다. 저장한 클립은 보존한다.

## 화면별 정상·취소·실패·재시도

| ID / 화면 | 진입·정상 동작 | 닫기·취소·뒤로 가기 | 실패·중단 | 재시도·복구 |
| --- | --- | --- | --- | --- |
| S01 준비 화면 | 앱 실행. 카메라는 사용자 조작 전에는 켜지지 않음 | 앱 종료 시 저장한 클립 유지, 임시 버퍼는 폐기 | 저장소 사용 불가·비보안 주소는 해당 기능 불가 안내 | Chrome 설정·HTTPS 주소를 확인해 다시 실행 |
| S02 최초 PIN | PIN 없는 기기에서 교사 진입. 두 번 입력한 PIN이 일치하면 초기화 | 닫으면 PIN 없이 준비 화면. 카메라·저장 기능을 임의로 활성화하지 않음 | 자릿수·숫자 형식·확인 불일치·키 생성·설정 저장 오류 | 입력을 수정해 재시도. 설정 저장 실패를 성공으로 표시하지 않음 |
| S03 PIN 확인 | 기존 PIN 검증 성공 후 교사 화면 진입 | 닫으면 교사 화면 접근 취소. 기존 학생 클립은 유지 | 오입력은 안내만 표시. 기존 정상 수업용 키와 저장 클립을 파괴하지 않음 | 다시 입력. 분실 시 복구 불가 안내를 제공하고 데이터 초기화를 자동 실행하지 않음 |
| S04 수업 설정 | PIN 확인 후 지연을 1~60초로 조절. 설정값 보존 | 닫으면 학생 화면. 목록 권한은 다시 잠그되 진행 중 수업의 저장 기능은 유지 | 설정 저장 실패는 안내. 화면 표시와 실제 적용값이 달라지지 않게 처리 | 다시 설정하거나 기존값 유지. 잠그기는 명시적으로 수업용 키 해제 |
| S05 카메라 시작 | 시작 버튼 → 권한 요청 → 영상 준비 → 지연 대기 | 시작 중 중복 요청 차단. 화면 이탈 시 시작 요청 무효화 | 거부·카메라 없음·다른 앱 사용·보안 컨텍스트 오류 구분 | 사유별 안내 후 다시 시작. 뒤늦게 도착한 이전 스트림은 종료 |
| S06 지연 미러 | 설정 시간 충족 후 지연 재생. 버퍼는 최근 범위로 순환 | 촬영 종료 시 스트림·임시 버퍼·수업용 키 해제. 저장 목록은 유지 | 영상 정지·연결 종료·화면 이탈 시 중단 화면 | 명시적으로 다시 시작. 이전 촬영과 새 촬영 사이를 이어 붙이지 않음 |
| S07 구간 선택 | 창을 연 시점의 버퍼 고정. 끝 시점·길이 선택과 이름·번호 입력 | 저장 전 닫기는 전체 선택과 입력 폐기. 다음 진입 시 다시 입력 | 충분한 영상 없음·장면 디코딩 불가·잘못된 입력은 저장하지 않음 | 길이·구간·입력을 수정. 카메라가 중단돼도 유효한 선택 스냅샷은 재시도 가능 |
| S08 저장 중 | 원본 시각에 맞춰 클립 생성 → 암호화 → 영구 저장 → 성공 | 앱 내 닫기·수정·중복 저장 차단. 브라우저 이탈은 지원될 때 경고. 강제 종료를 완전히 막을 수 없음 | 카메라·화면 중단, 인코더·암호화·저장 공간·DB 오류 시 성공 표시 금지 | 오류를 표시하고 편집 잠금 해제. 선택이 남아 있으면 같은 장면 재시도. 불완전 DB 기록은 만들지 않음 |
| S09 교사 목록 | 매번 PIN 검증 후 진입. 만료 삭제 후 최신순 표시. 영상은 기기에서 복호화 | 창 닫기 시 재생 중지·복호화 URL·화면의 학생 정보 제거. 다시 열 때 PIN 요구 | 목록 전체 읽기 실패와 개별 파일 손상을 구분. 한 손상 파일이 정상 파일 표시를 막지 않음 | 전체 읽기 재시도 또는 손상 항목만 삭제. 키와 만료 정책을 우회하지 않음 |
| S10 삭제 확인 | 교사가 목록에서 삭제 선택 → 확인 후 DB 삭제 → 목록 갱신 | 취소·닫기는 원래 목록으로. 원본 파일 유지 | 삭제 트랜잭션 실패 시 삭제됐다고 표시하지 않음 | 다시 삭제. 성공한 파일은 앱에서 복구 제공하지 않음 |
| S11 촬영 중단 | 중단 사유와 재시작 필요를 지속 표시. 실시간 버퍼 폐기 | 저장 전 선택 창은 닫거나 유지 가능. 저장 도중이었다면 중단 후 결과 안내 | 자동으로 정상 촬영처럼 보이게 복귀하지 않음 | 사용자 재시작 후 새 지연 대기. 보존된 선택의 저장은 카메라 재시작과 독립적으로 가능 |

## 경계를 넘는 예외 흐름

| 상황 | 처리 계약 |
| --- | --- |
| 지연을 짧게 변경 | 충분한 과거 프레임이 있으면 새 시점으로 전환 |
| 지연을 길게 변경 | 부족하면 대기 화면으로 돌아가 남은 시간 표시 |
| 학생이 이름 입력 중 버퍼 순환 | 선택 스냅샷은 고정. 새 실시간 프레임이 저장 대상을 밀어내지 않음 |
| 화면 이탈 중 저장 | 부분 결과를 목록에 추가하지 않음. 복귀 후 실패 이유와 재시도 제공 |
| 앱 강제 종료 | 메모리 버퍼·선택·키 소멸. 완료된 IndexedDB 기록만 다음 실행에서 사용 |
| 앱이 닫힌 채 7일 경과 | 다음 실행·목록 접근에서 만료 정리 후 재생. 정시 백그라운드 삭제를 보장하지 않음 |
| 브라우저 데이터 정리 | 로컬 영상과 PIN 설정을 잃을 수 있음. 서버 복구·백업은 현재 범위에 없음 |
| 저장 중 새 앱 버전 도착 | 작업 중 강제 재시작 금지. 4단계에서 대기 worker로 구현했고, 앱을 완전히 닫았다 다시 열 때 적용 |

## 구현과의 차이 및 후속 추적

정의는 여기서 완료하되, 아래 기능이 구현 완료됐다고 표시하지 않는다.

| 설계 계약 | 현재 남은 구현·검증 | 추적 작업 |
| --- | --- | --- |
| PIN 오입력이 기존 수업용 키에 영향 없음 | 3단계에서 후보 키와 수업 키 분리, 닫기·오입력 회귀 통과 | D01 개발 검증 완료 |
| 설정·최초 PIN 저장 오류의 일관성 | 3단계에서 저장 완료 후 키 채택 및 실패 시 UI·값 유지 검증 | D01·D04 개발 검증 완료 |
| 개별 손상 클립만 실패 처리 | 3단계에서 손상 학생 정보·영상 항목 격리 검증 | D02 개발 검증 완료 |
| 목록 닫기 후 비동기 결과 폐기 | 3단계에서 늦은 목록·영상 결과 폐기와 URL 정리 검증 | D02 개발 검증 완료 |
| 실제 Android 뒤로 가기·화면 잠금 | 가상 브라우저 이벤트와 별도로 실기기 확인 필요 | B04·E01 |
| 최대 30초 파일 | 2단계에서 명시적 프레임 시각으로 해결. 5·15·30초 파일 검사 통과 | C03 개발 검증 완료 |
| 수업 중 업데이트 유예 | 4단계에서 즉시 활성화·강제 새로고침을 제거하고 대기 worker 안내를 구현·개발 검증 | E04 개발 검증 완료, A9+ 적용 대기 |

## A01 완료 근거

학생·교사 화면, 수업 시작부터 삭제까지의 정상 경로, 닫기·취소·실패·재시도, 데이터의 보존·폐기 경계를 이 문서에 정의했다. 기존 코드와 비교해 차이를 구현 과제로 연결했다. 이는 A01의 설계 산출물 완료이며 위 후속 과제의 동작 보증은 아니다.
