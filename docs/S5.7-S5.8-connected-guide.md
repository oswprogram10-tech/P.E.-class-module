# GPS 미션·암호화 전술판 공유·로컬 LLM

2026-11-17 QR 카메라 대체 경로와 전술판 HTTPS 배포·게시 복구를 보완했다. GPS는 이 기기에서 한 번의 도착 확인으로 동작한다. 전술판은 교사와 참여자가 명시적으로 공유·갱신한다. 경기 사례 검색과 선택적 3B 모델은 [기기 내 실행 안내](tactics-pilot-stage3-device.md)를 따른다. AI 실기기 성능과 선택 품질은 마지막 검증 항목이다.

## QR 미션 카메라

교사가 해당 기기에 미션을 준비한 뒤 **학생 QR 미션 참여**를 연다. **카메라로 QR 스캔**을 누르고 카메라 권한을 허용해 코드가 화면에 온전히 들어오도록 비춘다. QR 자동 스캔을 지원하지 않거나 카메라를 열 수 없으면 QR 아래 무작위 ID를 입력하고 **미션 ID 열기**를 누른다. 스캔을 중단하려면 미션 패널을 닫는다. 권한 요청 도중 패널을 닫거나 화면을 벗어났을 때는 늦게 시작된 카메라와 판독 결과를 정리한다.

## GPS 미션

교사 PIN → 학급·제출 → **오프라인 QR·GPS 미션 만들기**에서 첫 활동의 GPS 옵션을 연다. 목표 위도·경도와 도착 반경(10~200m), 안전 구역 중심과 반경(20~1000m)을 입력한다. **현재 위치를 한 번 읽기**로 좌표를 입력할 수도 있다. 도착 구역 전체가 안전 구역 안에 있어야 하며 교사는 도로·차량·위험 시설·이동 경로를 직접 확인한다. 나머지 순서 활동은 기존 QR 활동으로 동작한다.

참가자는 이 기기의 익명 학생 미션 영역에서 미션을 열고 위치 확인 안내에 동의한 뒤 **현재 위치로 도착 확인하고 활동 완료**를 누른다. 위치를 계속 추적하지 않는다. 30초 이내의 위치, 최대 50m 정확도, GPS 오차 원 전체가 안전 구역과 도착 구역 안에 있다는 조건으로 확인한다. 거부·시간 초과·구역 밖·오차 과다는 완료로 처리하지 않는다. 확인이 안 되면 이동을 멈추고 교사 안내를 받는다. GPS가 없는 대체 활동은 교사가 GPS 옵션 없이 별도로 만든다.

목표·안전 구역 정의는 기존 PIN 암호화 미션 저장소에 보관한다. 실제로 읽은 참가자의 좌표·정확도·이동 경로는 저장하거나 서버에 전송하지 않는다. 응답에는 `locationVerified: true`만 추가한다. 위치 결과는 PIN/수업/화면이 바뀌거나 앱이 화면에서 벗어나면 사용하지 않는다. 미션은 기존처럼 현재 기기의 저장소에서 진행하며 여러 기기의 GPS 미션 동기화는 포함하지 않는다.

HTTPS·OS 위치 권한·실제 센서가 필요하다. 일반 PWA는 브라우저 권한을 사용하고 Android 호스트는 신뢰하는 앱 원본에만 전경 위치 권한을 중계한다. 백그라운드 위치 권한을 요청하지 않는다. 실내·GPS 없는 기기에서 실제 동작과 오차를 별도로 확인해야 한다.

## 공유 서버 준비

학급 기록 서버와 별도의 `server/tactics-hub.js`를 사용한다. Node 24에서 실행하며 추가 npm 패키지는 필요하지 않다. 학교 출시용 [통합 Caddy 설정](../examples/classroom-hub.Caddyfile)은 같은 HTTPS 주소로 전술판 공유 경로를 제공한다. Android APK는 전술판에 학교 HTTPS 주소를 입력한다. Ollama 연결과 비교자료 저장은 개발 환경의 시범 기능이며 학교 출시용 프록시의 공개 경로에서 제외했다.

```sh
# 예시: 값은 실제 배포 환경으로 바꾼다. 비밀값을 채팅이나 저장소에 기록하지 않는다.
export PE_TACTICS_ADMIN_TOKEN="$(openssl rand -hex 32)"
export PE_TACTICS_DB='/운영용/영속경로/tactics.sqlite'
export PE_TACTICS_PUBLIC_ORIGIN='https://pe.school.example'
# APK 호스트를 운영에 포함할 때만 추가한다. 웹 PWA는 같은 HTTPS 주소를 기본 허용한다.
export PE_TACTICS_ALLOWED_ORIGINS='https://appassets.androidplatform.net'
export PE_TACTICS_PORT='8788'
node server/tactics-hub.js
```

서버는 `127.0.0.1:8788`에만 바인딩한다. 같은 HTTPS 주소에서 `/classroom-api/`는 학급 서버, `/tactics/v1/boards`와 하위 경로는 전술판 서버로 보낸다. 전술판 경로는 접두사를 유지하며 원래 Host를 보존하고 `X-Forwarded-Proto: https`를 지정한다. HTTPS 공개 주소를 설정하면 영속 DB가 필요하고 외부 Origin은 같은 주소와 지정한 허용 목록만 받는다. 별도 전술판 도메인이 이미 있다면 해당 도메인과 사용할 앱 Origin을 각각 등록한다.

앱 호스팅과 공유 서버의 TLS 인증서가 실제 기기에서 신뢰되어야 한다. DB는 정적 웹 디렉터리와 별도인 영속 경로에 둔다. 관리자 비밀값은 운영자가 비밀 관리 수단으로 보관하고 교사에게 제공한다. PWA의 **서버 관리자 비밀값** 칸에 입력하며 교사 PIN과 다르다. 앱은 교사 메뉴를 닫거나 잠그면 이 값을 메모리에서 지운다. 로컬 개발은 공개 주소 설정 없이 `http://127.0.0.1:8788`을 사용할 수 있다.

## 기기 간 공유

1. 교사 PIN → 학급·제출 → 전술판에서 공유 서버 주소와 관리자 비밀값을 입력하고 **암호화 공유 만들기**를 누른다.
2. **읽기 전용 초대** 또는 **편집 초대** 내용을 신뢰하는 참여자에게 전달한다. 화면의 QR에도 동일한 내용이 들어 있다. 다른 기기에서 교사 PIN으로 학급을 연 뒤 **다른 기기에서 받은 전술판 초대 내용**에 입력해 가져온다. 초대는 웹 링크가 아니라 앱 입력용 코드이며 이 구현에서는 텍스트로 입력한다.
3. 배치 수정은 먼저 기존 PIN 로컬 저장소에 저장된다. **내 배치 변경을 공유 서버에 올리기**를 눌러 명시적으로 게시한다. 읽기 전용 초대는 로컬 사본을 편집해도 서버에 게시할 수 없다.
4. 연결이 끊겼다면 로컬 사본에서 계속 편집하고 연결을 복구한 뒤 게시 버튼을 다시 누른다. 서버에 바로 다음 버전의 동일한 배치가 있으면 그 버전으로 연결한다. 다른 배치가 먼저 올라갔다면 로컬 수정을 보존하고 **최신 공유 배치를 새 전술판으로 불러오기**로 나란히 비교한다. 게시와 충돌 해결은 참여자가 직접 진행한다.
5. 편집 권한은 공유 종료 권한도 포함한다. **서버 공유 종료**는 모든 초대의 서버 접근과 암호문을 삭제한다. 이미 각 기기에 받은 로컬 사본은 별도 삭제해야 한다. 만료/서버 장애 때도 **이 로컬 사본의 공유 연결만 해제**로 배치를 남기고 새 공유를 만들 수 있다. 이 동작은 원격 공유를 종료하지 않는다.

공유는 24시간 만료이고 갱신으로 연장되지 않는다. 서버는 SQLite에 암호문·토큰 해시·버전·만료만 보관한다. AES-GCM 키는 초대와 각 기기의 PIN 암호화 공유 메타데이터에만 존재한다. 판 제목·회고·스냅샷·학생/학급 식별자는 공유에서 제외하고 도형 ID도 익명 순번으로 다시 만든다. 초대에는 서버 접속 권한과 복호화 키가 있으므로 공개 게시하지 않는다. 새 빈 판·복제판은 원격 공유 연결을 물려받지 않는다.

## 선택적 Ollama 서버 연결과 참고자료

이 절은 개발 환경에서 시험하는 선택적 서버 방식을 설명한다. 기본 기기 내 검색·ID 선택은 [기기 내 실행 안내](tactics-pilot-stage3-device.md)를 따른다.

운영 컴퓨터에 Ollama와 해당 모델을 먼저 설치한다. 모델은 한국어·구조화 JSON 출력을 지원하는 모델로 실제 하드웨어에서 평가해야 한다. 아래 이름은 구성 예시이며 설치·성능·모델 사용권을 인증한 목록이 아니다.

```sh
# 별도 터미널에서 Ollama 실행. 모델 다운로드에는 인터넷과 모델 사용권 확인이 필요하다.
OLLAMA_HOST=127.0.0.1:11434 ollama serve
ollama pull qwen3:8b

# 공유 서버 실행 터미널: 위의 관리자/저장/HTTPS 환경변수도 함께 유지한다.
export PE_TACTICS_LLM_URL='http://127.0.0.1:11434'
export PE_TACTICS_LLM_MODEL='qwen3:8b'
node server/tactics-hub.js
```

학교 태블릿이 직접 8B 모델을 실행할 필요는 없다. 추론은 서버 컴퓨터의 CPU/GPU·RAM을 사용한다. 속도와 필요한 메모리는 모델·양자화·문맥 길이에 따라 다르다. 로컬 LLM URL은 같은 컴퓨터의 localhost HTTP Ollama 주소만 허용한다. 외부 생성형 AI API와 키를 사용하지 않는다.

전술판에서 종목·비교 관점을 고르고, 팀이 원하는 상황을 문장으로 설명한 뒤 전송 범위를 확인한다. 익명 배치·종목·비교 관점·요청 문장만 서버로 보내며, 현재 학급 학생의 이름과 눈에 띄는 연락처·식별번호는 전송 전 거부한다. 서버는 완전 오프라인으로 동작하는 국문/영문 용어 검색으로 같은 종목의 A/B·사실 확인 완료 카드 중 요청과 가까운 후보를 최대 8개 찾고, 같은 출처당 최대 2개로 제한한다. 후보만 로컬 Ollama에 보내며 모델은 최대 3개를 고른다. 경기 내용·조건·출처 제목과 링크는 참고자료에서 가져오며, 모델은 요청과의 닮은 점과 차이만 설명한다. 관련 후보가 없으면 모델 호출 없이 빈 결과를 돌려준다. 이는 검색 보강 생성(RAG)이며 모델 가중치를 학습하지 않는다. 모델명과 자료 검토 상태를 표시한다. 관련 사례가 없으면 빈 결과를 내며 새 전술을 만들어 답하지 않는다.

교사 PIN으로 여는 전술판의 서버 요청 흐름 외에, 학생·모둠이 PIN 없이 상황을 입력해 기기 자료를 검색하고 선택적으로 기기 모델을 사용하는 흐름이 있다. 학생 개인 계정은 필요하지 않으며, 실제 학교 기기 사용은 아직 검증하지 않았다.

기본 `server/tactics-knowledge.json`에는 [실제 경기 사례 조사 자료](tactics-ai-research-catalog.md)에서 정리한 농구 44개·배구 45개·축구 30개·티볼 8개·피구 10개, 총 137개 카드가 있다. 출처 대조 완료 A/B 카드 중 배구 42·43번의 명시적 AI 제한, 배구 33번의 부분 확인, C 등급 5개를 제외한 129개를 로컬 검색 후보로 둔다. 129개 모두 교사·코치 검토 전 초안이고 앱 이용 권리도 확인되지 않았다. 나머지 초안의 `reviewStatus` 승인 필터는 아직 없어, 제품 사용 전 교사·코치 검토와 이용 조건 확인을 연결해야 한다. 티볼은 일본 여러 지역·리틀리그 팀의 경기 보고, 피구는 여러 팀의 국제·대학·클럽 경기 분석을 포함한다. 원문 기사·영상 전체를 복제한 학습 자료가 아니다. 대회별 규칙·연령·공 종류가 다를 수 있어 앱은 학교 규칙에 바로 적용할 전술로 안내하지 않는다. `PE_TACTICS_KNOWLEDGE`로 교체하는 파일은 종목, 실제 경기 요약, 조건·맥락, 출처 제목과 HTTPS URL뿐 아니라 감사에서 부여한 `candidateGrade`와 `factStatus`도 포함해야 검색 후보에 들어간다.

모델 미설정·연결 실패·잘못된 JSON·없는 출처 ID는 실패로 표시한다. 모델이 선택한 각 항목에는 연결된 원 출처가 붙고, 경기 전개 자체는 모델이 새로 쓰지 않는다. 한 번에 모델 요청 하나, 같은 권한의 요청 간격 60초, 응답 제한 55초를 적용한다. 결과는 실제 경기의 여러 참고 사례이지 정답 전술이나 학생이 실행할 지시가 아니다. 팀은 각 사례의 공통점·차이·조건을 비교하고, 실제 경기와 현재 팀 상황이 다르다는 점을 확인한다.

## 실제 경기 사례 검색·검토 경로

별도의 [합성 예제 48개](../examples/tactics-review-starter/README.md)는 가상의 학교 체육 질문 묶음이다. “이 상황에서 어떻게 행동할까?”를 묻는 과거 검토 화면용 자료로, 실제 경기 사례나 검색 근거로 사용하지 않는다.

현재 기기 내 경로는 모델 가중치에 경기 사실을 외우게 하는 대신, 출처가 붙은 실제 경기 사례를 검색하고 모델이 허용된 ID만 선택하도록 한다. 기록·부분 조건·한계는 원자료를 표시한다. 서버 방식의 모델 비교 문구는 별도 미검토 초안이다. 학생이 팀의 전개와 막히는 지점을 설명하면 자료에 기록된 경기 조건과 한계를 살펴볼 수 있으며, 이를 정답이나 실행 지시로 단정하지 않는다. 카드 137개는 서로 다른 경기·장면 수나 학습 자료 수가 아니다. 과학적으로 확정된 종목별 최소 카드 수도 두지 않는다.

단계는 다음과 같다.

1. 기존 카드의 경기 사실과 행동 순서를 출처 문장·영상에 대조하고, 경기·상대·날짜·점수·근거 위치가 확인되지 않는 값은 미상으로 둔다.
2. 원문·영상의 앱 재사용 조건을 확인하고, 교사·코치가 경기 맥락과 설명의 적절성을 검토한다. 현재 137개 카드는 모두 `draft`다. 연합뉴스 배구 42·43번, 부분 확인 카드, C 등급은 검색에서 제외한다. 나머지 출처 대조 완료 A/B 자료를 `reviewStatus`로 거르는 교사 승인 게이트는 아직 구현되지 않았다.
3. 농구·배구 각 20건을 검색 파일럿의 운영 목표로 삼아 자연어 요청에서 적합 사례와 근거가 검색되는지 평가한다. 이 수치는 학습 최소치나 정확도 보증이 아니다.
4. 검색 요청·검토 기록은 모델의 자동 학습으로 연결하지 않는다. 이후 모델 튜닝을 검토하더라도 검색된 사실을 기억시키기보다 출처 비교·불확실성 설명의 형식을 평가한 뒤 별도 결정한다.

### 경기 사례 시범 자료 연결

서버 기본 실행은 `server/tactics-knowledge.json`과 `docs/tactics-pilot-status.json`에 수용된 두 조사 JSON 및 연결 CSV를 함께 읽는다. 배포 시 이 다섯 docs 파일과 `server/tactics-pilot-loader.js`를 같은 상대 경로로 복사하고 서버를 재시작한다. 자료가 손상되거나 ID·개수가 맞지 않으면 서버가 시작을 거부한다. `PE_TACTICS_KNOWLEDGE`로 기존 형식 파일을 지정하면 해당 파일만 사용한다. 사용자 시범 수용은 교사·전문가 검토나 권리 확인이 아니다. 기사 대조는 기록된 주장 범위에 한정되며 야구는 티볼과 공통 기술만 부분 비교한다. 연결의 확인된 조건과 빠진 조건을 확인해야 한다. 450개 평가 질문은 검색 자료나 모델 입력에 넣지 않는다. 450문항 검색 대조는 [실행 기록](tactics-retrieval-evaluation-2026-11-15.md)에 있으며 사람의 관련성 검토와 모델 전수 평가는 후속 단계다.

단계 2 검색은 입력 상황의 행동과 자료에 기록된 조건이 겹치는 후보를 직접 관련 또는 부분 관련으로 표시한다. 시범 자료는 항상 부분 관련이며 일치한 연결의 지원·미확인 조건만 표시한다. 규칙은 별도 확인해야 한다. 공통 기술이 포함된 티볼 요청은 야구 자료를 부분 비교할 수 있으나 규칙만 묻는 요청은 야구 자료를 제외한다. 이는 제한된 표현 규칙으로 동작하며 450문항 평가 결과는 아직 없다.

기기 내 3B 엔진 연결과 모델 설치·라이선스·오프라인 범위는 [기기 내 실행 안내](tactics-pilot-stage3-device.md)를 확인한다. 오프라인 Chromium에서 실제 3B ID 선택을 한 번 확인했으나 실측에 수 분이 걸렸고, Android 기기·학교 환경 검증은 대기 중이다.
