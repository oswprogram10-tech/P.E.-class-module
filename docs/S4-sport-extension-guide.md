# 실험용 종목 확장과 모델 프로필

2026-11-06. 농구의 기존 기본값·설정·이력 의미를 유지하면서 배구 머리 위 팔 스윙 연습 cue를 추가했다. 이는 로컬 개발 기능이며 실제 배구 감지 정확도나 교육적 타당성 검증 완료가 아니다.

## 사용과 세션 범위

교사 PIN → 수업 설정 → 「이번 실행의 종목」에서 배구를 선택하고 사용 여부·팔을 지정한 뒤 「이번 실행에 적용」을 누른다. 카메라와 준비된 전신 확인도 켜야 한다. 선택은 현재 탭 메모리에만 두며 재실행/새로고침과 PIN 데이터 초기화 후 농구 기본으로 돌아간다. 기존 저장된 농구 사용 여부·팔·민감도는 그대로 사용한다. 배구는 별도 팔·기본 민감도를 사용하며 저장하지 않는다.

적용할 때 기존 준비 상태·순간 이미지/효과음/시각 강조·이력 기록을 끈다. 농구로 돌아와도 이력·추가 피드백은 직접 다시 켜야 한다. 배구 화면에서는 농구 시도 로그를 기록하지 않는다. 기존 농구 이력 조회·삭제 기능은 유지한다. 학생·수업 맥락 변경, 전신 신뢰도 저하, 프레임 간격/추적 변화, 카메라·화면 중단 때 새 준비부터 시작한다.

배구 cue는 선택한 팔을 머리 위로 구부린 자세를 2프레임·250ms 이상 유지한 뒤, 준비 위치에서 손목을 옆·아래 방향으로 옮기며 팔을 펴는 자세를 다시 2프레임·250ms 이상 유지할 때 한 번 발생한다. 다음 cue 전에는 팔을 내리는 별도 유지가 필요하다. 느린 팔 동작 연습용이며 실제 빠른 스파이크 속도·3D 전방 운동·공 접촉·성공·기술 정확성·성적을 판정하지 않는다. 흔들기·다른 동작도 조건을 만족하면 반응할 수 있다. 현재 약 333ms 이상의 분석 간격에서 실제 고속 동작을 포착한다고 주장하지 않는다.

배구 이벤트는 `type: volleyball-overhead-cue`, `ruleVersion: volleyball-overhead-cue-v1`이며 농구 evidence·이미지·효과음·자동 제출·영속 이력은 만들지 않는다. `swing` 상태와 각도는 메모리에만 존재한다.

## 모델 로더의 허용 범위

`new PoseRuntime({ profileId: ModelProfiles.DEFAULT_ID })`는 등록된 `mediapipe-pose-lite-v1` 하나만 resolve한다. 기존 인자 없는 호출도 같은 공식 Lite를 사용한다. `ModelProfiles.list()`로 승인 목록과 출력 계약·라이선스 근거를 확인할 수 있다. 파일 업로드·사용자 URL·직접 weights·assets override·알 수 없는 옵션/ID는 지원하지 않는다.

프로필은 동일 출처의 기존 SDK/WASM/Lite `.task` SHA-256 pins와 버전을 불변 객체로 묶는다. 준비/실행 때 bytes를 다시 검증하며 fetch redirect는 거부한다. 출력 계약은 기존 MediaPipe Pose Landmarker 정규화 33관절·최대 1명이다. 현재 worker의 CPU·VIDEO 설정과 기존 캐시 버전/자산을 유지한다. 새 모델 다운로드나 외부 URL 요청은 추가하지 않았다.

이는 승인된 프로필 기반 로더 확장 인터페이스다. 호환되고 이용조건을 확인한 대체 모델 weights가 없어 다른 모델을 통합하지 않았다. 후속 대체 모델은 개발자가 동일 출력 계약·worker 호환·이용조건·고정 경로/hash·별도 캐시 버전과 경계 테스트를 확인한 뒤 코드의 승인 목록에 추가해야 한다. 임의 custom 모델 파일 지원 완료로 해석하지 않는다. 일반 앱 API 제한이며 같은 페이지의 악성 JavaScript나 DevTools를 격리하는 보안 장치가 아니다.

현재 모델 이용조건 근거는 [자산 기록](pose-assets.json)의 공식 모델 계열 카드와 SDK 라이선스를 따른다. 계열 카드가 정확한 `.task` archive hash를 인덱싱하지 않는 한계를 그대로 남긴다. 지역 pins는 공급자의 전자서명이 아니다.

## 평가와 제외 조건

기존 [S4.6 합성 평가](stage-S4-evaluation-validation.md)의 TP/FP/FN은 농구 규칙 전용이다. 배구에 재사용해 배구 정확도를 주장하지 않는다. 배구 단위 검사는 좌우·유지·재준비·손실/간격/설정/추적 초기화와 농구 위쪽 신전 구별을 정의된 좌표로 검사한다. 실제 자료의 독립 라벨·교사 검토·촬영 방향별 배구 성능은 미확인이다.

사용자 지시에 따라 Android·학교 환경·발열·40분 연속 사용 검사는 이번 범위에서 제외하고 대기로 유지한다. 학생 자료·새 모델·배포·네트워크/환경 변경은 수행하지 않았다. 실행 근거는 [종목 확장 검증](stage-S4-sport-extension-validation.md)을 따른다.
