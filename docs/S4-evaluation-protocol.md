# S4.6 평가와 자원 계측 절차

2026-11-06. 현재 산출물은 합성 입력에 대한 READY→SHOOT 규칙 평가와 Linux Node 개발용 자원 계측이다. 실제 학생·농구 영상의 감지 정확도, 골 성공·기술 정확성·성적 평가를 검증한 결과가 아니다. 실행 결과는 [S4.6 검증 기록](stage-S4-evaluation-validation.md)을 따른다.

## 평가 단위와 해석

한 sequence는 독립된 촬영 구간이다. 구간마다 새 detector를 만들고, 정의된 입력 시각의 landmark를 순서대로 처리한다. reference는 detector 출력에서 역산하지 않고 fixture에 선언한 사건 시간 구간이다. reference 구간의 양끝을 포함해 사건 하나와 detection 하나를 최대 한 번만 연결한다. 같은 구간에 여러 출력이 있으면 나머지는 FP이며, 연결되지 않은 reference는 FN이다. sequence 사이에서 사건을 연결하지 않는다.

TP는 연결 수, FP는 연결되지 않은 출력 수, FN은 연결되지 않은 reference 수다. precision=TP/(TP+FP), recall=TP/(TP+FN)이며 분모가 0이면 null이다. 전체와 촬영 방향·조건별 결과는 각 사건 수를 더한 micro 집계다. 그룹별 비율을 단순 평균하지 않는다. 연속 시간의 true negative는 정의하지 않으므로 accuracy·specificity를 계산하지 않는다. 사건 없는 구간의 FP 수와 관측 시간도 별도로 확인한다.

fixture의 방향은 수동으로 붙인 합성 시나리오 이름이다. 좌우 팔·좌표 이동·축소·가림·시간 간격 등의 정의된 변형을 다루지만, 실제 카메라 투영·역광·옷·나이·신체 차이·다인 상황을 재현하거나 방향별 성능 차이를 입증하지 않는다. 의도적으로 포함한 non-shot 팔 올리기 FP와 가림/간격 FN은 집계 경계와 규칙의 한계를 드러내는 개발 사례다. 이 비율을 현장 정확도로 인용하지 않는다.

## 실제 자료를 사용할 때의 후속 검증

학생 자료를 이번 작업에서 수집·업로드하지 않았다. 후속 실제 검증은 동의·보관/삭제 범위를 확인한 자료만 별도 로컬 관리하고 앱의 자동 제출과 분리한다. 교사와 먼저 감지 대상 사건을 정의하고, 모델 출력에 가려진 상태에서 두 검토자가 사건 시각/구간·촬영 방향·거리·조명·가림과 제외 사유를 기록한다. 불일치는 교사 검토로 조정하고 판정 일치 수준을 남긴다. 공이 없는 유사 팔 동작과 추적 실패도 포함한다.

검증 전 reference 구간 또는 허용 시차와 규칙 버전을 고정한다. 결과를 본 뒤 시차를 넓히거나 임계값을 바꾼 자료는 개발 자료로 분리한다. 학생·수업별로 개발/검증 자료를 분리하고 같은 동작의 인접 프레임을 양쪽에 배분하지 않는다. 사건 수·촬영 시간·FP/FN 사례와 방향/조건별 분모를 함께 보고한다. 자료가 충분하면 학생/수업 군집을 고려한 불확실성 구간을 제공한다. 지금의 소수 합성 사례에는 모집단 추정이나 신뢰구간을 붙이지 않는다. 교사 검토와 외부 검증 전 종목 확장의 실제 감지 정확도·교육적 타당성 검증 완료를 선언하지 않는다. 로컬 개발 기능 구현과 이 판정을 구분한다.

## 자원 계측과 기기 검증 경계

신규 Node benchmark는 준비된 좌표를 규칙 모듈에 반복 입력하는 프로세스만 측정한다. wall time·CPU user/system·RSS/heap 전후·프로세스 최대 RSS는 모델 추론이나 브라우저 전체 비용이 아니다. JIT·GC·공유 호스트 부하로 수치가 변하며 RSS 전후 차이는 누수 판정이나 최대 메모리 증가량을 뜻하지 않는다. 프로세스 최대 RSS에는 준비·warm-up도 포함된다. 표본 수·반복 수·환경·코드/fixture hash를 결과에 남긴다. 시간상 가속 반복은 실제 수업 길이의 연속 실행이 아니다.

기존 [실제 모델 측정 JSON](S4-real-model-measurement.json)은 별도 과거 환경의 정지 사진 추론과 각각 약 4초인 가상 카메라 baseline/동시 실행 결과다. baseline 36프레임/4003.3ms, 동시 36프레임/4000.2ms, 동시 구간 새 결과 11개·관측 지연 1091.5ms를 기록했다. 해당 JSON의 inferenceMs 배열은 구간별 결과 수와 같은 모집단으로 단정하지 않는다. 새 규칙 benchmark와 합산하지 않으며 이번에 재측정한 값으로 표시하지 않는다.

실제 Android 후속 측정은 기기 모델·RAM·OS/Chrome·모델/코드 hash·해상도·배터리/충전·주변 온도·설정을 먼저 기록한다. 동일 조건에서 AI 끔 baseline과 AI 켬을 별도 실행하고 초기 로딩/첫 추론을 warm 상태와 구분한다. 40분 실제 카메라·지연·탐색·30초 저장을 수행하며 일정 간격의 캡처율·추론 지연 분포·프레임 건너뜀·표시 지연·메모리·배터리·온도/thermal 상태를 기록한다. Android 도구가 허용하면 adb dumpsys meminfo/batterystats와 thermalservice를 보조 근거로 쓰고, 브라우저 heap만으로 전체 메모리를 대신하지 않는다. 권한·잠금·복귀와 감속·중단·실패도 기록한다. 현재 이 실기기/발열/40분 항목은 모두 미실행이다.
