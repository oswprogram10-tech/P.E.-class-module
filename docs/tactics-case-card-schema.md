# 실제 경기 사례 카드 스키마 v1

작성일: **2026-11-13**

기계가 읽는 기준은 [`server/tactics-case.schema.json`](../server/tactics-case.schema.json)이고, 입력 예시는 [`tactics-case-schema-example.json`](../examples/tactics-case-schema-example.json)의 경기 흐름 요약과 [`tactics-case-volleyball-45.json`](../examples/tactics-case-volleyball-45.json)의 두 득점 시퀀스다. 스키마는 기존 `tactics-knowledge.json`을 아직 변환하지 않는다. 마이그레이션 전에는 새 형식의 카드가 기존 앱에 연결되지 않는다.

## 데이터 단위

카드 한 장은 확인 가능한 경기 장면 하나를 기록한다. 출처가 점수 흐름만 설명한다면 `scene.level`을 `match-flow`로 둔다. 기사에 없는 랠리나 포제션을 만들어 더 자세한 장면인 것처럼 쓰지 않는다. 통계 연구의 집계 결과는 `aggregate`이며, 특정 경기의 `point`, `possession`, `rally`, `sequence`와 구분한다.

필드가 출처에 없으면 빈칸을 추측해 채우지 않는다. 날짜·시각 등 모르는 값은 `null`, 모르는 사건 전개는 빈 `events` 배열로 둔다. 확인된 출처 문장과 조사자 관찰은 각각 `sourceClaims`와 `interpretation`에 기록한다. 점수나 경기 승패는 관찰된 결과이며, 전술의 원인·효과를 입증하지 않는다.

## 핵심 필드

| 그룹 | 내용 | 작성 원칙 |
| --- | --- | --- |
| `rulesContext` | 경기 형식·규칙 판본·연령/부문 | 출처에 나온 만큼만 기입. 모르면 `null` |
| `match` | 대회·단계·날짜·팀·결과 | 각 카드가 어느 경기를 가리키는지 재식별할 수 있게 기록 |
| `scene` | 장면 수준·이닝/쿼터/세트·시각·점수 흐름·행동 순서·결과 | 경기 진행 수준을 과장하지 않고, 이벤트마다 근거 주장 ID를 연결 |
| `sourceClaims` | 출처에서 확인할 수 있는 사실의 짧은 바꿔쓰기 | 주장 하나씩 확인 상태와 문단/표/영상 시점을 기록 |
| `interpretation` | 원 출처의 분석, 조사자 관찰, 한계, 질문 | 출처의 분석과 조사자 해석을 섞지 않으며, 질문은 탐구용으로 쓴다 |
| `searchTags` | 종목 용어와 검색용 표현 | 사례를 찾는 분류어다. 경기 사실이나 추천 작전으로 취급하지 않는다 |
| `sources` | 제목·게시자·URL·발행일·접근일·정확한 근거 위치·이용 권리 상태 | 공개 접근과 콘텐츠 재사용/학습 허가를 분리해 기록 |
| `review` | 사실·근거·교사·종목 전문가 검토 | 서로 독립된 상태다. 교사 승인만으로 출처 사실이나 권리를 승인하지 않는다 |

## 상태의 의미

- `sourceClaims.checkStatus`: 출처 문장을 아직 대조하지 않음(`pending`), 일부 주장만 대조(`partially-verified`), 카드의 사실 주장을 모두 대조(`verified`), 또는 반박/오류로 제외(`rejected`).
- `review.factStatus`: 카드 전체 사실 주장의 확인 수준이다. 일부만 확인되면 `partial`을 유지한다.
- `review.evidenceStatus`: 해당 장면을 다시 찾을 근거 위치가 없음/부분/충분한지 기록한다. 직접 영상 타임스탬프, 플레이바이플레이 행, 기사 문단/표 등이 가능하다.
- `sources[].reuse.status`: 원문·영상의 재사용, 재배포, 모델 학습 권리를 각각 확인한다. 기본값은 `not-checked`; “웹에서 읽을 수 있음”만으로 `limited-use-cleared`로 바꾸지 않는다.
- `educatorStatus`와 `expertStatus`: 교사와 종목 분석자/코치의 검토를 따로 기록한다. 교사가 실제로 검토하지 않았으면 승인 상태로 만들지 않는다.

## 기존 카드 이관 규칙

기존 카드의 `title`, `observed`, `context`, `tacticTags`, 출처 정보를 그대로 자동 승인하지 않는다. 이관할 때는:

1. `observed`의 각 주장에 출처 근거를 붙이고, 대조 전에는 `pending`으로 표시한다.
2. 경기·날짜·팀·점수·시간은 확인된 필드만 채운다. 확인되지 않는 항목은 `null` 또는 `unknown`으로 남긴다.
3. 여러 랠리/행동이 묶여 있으면 출처가 각각 구분하는 만큼 이벤트를 나누거나 `match-flow` 수준으로 낮춘다.
4. `tacticTags`는 `searchTags`로 옮기고, 카드에 없는 행동이나 효과를 새로 추론하지 않는다.
5. 모델 응답에 나온 유사성 설명은 원자료 카드에 쓰지 않는다. 이는 검색 당시의 비교 결과이지 경기 사실이 아니다.
6. 출처가 사라졌거나 주장과 맞지 않으면 출처를 교체해 좁힌 요약을 다시 검토하거나 검색 후보에서 제외한다.

첫 예시 카드는 배구 18번의 공식 구단 리포트에서 확인되는 2세트 점수 흐름으로 필드를 채운 것이다. 두 번째 예시는 USA Volleyball 리포트가 설명하는 미국-이란전 결정 세트의 마지막 두 득점이다. 랠리별 정보가 없어서 `match-flow`로 표시하고 전술 원인을 적지 않았다. 사실 두 항목의 문장 대조는 끝났지만 별도 영상/기록지, 종목 전문가 검토, 콘텐츠 이용 조건이 미확인이라 카드 전체 상태는 여전히 `partial`/`pending`이다.
