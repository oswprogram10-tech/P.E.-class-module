# S2 장면 복습·성찰의 구현·검증 기록

검증일: 2026-11-05. Linux Chromium 155.0.8059.79, Node v24.22.1, Playwright 가상 카메라, FFmpeg/ffprobe와 로컬 loopback 서버에서 확인했다. S2.1~S2.6의 로컬 기능을 구현했으며 실제 Android·광학 입력·학교 수업 성능은 미확인이다. S3에는 착수하지 않았다.

## 구현과 확인 범위

| 작업 | 구현·검증한 동작 | 범위와 한계 |
| --- | --- | --- |
| S2.1 | 비동기 그리기까지 완료된 `lastDrawnFrame`을 선택의 기본 끝 경계로 사용. 창을 열 때 스냅샷을 고정 | 표시 장면이 없거나 버퍼에서 사라지면 안내. 이전 영상이 부족해도 최신 구간으로 조용히 이동하지 않음 |
| S2.2 | 확보된 프레임 인덱스로 시작·끝 개별 조절, 경계 장면 정지 미리보기·구간 반복. 소수 초 무음 WebM | 5~30초·누락 검사 유지. 시작 포함/끝 경계 제외, 길이 밀리초 내림 오차 1ms 미만. 원 프레임 시각과 출력 10fps를 구분 |
| S2.3 | 교사 목록에서 속도·반복 재생, 명시적 파일 내보내기와 평문 확인 | 저장 암호문·길이 불변. 교사 접근 종료·만료 시 내보내기 차단. 앱 밖 파일은 PIN·자동 삭제 보호 밖 |
| S2.4 | 로컬 시범 영상의 겹침/나란히, 투명도·크기·위치·시점·재생 조절 | 화면 비교만 제공하고 저장 파일에 합성하지 않음. 파일 교체·삭제·페이지 종료 때 URL 해제, 숨김 때 일시정지 |
| S2.5 | 잘된 점·다시 시도할 점 각각 최대 300자, 메타데이터 암호화·교사 목록 표시 | 성찰 없는 이전 클립 호환. 현재 기기의 7일 보관 정책이며 장기 포트폴리오·클라우드 제출 아님 |
| S2.6 | 1~300초 지연 설정, 실제 촬영 경과·샘플 경계·메모리 부족 구분 | 실제 310초 가상 촬영 및 합성 부족 검사를 아래에 기록. 모든 기기·장면에서 300초를 보장하지 않음 |

사용 흐름은 [복습·비교·성찰 안내](S2-review-guide.md)를 따른다. 셸은 `pe-loop-shell-v7`로 올렸고 S1의 대기·자연 활성화·오프라인 캐시 정책을 유지한다.

## 정밀 선택과 실제 출력

합성 원 프레임의 시각을 44.750초와 50.000초로 선택해 **정확히 5.250초**를 저장했다. 실제 파일은 무음 비디오 53개 패킷이며 `ffprobe` 패킷 끝도 5.250초였다. 마지막 50ms 프레임은 BlockDuration을 사용하고 비키프레임의 ReferenceBlock을 기록한다.

Chrome에서 파일을 실제 재생·탐색한 RGB는 다음과 같다. 모든 채널 오차는 허용한 15 이내이며 이 실행의 최대 오차는 4였다.

| 시점 | 선택한 원본 RGB | Chrome RGB |
| --- | --- | --- |
| 시작 | 64, 196, 152 | 64, 197, 148 |
| 중간 | 126, 94, 98 | 125, 94, 99 |
| 끝 직전 | 219, 51, 127 | 218, 51, 127 |

분수 길이 검사에서 일시정지 상태의 동일 프레임에 새 프레임 콜백을 기다려 멈추는 검사 문제가 있었다. 실제 재생으로 첫 표시를 확인한 뒤 탐색·화면 갱신을 기다리고 시간 제한을 두어 진단했다. 기대 색상·채널별 오차·실제 패킷 검사는 약화하지 않았다.

실제 성찰 textarea 두 개를 채워 `saveSelectedClip`을 실행한 뒤 복호화한 문구 일치와 원 저장 레코드에 평문이 없는 것을 검사했다. 별도로 성찰 있는 암호화 기록과 이전 메타데이터를 읽고 재생·내보내기 경계를 검사했다.

## 300초 버퍼의 실제 경과시간 측정

원시 수치는 [측정 JSON](S2-buffer-measurement.json)에 보관했다. 합성 시각 검사가 아니라 가상 카메라를 각각 실제 310초 실행한 측정이다. 실제 학생 영상·이름·PIN·키는 측정 결과에 없다.

| 항목 | S1 기준 촬영, 310초 시점 | S2 300초 지연, 310초 시점 |
| --- | ---: | ---: |
| 보관 프레임 | 2,772 | 2,756 |
| JPEG 바이트 | 8,323,228 | 8,287,877 |
| 보관 프레임 시각 범위 | 299.9874초 | 299.9554초 |
| 평균 샘플 간격 | 108.260ms | 108.877ms |
| 최대 샘플 간격 | 134.200ms | 283.000ms |
| 바이트/프레임 한도 도달 | 아니오 | 아니오 |

S2 시험은 실제 첫 프레임부터 300초가 지나기 전에는 지연 화면을 표시하지 않았다. 이후 8회 표시 나이 표본은 **299.9925~300.0958초**였다. 300초 시점의 단일 샘플에서는 아직 UI 주기가 표시를 완료하지 않았으며 310초 확인과 최종 표본에서는 정상 표시했다.

5분 보관 창에서 샘플의 양 끝이 정확히 300초 차이가 되는 것은 드물다. 실제 설정 시간이 지난 뒤, 필요한 보관 범위가 확보되고 목표 시각과 최초 보관 프레임 차이가 최대 150ms일 때만 샘플 지터를 허용한다. 메모리 한도로 수십 초가 부족한 상태를 이 허용 범위로 숨기지 않는다.

이 환경의 저복잡도 가상 카메라는 약 8.3MB로 80MiB 예산 안에 들어 300초 지연을 지원했다. 보장 범위는 5분·3,001프레임·80MiB 중 먼저 도달한 제한 안의 영상이다. 장면 복잡도와 기기에 따라 유지 시간이 짧아지면 안내 후 지연을 줄여야 한다. 선택 스냅샷과 디코더·인코더·전체 브라우저 메모리는 JPEG 바이트와 별도다. JS 힙 표본만으로 전체 메모리 안정성을 주장하지 않는다.

## 실행한 검사

기존 Node 13개와 신규 정밀 Timeline 4개, **단위 검사 17개**를 통과했다. 기존·S1 브라우저 9종과 신규 S2 5종, **브라우저 스크립트 14종**이 아래 범위로 통과했다. 실제 Android 검증을 포함하지 않는다.

| 명령 | 결과·범위 |
| --- | --- |
| 각 `tests/*.test.cjs`의 TAP 실행 | 17개 통과. 버퍼·암호화·만료·시각 선택·WebM 및 분수/지터 경계 |

기존 선택 검사의 촬영 준비는 실제 표시된 프레임 앞에 필요한 구간이 확보될 때까지 기다리도록 갱신했다. 출력은 실제 선택 시각·밀리초 내림과 비교하며 무음·상한·색상·취소/재시도·교사 접근 검사를 유지했다. 기본 sandbox의 로컬 `listen EPERM`은 해당 검사만 최소 권한 실행으로 해결했다.

Sol은 작업·파일 소유권·통합과 화면/실측/reference 검사를 맡고, Terra는 제품 구현과 복잡한 출력·회귀 진단, Luna는 독립 검사와 성찰·접근 테스트를 맡았다. Luna가 최종 5.25초 출력 검사를 직접 독립 실행해 종료 코드 0을 확인했다.

최종 수정 후 PWA·기존 데이터·화면 검사도 다시 통과했다. JavaScript 문법·기존/신규 파일 공백 검사와 문서 상대 링크를 확인했다. 필요한 검증이 통과한 뒤 관련 없는 검사는 반복하지 않았다.

## 남은 외부 조건

- 실제 Android의 회전·키보드·권한·WebCodecs 지원과 메모리·발열·배터리·화질, 300초 장면 유지와 40분 수업은 미확인이다.
- 실제 HTTPS 설치·업데이트·버전 복귀와 현장 교사 준비·수업 측정은 기존 S1 외부 대기를 유지한다.
- 외부 시범 영상 URL·교과서 QR, 장기 포트폴리오·클라우드 제출·AI 분석은 구현하지 않았다. S3에는 착수하지 않았다.
- commit/push·외부 배포·클라우드 설정 변경은 수행하지 않았다. 기존 목표와 S1 변경을 보존했다.
