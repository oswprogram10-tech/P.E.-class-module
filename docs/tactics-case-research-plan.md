# 실제 경기 사례 중심 조사 계획

작성일: **2026-11-13**

## 목적과 방향 변경

학생이 자기 팀의 현재 경기 전개와 막히는 지점을 설명하면, 앱이 실제 경기 기록에서 가까운 장면을 찾아 출처와 함께 보여주고 AI가 공통점·차이점·자료의 한계를 설명하도록 한다. 전술명을 정답처럼 외우거나 학생에게 특정 작전을 실행하라고 지시하는 기능은 목표가 아니다.

따라서 조사 단위는 “전술 하나”가 아니라 **실제 경기에서 관찰된 한 포제션·랠리·플레이 연쇄 또는 구분 가능한 경기 국면**이다. 전술 용어는 검색 태그와 분류 체계로만 활용한다. AI는 사례를 새로 학습해 기억하는 대신 검색된 사례를 요청 시 참고한다. 추후 지도 학습을 하더라도 출처 사실보다 사례 비교·출처 표시·불확실성 표현 방식을 가르치는 용도로 분리한다.

## 자료 수집 기준

### 한 장면 카드에 기록할 항목

각 카드는 한 출처의 주장과 조사자가 정리한 해석을 구분하고, 확인되지 않은 값은 추측하지 않고 `unknown`으로 둔다.

| 필드 | 기록 내용 |
| --- | --- |
| 식별·경기 | 카드 ID, 종목, 경기 ID, 대회·리그, 경기일, 팀, 경기 형식·규칙 버전. 출처가 밝힌 범위까지만 기록 |
| 장면 조건 | 이닝·쿼터·세트·포인트·시간·점수·공 소유·로테이션 등 해당 종목에 필요한 당시 조건. 알 수 없는 항목은 비워 둠 |
| 관찰 기록 | 장면 직전 상황, 확인된 행동 순서, 상대의 대응, 이어진 다음 행동 |
| 기록된 결과 | 슛·득점·아웃·턴오버·랠리 결과 등 출처에서 확인되는 결과. 결과와 전술의 인과관계를 임의로 단정하지 않음 |
| 증거·출처 | 출처 제목·URL·게시자·게시일, 영상 타임스탬프나 문서의 절/문단/표 등 장면을 다시 찾을 위치, 근거 종류 |
| 해석·비교 | 출처가 직접 제시한 해석과 조사자의 해석을 별도 필드로 둠. AI가 나중에 만드는 요청과의 유사성 설명은 원자료 사실로 저장하지 않음 |
| 검색 분류 | 경기 국면, 공간·배치, 수적 관계, 상대 대응, 사용자가 흔히 겪는 막힘 등 검색 태그 |
| 검토·권리 | 사실 확인자·검토 상태, 규칙 차이, 출처 이용 조건, 재사용·재배포·모델 학습 허가 확인 범위 |

개인 식별 정보는 수집하지 않는다. 영상 파일·기사 전문·도표를 복사하지 않고 링크와 필요한 최소한의 출처 위치, 자체 요약을 저장한다. 공개된다는 사실만으로 재배포 또는 모델 학습 허가가 있는 것으로 간주하지 않는다.

### 자료 출처 우선순위

1. **1순위 — 장면을 직접 확인할 수 있는 자료:** 공식 경기 영상·공식 플레이바이플레이·대회 기술 보고서·공식 경기 분석. 경기와 장면 시점을 함께 식별할 수 있는지 확인한다.
2. **2순위 — 장면을 구체적으로 설명하는 분석:** 리그·종목단체·방송사·팀의 경기 리뷰와 전술 분석. 경기 결과만 요약하는 글과 실제 장면 설명을 구별한다.
3. **3순위 — 연구·공개 경기 데이터:** 표본, 코딩 정의, 규칙·대회 범위, 데이터 이용 조건이 확인되는 경기 분석 연구. 통계적 연관성을 특정 장면의 원인·효과로 바꾸지 않는다.
4. **제외 또는 배경 분리 — 일반 전술 설명:** 특정 경기·장면을 확인할 수 없는 교본, 훈련안, 전술 사전, 생성형 요약. 용어 체계에는 참고할 수 있지만 실제 경기 사례 카드로 쓰지 않는다.

예정 검색 경로는 농구의 NBA·FIBA·KBL 경기 영상 및 필름 분석, 배구의 FIVB·Volleyball World·KOVO 경기 분석과 랠리 자료, 축구의 FIFA Training Centre·UEFA·KFA 경기 분석, 티볼·피구의 실제 대회·팀·지역 리그·대학/클럽 경기 기록과 영상이다. 이는 조사할 출처 후보이며, 출처를 열고 장면을 검증하기 전에는 해당 자료가 확보됐다고 기록하지 않는다.

## 종목별 조사 우선순위

먼저 현재 카드가 가장 많은 농구와 배구에서 새 카드 형식과 출처 검토 절차를 시범 적용한다. 기준이 안정되면 축구로 넓히고, 규칙·연령·대회 형식의 차이가 큰 티볼과 피구는 규칙 맥락을 필수 필드로 두고 별도 보강한다.

| 종목 | 조사할 경기 상황의 예 | 추가로 분리할 맥락 |
| --- | --- | --- |
| 농구 | 공격 시작 상황, 볼스크린 뒤 수비 대응과 후속 선택, 전환 공격·수비, 컷·공간 지원, 인바운드·세트 상황 | 리그·팀 수준, 쿼터·점수·샷클락, 라인업, 수비 커버리지. 출처에 없는 값은 기록하지 않음 |
| 배구 | 서브와 리시브, 리시브 질에 따른 세터 선택, 공격과 블록·후위 수비 대응, 랠리 전환과 커버 | 실내·비치, 세트·점수·로테이션, 서브권, 대회 규칙과 공격 템포 |
| 축구 | 압박을 끌어내는 빌드업, 압박 탈출, 전환, 측면·중앙 전개, 세트피스와 수비 대응 | 포메이션만으로 장면을 설명하지 않음. 경기 시점·점수·선수 위치가 확인되는지 표시 |
| 티볼 | 타격 뒤 주루·수비 송구, 주자 상황에 따른 수비 선택, 아웃·진루 장면 | 대회·팀별 규칙, 연령, 베이스 간격, 주루·아웃 규정 |
| 피구 | 공격권 전환, 투구 선택·회피, 팀 배치와 수비, 경기 속도 변화 | 국제·대학·클럽 등 경기 형식, 공 수·코트·선수 수·아웃 및 복귀 규칙 |

이 표는 조사 분류표이지 추천 전술이나 효과 검증 기준이 아니다. 성공·실패 사례를 가능한 한 함께 모으고, 자료가 한쪽만 보여주면 그 편향을 카드에 표시한다.

### 티볼 질문에 야구 경기 사례를 비교 자료로 연결하는 기준

티볼과 야구는 타구를 처리하고 주자를 진루시키려는 공통 장면이 있으므로, 티볼 사례가 부족한 검색 질문에는 실제 야구 경기 사례를 **비교 자료**로 추가할 수 있다. 다만 야구 장면을 티볼 사례로 재분류하거나, 야구의 결과를 티볼에서 그대로 재현할 수 있다고 표현하지 않는다. 일본 티볼 협회 규칙도 티볼을 투수가 없고 티 위의 정지한 공을 치는 경기로 설명하며, 공식 규칙 발췌에는 도루·번트·푸시번트·슬라이딩 금지가 명시되어 있다. 한편 협회는 대회 규칙과 소규모 놀이 규칙이 다를 수 있고, 경기 운영 방식도 전원 타격 후 교대와 3아웃 교대 등으로 나뉠 수 있다고 안내한다. 따라서 티볼 사례와 비교 사례 모두 `rulesContext`를 유지하고, 적용 가능성은 해당 질문의 티볼 경기 형식에 맞춰 판정한다. ([티볼 공식 규칙](https://www.teeball.com/kyougikisoku/), [경기 방법과 놀이 방식](https://www.teeball.com/competition-method/))

비교 후보를 카드나 평가 질문에 붙일 때 다음 정보를 별도로 기록한다.

| 필드 | 기록 기준 |
| --- | --- |
| `sourceSport` | 실제로 기록된 종목. 비교 카드라면 `baseball`로 유지 |
| `crossSportRelation` | `shared-skill`(규칙 차이와 무관하게 비교할 수 있는 공통 기술), `conditional`(해당 티볼 경기의 규칙을 확인한 뒤 비교 가능) 중 하나. 어느 쪽에도 해당하지 않는 야구 장면은 티볼 검색 후보에 넣지 않음 |
| `sharedElements` | 타구 방향 판단, 수비 위치, 중계·백업, 송구 선택 등 실제 기록에서 확인되는 공통 행동만 기입 |
| `tballDifferences` | 투수/타격 방식, 주자·아웃·득점 방식, 수비 인원·경기장 크기 등 비교에 영향을 주는 차이와 확인한 티볼 규칙 |
| `applicableFormat` | 적용 가능하다고 확인된 티볼 대회·수업 형식. 모르면 `unknown`으로 두고 조건부 비교로 유지 |

예를 들어 야구의 외야 타구 중계·백업·송구 선택은 티볼에서도 공통 수비 과제로 비교할 수 있다. 포스 아웃, 뜬공 뒤 주루, 주자 진루와 득점 장면은 해당 티볼 경기의 아웃·주루·득점 규칙을 확인한 경우에만 조건부로 연결한다. 티볼 규칙에 대응시킬 수 없는 야구 장면은 별도 비교 항목으로 만들지 않고 티볼 검색 후보에서 제외한다.

AI 검색 결과에서는 티볼 직접 사례를 먼저 보여주고, 직접 사례가 부족할 때 공통 기술 사례 또는 규칙 확인을 마친 조건부 사례만 별도 표식과 함께 제시한다. 각 비교 카드에는 “공통점”, “확인한 티볼 규칙과 차이”, “학생이 자기 팀 상황과 비교해 볼 질문”을 붙인다. 이는 정답 전술이나 실행 지시가 아니라 참고 사례이며, 공통점과 차이의 설명은 카드 원문 사실 및 출처와 분리해 생성한다. 티볼 질문의 검색 평가에서는 야구 비교 사례가 있다는 이유만으로 현재의 직접 사례 공백을 해결 처리하지 않고, 사람 검토 뒤 비교 적합성 라벨을 부여한다.

### 시범 목표와 중단 기준

- 첫 시범은 농구·배구 **각 20개의 교사·코치 검토 후보 장면**으로 한다. 기존 카드가 기준을 통과하면 재사용하고, 부족분만 새로 조사한다.
- 5종목 전체의 첫 검색 가능 묶음도 종목별 20개를 작업 목표로 둘 수 있으나, 티볼·피구에서 출처가 없는 내용을 만들어 채우지 않는다. 목표 미달 자체를 자료 한계로 보고한다.
- 종목별 20개는 검색 구조와 검토 절차를 시험할 작은 파일럿이다. 20개를 달성했다고 전술 전반의 정확도, 실제 수업 적합성, 모델 학습 충분성을 주장하지 않는다.
- 이후 수집은 고정된 카드 수를 채우기보다 평가 질문에서 반복되는 공백에 따라 10개 안팎의 소규모 묶음으로 보강한다. 하나의 경기·출처에 카드가 몰리면 총량이 충분해도 다양성이 부족한 것으로 판단한다.
- 성능 평가는 카드 수가 아니라 질문별로 적합 사례가 검색되는지, 출처가 해당 장면을 지지하는지, 자료가 없을 때 모델이 거절하는지로 종료 여부를 판단한다.

## 검색 및 데이터 사용 계획

1. 검색 전에 종목을 필수 조건으로 적용한다. 현재 구현은 팀 요청의 국문·영문 용어와 한글 bigram에 BM25 방식의 점수를 매기고, 선택한 비교 관점과 전술판의 표식은 약한 검색 힌트로 더해 후보를 좁힌다. 의미 임베딩은 아직 사용하지 않으며, 평가 질문에서 어휘 검색의 누락이 반복될 때 별도 검토한다.
2. 상위 후보와 근거 필드만 로컬 모델에 제공한다. 모델은 서버가 검색한 후보 ID 안에서만 사례를 선택하고, 닮은 점·다른 점·불확실성을 설명한다. 응답은 카드 ID 및 출처로 검증한다. 현재 교사·코치 승인 게이트는 아직 구현되지 않아 실제 후보는 모두 `draft`이며, 제품 사용 전 검토와 이용 조건 확인을 연결해야 한다.
3. 출처의 문장이나 영상에 없는 행동·점수·시점·인과를 보충하지 않는다. 관련 사례가 없거나 규칙 조건이 맞지 않으면 빈 결과나 추가 질문을 반환한다.
4. 경기 사실 카탈로그, 교사·코치가 검토한 검색 결과 예시, 평가 질문 세트를 서로 다른 파일·용도로 관리한다. 평가 질문과 유보 사례를 학습에 섞지 않는다.
5. 교사·학생의 매 검색 요청을 자동으로 학습 자료로 저장하지 않는다. 검토된 자료를 명시적으로 승인한 뒤 별도 버전으로 추가한다.

현재 런타임은 로컬 용어 검색으로 팀 요청·비교 관점·전술판의 패스/이동/공격/수비 표시를 반영해 후보를 최대 8개 고른 뒤 같은 컴퓨터의 Ollama에 보낸다. 출처 대조가 `verified`이고 A/B 등급이며 `aiUseBlocked`가 아닌 사례만 검색한다. 부분 확인·C 등급·명시적 AI 제한은 제외되고, 관련 후보가 없으면 모델을 호출하지 않는다. 검색은 임베딩이나 가중치 학습이 아닌 국문/영문 용어 점수화와 한글 bigram 보강이며, `reviewStatus` 교사 승인 게이트는 아직 없다. 현재 검색 가능한 129개도 모두 초안이고 이용 권리는 미확인이다.

## 별도 데이터 분할·평가 원칙

- 동일 경기, 동일 출처 글, 같은 플레이의 변형 카드는 평가 세트와 검색 개발 세트에 걸쳐 중복되지 않게 묶어 관리한다.
- 질문 세트는 학생의 문제 설명처럼 자연어로 작성하고, 직접 관련된 사례·부분적으로만 유사한 사례·자료가 없는 상황을 포함한다.
- 검색 지표는 관련 사례의 상위 5개 포함 여부와 상위 3개 관련성으로 본다. 응답 지표는 출처가 주장한 사실과 카드에 기록된 사실의 일치, 비교 근거, 한계 설명, 무근거 추측의 부재를 별도로 평가한다.
- 교사·코치는 교육적 설명의 적절성을, 종목 지도자나 경기 분석자는 경기 사실·상황 비교의 타당성을 검토한다. 어느 한 검토 결과도 실제 학생 팀에서의 효과 검증을 대신하지 않는다.
- 기사에 “이 전술로 이겼다”고 적혀 있어도 결과만으로 전술의 인과 효과를 승인하지 않는다. 상대 대응·라인업·시간·점수 등 확인 가능한 맥락을 보존한다.
