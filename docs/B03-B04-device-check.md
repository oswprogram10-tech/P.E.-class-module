# B03·B04 — A9+ 실기기 검증 절차

상태: 절차 작성 완료, 실제 실행 대기. 이 문서는 측정 결과가 아니다.

## 시작 조건

- 실제 갤럭시 탭 A9+, 설치된 Android·Chrome 버전과 RAM 구성 기록.
- 검증할 배포 버전과 HTTPS 주소, 일반 탭 및 설치 PWA 각각의 실행 환경.
- 저장소 여유와 배터리 상태 확인. 검증 중 실제 학생을 촬영하지 않는다. 움직이는 시계·테스트 영상 또는 성인 시연을 사용한다.
- 연속 촬영 중 상태 확인을 위해 별도 PC의 Chrome 원격 디버깅을 사용할 수 있어야 한다. 태블릿 설정 앱으로 이동하면 촬영이 중단되므로 연속 시험 중에는 앱을 전면에 유지한다.

## B03 — 실제 40분 연속 촬영

| 시점 | 실행 | 기록·판정 |
| --- | --- | --- |
| 시작 전 | 기기·브라우저·앱 버전, 충전·밝기·배터리 기록. 촬영 시작 | 예상 영상과 전신 식별 가능 여부, 시작 시각 |
| 1분 | 1·20·60초 지연의 표시와 초기 대기 확인 후 원하는 시험 지연으로 고정 | 타임코드가 있는 입력 영상으로 지연 오차 측정 |
| 5분 | 실시간 버퍼의 프레임 시각 범위·바이트·프레임 수 기록 | 5분 이전 영상이 계속 누적되지 않는지 확인 |
| 10분 | 앱 안에서 5·15·30초 클립 선택·저장·PIN 목록 재생 | 선택 일치·출력 길이·대기 시간·무음 확인. 촬영은 계속 유지 |
| 20·30분 | 버퍼 및 전체 메모리, 영상 갱신·발열 상태 기록 | 실시간 버퍼와 프로세스 전체 메모리를 구분. 지속 상승·화면 멈춤 기록 |
| 40분 | 최종 수치와 종료 배터리 기록. 촬영 종료 | 앱 종료·버퍼 무한 증가·심한 화면 정지 없이 완료했는지 판정 |

원격 디버깅에서 개인정보 없이 수집할 수 있는 예시:

```js
({
  sampleAtMs: performance.now(),
  frames: frameBuffer.frames.length,
  frameBytes: frameBuffer.bytes,
  bufferSeconds: frameBuffer.duration / 1000,
  selectedFrames: selectionSnapshot.length,
  jsHeapBytes: performance.memory?.usedJSHeapSize ?? null,
  state: studioState,
})
```

위 JS 힙 수치만으로 프로세스 전체 메모리, Blob·GPU·인코더 메모리를 판단하지 않는다. Chrome/Android의 외부 프로세스 측정도 함께 사용한다. 측정 수단이 없으면 메모리 검증은 미실행으로 남긴다. 온도를 읽을 수 없으면 수치 온도를 추정하지 말고 사용 중 발열 관찰만 기록한다.

화질 비교는 현재 저부하 설정 480×270·약 10fps와 별도 후보 설정으로 동일 조건에서 수행한다. 현재 코드에 없는 640×360·15fps를 사용했다고 기록하지 않는다. 설정 변경본과 재시험 결과가 있어야 비교 완료다.

## B04 — 연속 촬영 시험을 끝낸 뒤 별도로 실행

| 항목 | 실행 | 통과 기준 |
| --- | --- | --- |
| 화면 잠금 | 촬영 중 전원 버튼으로 잠금 후 복귀 | 촬영 중단·이유 표시, 자동 재시작 없음, 사용자 시작 후 새 버퍼 |
| 앱 전환 | 다른 앱으로 이동 후 복귀 | 위와 동일. 새 촬영에 중단 이전 프레임 혼입 없음 |
| 권한 철회 | 촬영 종료 후 사이트 카메라 권한을 거부로 변경하고 시작 | 이유 안내, 무한 로딩 없음, 권한 재허용 후 재시도 가능 |
| 카메라 충돌 | 다른 카메라 앱 사용 등 가능한 기기 조건에서 시작 | 오류·복구 안내. 기기가 충돌 조건을 제공하지 않으면 재현 불가로 기록 |
| 선택 중 전환 | 구간 선택과 이름 입력 후 앱 전환·복귀 | 선택 장면 유지, 실시간 촬영은 중단, 선택 재시도 또는 취소 가능 |
| 저장 중 전환 | 인코딩 중 앱 전환·복귀 | 성공 오표시·부분 클립 없음, 같은 선택 재시도 가능 |
| 수업 종료·재시작 | 촬영 종료 후 다시 시작 | 임시 버퍼·키 정리, PIN 후 새 촬영, 기존 완료 클립 유지 |
| 앱 강제 종료 | 저장 완료 후 앱을 종료하고 다시 실행 | 완료된 클립은 PIN으로 확인 가능. 미완료 저장은 성공 처리하지 않음 |

일반 Chrome 탭과 설치 PWA 결과를 따로 기록한다. 통과·실패·재현 불가·미실행을 구분하며, 개발용 Linux 이벤트 검사를 실제 Android 결과로 대체하지 않는다.
