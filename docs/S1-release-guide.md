# 교사 설치·수업 준비·업데이트 안내

이 안내는 로컬 구현과 검증 절차를 정리한다. 실제 학교 기기의 설치·40분 사용 및 외부 HTTPS 배포는 아직 확인하지 않았다. 결과와 미확인 항목은 [S1 검증 기록](stage-1-validation.md)을 따른다.

## 수업 전에 준비하기

1. 사용할 Android 태블릿의 Chrome에서 교사가 제공받은 HTTPS 주소를 연다. 처음에는 인터넷에 연결한다. 사설 IP의 일반 HTTP 주소는 카메라·보안 저장·오프라인 설치가 동작하지 않을 수 있다.
2. 화면의 오프라인 준비 상태를 확인한다. 준비 실패나 미완료 안내가 있으면 온라인에서 다시 준비한다. 홈 화면 아이콘이 생겼다는 사실만으로 오프라인 준비가 끝난 것은 아니다.
3. Chrome 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 선택한다. 설치 항목이 없으면 지원되는 Chrome과 올바른 HTTPS 주소인지 확인한다.
4. 첫 실행에서는 교사 메뉴에서 6자리 PIN을 두 번 입력한다. 이후 수업은 같은 PIN으로 연다. 교사 메뉴에서 지연 시간을 정하고 창을 닫는다.
5. 태블릿을 거치하고 **카메라 시작**을 누른다. 카메라 권한을 허용하고, 전신이 보이는지와 지연 대기가 끝난 뒤 지난 동작이 표시되는지 확인한다.
6. 최초 준비 이후 비행기 모드에서 앱을 다시 열고 PIN → 촬영 → 5초 장면 저장 → 교사 목록 재생까지 확인한다. 테스트에는 실제 학생 대신 교사의 동작이나 별도 가상 자료를 사용한다.

설치·권한·PIN 최초 생성을 마친 기기에서는 PIN 입력 → 지연 설정 → 촬영 시작의 모의 수업 준비 시간을 측정한다. 목표는 1분 이내다. 자동화 측정과 실제 교사의 준비 시간은 별도 기록한다.

## 학생이 장면을 남기기

1. 전신이 보이도록 서서 움직인 뒤 설정한 지연 시간만큼 기다린다.
2. **마음에 드는 장면 저장**을 누르고 끝나는 시점과 5~30초 길이를 고른다. 선택 화면에 표시한 구간은 입력 중에도 고정된다.
3. 이름과 번호를 입력하고 저장한다. 저장 중 앱을 전환하거나 화면을 잠그지 않는다. 실패·취소 안내가 나오면 같은 선택으로 다시 시도한다.
4. 교사는 PIN으로 저장 목록을 열고 재생한다. 수업을 마친 뒤 불필요한 자료를 삭제한다.

촬영 대기·중단·재시작 안내를 구분한다. 화면 잠금이나 다른 앱 전환으로 촬영이 중단되면 **촬영 다시 시작**을 누른다. 중단된 구간은 이어 붙이지 않는다. 임시 버퍼는 메모리에 있으므로 앱을 닫거나 다시 불러오면 사라진다.

## 새 버전 적용하기

새 버전 안내가 나와도 수업 도중 적용하지 않는다. 촬영을 종료하고 선택·PIN·목록 등의 열린 창과 저장 작업을 마친 뒤 **업데이트 준비**를 누른다. 안전하지 않은 상태에서는 작업을 마치라는 안내를 표시한다. 준비 버튼은 모든 PE Loop 탭과 설치된 앱 창을 닫고 다시 열라는 안내를 표시하며, 화면을 강제로 다시 불러오지 않는다. **모든 앱 창을 실제로 종료한 뒤 다시 실행**하면 대기하던 새 버전이 자연 활성화된다. 한 탭만 닫아서는 다른 탭의 수업이 끝나지 않았을 수 있으므로 즉시 적용을 보장하지 않는다. 저장된 클립과 PIN은 앱 셸 캐시와 별도 저장소에 유지한다.

초기 `v5` 서비스 워커에서 처음 전환할 때는 기존 버전의 캐시 정책 때문에 새 안내가 보이지 않거나 화면과 스크립트가 섞일 수 있다. 첫 전환은 수업을 마친 뒤 **모든 PE Loop 탭과 설치 앱 창을 닫고 다시 실행**한다. 브라우저 데이터 삭제로 업데이트 문제를 해결하려고 하면 클립도 잃을 수 있다. 새 코드의 업데이트 검증을 기존 v5 정책까지 소급한 보장으로 해석하지 않는다.

## 보관·PIN 분실·복구

- 원본 카메라 영상은 외부로 전송하지 않는다. 임시 영상은 최대 5분의 메모리 버퍼이고, 저장한 무음 클립만 이 기기의 앱 저장소에 암호화한다.
- 저장 후 7일 만료는 앱 실행·목록 확인·실행 중 점검 때 정리한다. 앱이 꺼진 동안 정시 삭제하거나 7일 보관을 보장하지 않는다. 브라우저의 공간 정리·기기 초기화로 더 일찍 사라질 수 있다.
- PIN은 복구할 수 없다. 분실 시 교사 메뉴의 초기화에서 새 PIN과 **모두 삭제**를 확인하면 기존 영상·이름·번호를 지우고 새로 시작한다. 기존 자료가 필요한지 먼저 확인한다.
- 저장 공간 부족 안내가 나오면 교사가 불필요한 클립을 삭제한다. 자동 정리 방지 요청은 보관 보장이 아니다. 앱 데이터·사이트 데이터 삭제는 캐시뿐 아니라 PIN과 클립도 제거한다.
- 목록을 열 수 없거나 DB 갱신이 막히면 다른 이전 앱 탭을 닫고 다시 실행한다. 비밀값·실제 학생 영상·이름을 오류 신고나 개발 로그에 붙이지 않는다.

## 배포 담당자의 사전 점검과 버전 복귀

실제 배포는 사용 가능한 HTTPS 호스팅과 접근 권한을 확보한 뒤 별도로 수행한다. 이 문서 작성만으로 외부 배포를 실행하지 않는다.

1. 정적 셸 파일을 같은 빌드로 묶고 `sw.js`의 캐시 버전을 새 값으로 올린다. 일부 파일만 순서대로 덮어쓰는 배포로 서로 다른 버전이 함께 다운로드되지 않도록 원자적 배포 기능을 사용한다.
2. 서비스 워커 파일은 재검사가 가능하도록 캐시 헤더를 설정한다. 루트/하위 경로에서 동일한 스코프와 상대 경로가 유지되는지 확인한다. 배포물에 PIN·키·학생 클립·개발용 개인정보를 포함하지 않는다.
3. 기존 버전을 사용 중인 격리된 테스트 프로필에서 새 버전 설치·대기·적용을 확인한다. 카메라/장면 선택/인코딩/DB 저장 중 유예, 다른 탭 열림, 실패 후 기존 버전 실행을 포함한다.
4. 실제 Android Chrome에서 설치, 오프라인 재실행, PIN, 촬영, 저장, 재생, 40분 사용을 확인한다. 기기 모델·RAM·Android·Chrome·배포 버전을 기록한다. 구체적인 기기 검사는 [기기 확인 절차](B03-B04-device-check.md)와 연결한다.
5. 이전 제품 코드로 복귀할 때도 이전 캐시 이름을 재사용하지 않고 **새 캐시 버전**으로 배포한다. DB 형식이 이전 코드와 호환되는지 먼저 확인한다. 현재 셸 갱신은 PIN·클립 삭제를 수행하지 않는다.

새 버전이 대기하는 동안에는 이전 캐시를 유지한다. 모든 이전 앱 창이 종료되어 새 버전이 자연 활성화될 때 `pe-loop-shell-`로 시작하는 구 앱 셸 캐시를 정리한다. PIN·클립 저장소와 다른 앱의 캐시는 정리하지 않는다. 설치 실패로 남은 캐시가 있으면 다음 정상 버전 활성화 때 함께 정리될 수 있다. 자료 보존이 필요한 기기에서 사이트 전체 데이터를 지우는 방식은 버전 복귀 절차로 사용하지 않는다.

현재 버전의 필수 캐시 파일이 손실되었다면 **다시 확인**이나 동일 워커 재검사만으로 복구된다고 보장하지 않는다. 배포 담당자가 완전한 필수 파일을 담은 **새 캐시 버전**을 준비한 후 온라인에서 설치하고, 모든 앱 창을 종료·재실행하는 경로를 사용한다. 기존 캐시에 현재 네트워크의 일부 파일만 채우면 버전이 섞일 수 있어 자동으로 그렇게 복구하지 않는다.
