# S3 학급·제출·동기화 사용 및 운영 계약

기준일: 2026-11-06 (한국 시간). 로컬 기능과 동일 호스트의 개발 허브를 구현했다. 실제 Android/LAN 운영이나 영속 서버 배포를 완료한 것은 아니다. 실행 근거는 [S3 검증 기록](stage-S3-validation.md)을 따른다.

## 교사와 학생의 사용 흐름

1. 교사가 로컬 PIN을 열고 **학급 · 제출**에서 학급, 모둠, 학생, 수업(단원·종목), 기기를 만든다. 같은 이름·번호도 서로 다른 UUID로 구분한다.
2. 학생·수업·기기·모드를 명시적으로 지정한다. 이후 저장한 클립과 성찰에는 이 ID가 암호화되어 연결된다. 기존 이름·번호만 있는 클립은 미배정 상태로 유지한다. 기존 클립의 수동 이관 UI는 제공하지 않는다.
3. 학생이 대표 클립을 직접 선택하고 성찰 포함 여부를 정한 뒤 **선택 장면 제출**을 누른다. 지정 학생·수업의 클립만 보이며 원본 카메라 스트림, 나머지 클립, 명단 전체, 관찰 메모는 전송하지 않는다.
4. 허브 참여 전에는 이 기기의 암호화 대기열에 저장한다. 참여 후 명시적 동기화 또는 재연결 때 이미 선택한 자료만 재전송한다. 대기·전송 중·완료·실패를 구별한다.
5. 교사는 로컬 학생 이력·관찰 메모와 허브 선택 제출을 확인한다. 학생의 칭찬·텍스트 피드백은 승인 대기로 시작한다. 교사가 공개 승인하거나 숨기며, 동료에게는 같은 수업의 승인된 글만 공개한다. 다른 학생 영상은 공개하지 않는다. 음성 피드백은 구현하지 않았다.

## 로컬 보관과 삭제

- 클립·이름·번호·성찰과 학급·명단·관찰·대기열은 로컬 PIN에서 파생한 AES-GCM 키로 암호화한다. S3 문서는 기존 IndexedDB v2의 `meta/classroom`에 넣으며 별도 평문 개인정보 저장소를 만들지 않는다.
- 모든 신규 학급 기록은 기본 최대 7일이다. 교사가 PIN으로 다시 열 때 만료 기록과 종속 항목을 정리한다. 제출 만료 상한은 원본 클립 만료와 제출 후 7일 중 빠른 시각이며 학급·학생·수업 삭제/만료로 더 일찍 철회될 수 있다. 무기한 포트폴리오 보관은 제공하지 않는다.
- 원본 클립 삭제는 연결 제출·성찰·전송 사본도 정리하고 허브 삭제를 대기열에 담는다. 제출만 철회하면 원본 클립은 유지한다. 전송 확인 후 불필요한 로컬 영상 사본은 제거한다.
- **이 기기의 학급·명단·수업 삭제**는 로컬 명단·관찰을 지우고 이 기기에서 작성한 제출·글을 철회 대기한다. 최소 ID의 ‘삭제 대기 학급’을 남긴다. 그 학급으로 허브 교사 연결 후 **삭제 대기 자료를 허브에서 철회**를 눌러 재시도한다. 다른 기기의 학급 전체 자료를 일괄 삭제하는 기능은 아니다.
- 삭제 대기 ID/작업도 최장 7일 후 정리한다. 허브 선택 자료 역시 최대 7일이며, 허브는 다음 요청 시 만료를 정리한다. 앱을 열지 않은 기기의 브라우저 저장소는 다음 PIN 열기까지 암호문이 남을 수 있다.
- PIN 초기화는 클립·암호화 S3 문서·vault를 같은 IndexedDB 트랜잭션으로 지운다. 이전 revision의 읽기·쓰기는 거부한다. 잠금/초기화는 현재 연결을 중단하고 다른 탭에 종료를 알린다. **이미 허브가 받은 자료는 초기화로 지워지지 않는다.** 초기화 전에 허브 자료를 별도로 삭제해야 하며, 네트워크 단절이나 이미 처리된 요청의 소급 철회는 보장하지 않는다.

## 개발용 허브 실행과 참여

Node.js 외 서버 의존성은 없다. 운영자가 별도 터미널에서 24자 이상의 새 `PE_HUB_SECRET`을 환경변수로 제공한 뒤 실행한다. 비밀값을 저장소·URL·공유 로그에 넣지 않는다.

```sh
node server/classroom-hub.js
```

기본 주소는 `http://127.0.0.1:8787`이며 `PE_HUB_PORT`로 포트를 정한다. UI 정적 서버도 같은 컴퓨터의 localhost/127.0.0.1에서 연다. 교사 콘솔의 개발 허브 주소와 **허브 교사 비밀값 (PIN과 별개)**을 입력해 연결한다.

- 교사 허브 비밀값과 로컬 6자리 PIN은 별개다. 허브 교사 세션은 학급에, 학생 세션은 학생·수업·기기에 제한한다. 세션은 8시간 후 만료하며 로그아웃은 토큰 폐기를 요청한다.
- 교사가 선택한 학생에게 10분·1회용 QR 참여 자격을 발급한다. QR에는 허브 주소와 단기 참여 자격만 넣고 PIN·키·명단·장기 교사 토큰을 넣지 않는다. URL fragment를 읽은 뒤 즉시 `history.replaceState`로 제거한다. 수동 참여 데이터 붙여넣기도 가능하다.
- 새 학생 브라우저는 교사가 로컬 PIN을 먼저 준비해야 한다. 참여 후 자기 학급/학생/수업/기기의 최소 ID만 생성하며 전체 명단은 받지 않는다. 이름·번호는 자기 기기에 한 번 저장하면 다음 촬영부터 기본 입력한다. 이 표시 정보는 허브로 보내지 않는다.
- 교사 모드 배포는 선택 기기/수업의 개인 연습 또는 모둠 스테이션 모드를 갱신한다. 참여 기기에서 동기화할 때 반영된다. 실시간 푸시나 자동 기기 발견은 제공하지 않는다.

**이 허브는 loopback 개발용이다. 선택한 WebM·성찰·글을 HTTP로 받아 RAM에 평문 보관하며, 재시작하면 모두 사라진다. 실제 학생 자료를 넣어 운영할 영속 암호화 서버가 아니다.** 다른 태블릿에서 `127.0.0.1`은 그 태블릿 자신이므로 이 QR로 교사 컴퓨터에 연결되지 않는다. 실제 LAN/HTTPS 호스팅·기기 신뢰·영속 암호화·운영 인증은 외부 운영 조건으로 남는다.

## 동기화와 권한 계약

- 암호화 문서의 버전 비교와 vault revision으로 동시 덮어쓰기·초기화 후 옛 문서 복원을 거부한다. 충돌을 이름·번호로 자동 병합하지 않는다.
- 각 작업은 안정 operation ID를 가진다. 응답 유실 시 같은 ID와 같은 본문으로 재전송하며 서버 중복 수신은 한 번만 반영한다. 같은 ID의 변경 본문은 409로 거부한다. 삭제 tombstone은 늦은 제출의 부활을 막는다.
- 요청/JSON 응답은 기본 10초 제한이다. 한 항목 실패가 다른 항목 전송을 막지 않고, 실패 항목은 동일 자료로 재시도한다. 잠금 뒤의 늦은 결과는 현재 DOM/암호화 문서에 반영하지 않는다.
- 허브는 학급 경계와 학생 세션의 학생·수업 범위를 매 요청 검증한다. 학생은 자기 제출과 자기 미승인 글, 같은 수업의 승인 글만 읽는다. 명단·관찰은 허브 API에 전송하지 않는다.
- 서버는 수신 시각+7일 상한, 신고된 `clipExpiresAt`, 제출 만료와 삭제 ID를 검증한다. 원본 생성 시각은 클라이언트 신고값이므로 악의적인 클라이언트의 원본 시각을 암호학적으로 증명하는 기능은 없다.

QR 생성기는 `qrcode-generator` 1.4.4([MIT 고지](../qrcode-generator.LICENSE))를 로컬 셸에 포함했다. 실행 시 외부 CDN이나 네트워크 QR 서비스에 접속하지 않는다.

## S4.5 로컬 동작 이력 schema와 연결

S4.5는 기존 IndexedDB v2의 PIN 암호화 `meta/classroom` 문서에 선택 배열 `shotAttempts`를 추가한다. 이전 문서에 배열이 없어도 빈 이력으로 취급하며 DB를 재생성하거나 기존 학급 자료를 평문 저장소로 옮기지 않는다. 문서의 기존 버전 비교와 vault revision을 그대로 사용한다.

한 이벤트에는 UUID `id/classId/studentId/lessonId/deviceId`, 추론 입력 시각 `inputAt`, 저장·만료 시각 `createdAt/expiresAt`, 선택 팔·민감도·2D 팔꿈치 각도, 손목/몸통 상대 비율, 임계값과 규칙 버전, 전신 gate 통과와 최소 visibility/선택적 presence, 모델 버전과 입력 치수만 보관한다. presence 미제공은 `null`로 남긴다. 이름·PIN·원본 프레임·이미지·전체 관절 배열·연속 궤적은 이벤트에 넣지 않는다.

교사 PIN으로 유효한 학급·학생·수업·기기를 지정하고 기록을 명시적으로 켜야 한다. 설정 창의 닫기(X)는 촬영용 복호화 세션을 유지하므로 기록도 계속될 수 있고, 「잠그기」·촬영 중단·화면 이탈·연결 변경은 기록을 끈다. 기록은 다음 실행에 자동으로 켜지지 않는다. 조회 필터는 촬영 학생 지정을 바꾸지 않으며 교사 PIN 뒤에서 학급·학생·수업별 최근 100건을 표시한다.

보관 상한은 입력 후 7일·저장 후 7일·네 부모의 유효기한 중 가장 이른 시각이다. 기기 전체 최대 2,000건이며 만료 항목만 정리한 뒤에도 가득 차면 새 기록을 거부하고 안내한다. 유효한 기존 이력을 조용히 지우지 않는다. 저장 중 다른 이벤트가 도착하면 무제한 대기열을 만들지 않고 이번 기록 생략을 안내한다.

로컬 클립 연결은 기록과 같은 학급·학생·수업·기기의 클립을 교사가 목록에서 고른 뒤 별도 연결 버튼으로 확정한다. 연결 후 기한은 클립보다 길 수 없다. 저장 직전 클립 존재와 기한을 `clips/meta` 단일 트랜잭션에서 다시 검사한다. 클립 삭제는 연결 이력도 제거하며, 중간 실패로 남은 연결은 이력 다시 읽기에서 정리한다. 부모 삭제·만료·삭제 대기 및 PIN 초기화도 해당 이력을 정리한다.

기록은 암호화 후와 IDB 저장 직전 세대·키·현재 바인딩을 재검사하고 중단 신호로 취소한다. 충돌·저장 실패를 자동 재전송하지 않으며 기본 촬영은 계속된다. `shotAttempts`는 허브·outbox·대표 클립 제출 payload에 추가하지 않는다. 이번 S4.5에는 이력의 원격 제출 기능이 없다. 자세한 사용법과 검증은 [이력 안내](S4-history-guide.md), [S4.5 검증 기록](stage-S4-history-validation.md)을 따른다.
