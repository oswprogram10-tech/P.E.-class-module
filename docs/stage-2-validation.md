# 2단계 — 클립 선택·저장 구현과 검증

## 현재 판정

C01~C04의 구현과 개발용 브라우저 검증을 완료했다. 갤럭시 탭 A9+에서의 WebCodecs 지원·인코딩 성능·실제 뒤로 가기 동작은 미검증이다. 0·1단계의 실제 기기 검증 대기도 그대로 유지한다.

## 작업별 변경

| 작업 | 구현 | 확인한 결과 |
| --- | --- | --- |
| C01 구간 선택 | 창을 연 시각과 스냅샷 고정, 시작·끝 시각 표시, 부족한 범위·중간 단절 구간 거부 | 입력 중 선택 시각 유지. 알려진 시각별 색상 영상에서 출력 시작·중간·끝이 선택한 구간과 일치 |
| C02 화면 분리 | 미리보기와 인코더가 각각 별도 캔버스 사용. 미리보기 디코딩 후 선택 토큰 재확인 | 이전 선택의 느린 디코딩이 새 선택 화면을 덮어쓰지 않음 |
| C03 정확한 영상 생성 | WebCodecs VP8 인코딩과 좁은 범위의 WebM 작성기 도입. 각 프레임에 100ms 간격·길이 부여 | 선택 5·15·30초에서 실제 파일 패킷 끝 시각이 각각 5·15·30초. 비디오 트랙만 존재하고 30초를 넘는 패킷 거부 |
| C04 저장 흐름 | 이름·번호 검증, 중복 요청 방지, 진행 표시, 명시적 취소, 커밋 중 취소 차단, 원자적 DB 기록, 실패 후 같은 선택 재시도 | 입력 오류·중복 클릭·취소·인코더 미지원·손상 이미지·공간 부족·재시도 검사 통과 |

이전 MediaRecorder 방식은 종료 타이머와 인코더의 프레임 마감으로 30.060초 파일을 만들 수 있었다. 새 방식은 입력 프레임 개수나 실행 경과 시간을 영상 길이로 사용하지 않고, 선택한 구간의 원본 시각을 10fps 출력 시각에 대응시킨다. 30초 파일은 0~29.9초의 300개 프레임과 각 0.1초 길이로 구성한다.

## 구현 모듈

- `timeline.js`: 선택 범위·경계·중간 단절 검증과 주어진 시각의 프레임 검색.
- `clip-exporter.js`: 작업별 전용 캔버스, VP8 인코딩, 명시적 타임스탬프, 진행·취소·자원 정리.
- `webm-muxer.js`: VP8 영상 한 트랙의 WebM 작성. 기간·프레임 시각을 검증하고 인코더의 색상 범위·행렬 정보를 기록.
- `app.js`: 고정된 선택, 입력 검증, 저장 상태, 암호화와 DB 트랜잭션, 취소·실패·성공 표시 조정.

새 WebM 작성기는 임의의 미디어 파일을 편집하는 범용 도구가 아니다. 앱이 생성한 640×360·10fps VP8 무음 클립에 사용한다. Codec이 지원되지 않으면 잘못된 길이의 파일로 우회하지 않고 지원 안내와 재시도를 제공한다.

## 저장 상태

`selecting → encoding → encrypting → committing → succeeded`

- encoding·encrypting 중에는 구간 변경·중복 저장·앱 내 닫기를 차단하고 ‘저장 취소’를 제공한다.
- 취소하면 인코더를 해제하고 편집을 다시 열며 선택한 구간·학생 입력을 유지한다. DB에 파일을 추가하지 않는다.
- committing은 짧은 트랜잭션 구간이며 사용자 취소 버튼을 비활성화한다. 실행 중 중단 신호는 가능한 경우 트랜잭션을 abort한다. 이미 커밋된 기록은 완료된 저장으로 취급한다.
- 실패하면 cancelled 또는 failed 상태와 복구 안내를 표시한다. 공간 부족은 교사 정리 후 재시도하도록 안내한다.
- DB 커밋과 화면 닫기를 분리해, 저장이 완료된 뒤 UI 오류를 저장 실패로 잘못 처리하며 중복 기록을 만들지 않도록 한다.
- 앱 강제 종료·브라우저 이탈을 완전히 차단할 수는 없다. 앱 내 닫기 차단 및 브라우저가 지원하는 종료 경고를 적용한다.

## 검증 방법

1. Node 회귀 검사: 선택 범위·빈 버퍼·중간 누락, EBML 길이 경계, 과도한 파일 길이·잘못된 프레임 시각 거부.
2. `tests/browser-smoke.cjs`: 가상 카메라에서 5·15·30초를 저장·복호화한 뒤 ffprobe로 실제 파일의 패킷 끝 시각과 트랙 구성을 확인.
3. `tests/browser-clips.cjs`: 알려진 시각별 색상 스냅샷으로 선택한 시작·중간·끝을 확인. Chrome에서 실제 출력 파일을 재생·탐색하여 픽셀을 비교하고, 파일의 선언된 색상 범위를 적용한 FFmpeg 디코딩도 비교.
4. 같은 검사에서 느린 이전 미리보기, 인코더 중도 취소·손상 이미지·지원 불가, 입력 오류·중복 요청·명시적 취소·공간 부족 후 재시도를 확인.
5. `tests/browser-camera.cjs`: 카메라·화면 중단, 기존 선택 보존, 복귀 후 저장 재시도 회귀 확인.

클라우드 Linux Chromium 155.0.8059.79에서 실행했다. 가상 테스트 영상만 사용하고 출력 임시 파일은 검증 후 삭제한다.

| 선택 길이 | ffprobe 패킷 끝 시각 | 영상 트랙 | 오디오 트랙 |
| --- | ---: | --- | --- |
| 5초 | 5.000초 | VP8 | 없음 |
| 15초 | 15.000초 | VP8 | 없음 |
| 30초 | 30.000초 | VP8 | 없음 |

직접 실행한 Node 단위 검사 9개가 통과했다. 저장 트랜잭션을 실제로 abort하는 검사에서도 부분 레코드가 남지 않았다. 손상 이미지·지원 불가·취소 후에는 정상 인코딩·저장을 다시 수행해 복구 가능 여부를 확인했다.

## 남은 기기·운영 검증

- A9+에서 VP8 VideoEncoder·VideoFrame 사용 가능 여부와 저장 대기 시간·발열·전체 메모리 측정.
- 실제 Android 뒤로 가기·키보드·화면 잠금 중 저장 상태 확인.
- 학교 기기의 Chrome 정책과 HTTPS 배포 환경에서 인코더·로컬 저장 동작 확인.
- PIN 수명·손상된 기존 목록·7일 만료·저장 공간 관리는 3단계에서 확장 검증.

색상 비교에는 파일에 기록된 전체 범위 BT.709 정보를 사용한다. 일부 FFmpeg VP8 디코딩 경로는 선언된 범위와 다른 기본 변환을 적용할 수 있어, 외부 픽셀 검사에서는 선언된 범위를 명시했다. 앱에서 사용하는 Chrome 재생기의 직접 비교도 함께 통과해야 한다.
