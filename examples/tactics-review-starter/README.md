# 교사가 검토할 전술 예제 48개

작성·인터넷 출처 확인: **2026-11-12**. 학교 체육의 가상 상황을 놓고 학생에게 어떤 행동을 할지 묻도록 직접 만든 합성 예제다. **48개 모두 교사 검토 전**이며 공식 단체의 정답, 실제 경기 자료, 실제 학생 수행 자료, 검증된 학습 데이터가 아니다. 현재 실제 프로·국가대표 경기 사례 찾기 기능의 참고자료나 비교 학습 기록으로 사용하지 않는다. 인터넷의 훈련안·그림·문장을 복제하거나 번역해 만든 자료가 아니다.

## 바로 사용하기

1. **[review-pack.html](review-pack.html)**을 브라우저로 연다. 한 파일로 작동하며 별도 서버·Ollama·인터넷 연결이 필요하지 않다.
2. 전술판과 좌표 목록을 확인하고 관찰·이유·진행 단계·안전 안내 초안을 수정한다. 입력에는 공·골대·네트·공격 방향·시간·키/능력 정보가 없다. 보이는 도형만으로 설명 가능한지 확인한다. 배구 그림에도 네트로 오인할 수 있는 중앙선을 그리지 않았다.
3. 여섯 검토 항목과 사례별 질문을 확인한다. 적절하면 교사의 역할·별칭을 입력하고 **교사 승인**을 선택한다. 부적절하면 **수정 필요**로 남긴다. 답변을 수정하면 승인과 검토 체크가 초기화되어 다시 확인해야 한다.
4. **검토 기록 JSON 저장**으로 수정 답변과 검토 결과를 보관한다. 화면을 닫거나 새로고침하면 작업 내용은 사라지므로 먼저 저장한다. 이후 **검토 기록 불러오기**로 이어갈 수 있다. 다른 버전 묶음의 기록은 섞지 않는다.
5. **승인한 합성 수업 예제 JSONL**은 이 오프라인 검토 화면에서 승인한 항목만 내보낸다. 검토자 별칭과 메모는 모델 메시지에 포함하지 않는다. 이 파일은 현재 실제 경기 사례 찾기 기능의 학습 형식과 별개다. 파일을 내려받는 것이 모델 학습을 실행하는 것은 아니다.
6. **평가 전용 사례 JSON 저장**은 평가용 12개만 내보낸다. 승인 여부와 무관하게 학습 내보내기에서는 제외된다. 평가 답안도 승인 전에는 초안이다. 평가용 입력을 학습에 넣지 말고 실제 교사가 기대 답변·기준을 검토한 뒤 비교에 사용한다.

개인 학생·학교명·학급명·건강·성적·GPS 좌표·실제 영상은 넣지 않는다. 좌표는 1000×600 전술판의 추상 단위이며 실제 미터가 아니다. 웹 출처는 원리 확인용으로만 제시하며 답변의 전술적 적합성과 학교 안전성은 교사가 확인해야 한다. 질문에 보이지 않는 배경 정보를 답변에 추가하지 않는다.

관리 브라우저에서 로컬 HTML 열기가 제한되면 저장소 루트에서 `python3 -m http.server 8080 --bind 127.0.0.1`로 정적 파일을 제공하고 `http://127.0.0.1:8080/examples/tactics-review-starter/review-pack.html`을 연다. 자동 브라우저 검사도 이와 같은 loopback 방식을 사용한다.

## 파일

| 파일 | 용도 |
| --- | --- |
| `review-pack.html` | 전술판·답변 수정·교사 검토·승인된 JSONL 내보내기. 모든 데이터가 포함된 오프라인 화면 |
| `review-sheet.csv` | 엑셀 등에서 볼 수 있는 UTF-8 BOM 검토표. CSV 수정 결과를 HTML에 자동으로 불러오는 기능은 없음 |
| `draft-cases.jsonl` | 익명 배치·답변 초안·미검토 표시·출처·사례별 검토 기준. **학습 준비 완료 파일이 아님** |
| `sources.json` | 실제 열어 본 인터넷 출처·관련 부분·이용조건 확인 범위·제외한 링크 |
| `manifest.json` | 개수·묶음 ID·파일 SHA-256. 교사 승인/학습 완료가 0건임을 표시 |
| `scenarios.cjs` | 저장소에서 재생성하는 원본 합성 사례 정의 |

이 자료들은 공개된 코칭 자료이며, 이 가상 질문을 교사 검토 완료 전술판 사례로 승인하거나 경기에서의 정답을 뜻하지 않는다. 전문 경기 전술·최신 규칙·의학 지침을 이 예제에서 다루지 않는다. 원문 PDF나 그림은 묶음에 넣지 않았고 짧은 출처 정보와 링크만 기록했다. FIVB의 오래된 미니배구 PDF 주소는 검색 결과에 있었지만 직접 열기에서 404여서 채택하지 않았다.

국내 교육과정과 추가 협회·코치 자료를 대조한 전술 주제 및 현재 전술판 입력의 한계는 [농구·배구 전술 자료 조사](../../docs/tactics-research.md)에 정리했다.

## 앱·추가 학습과 연결

내보낸 학습 JSONL은 현재 `server/tactics-llm.js`의 프롬프트와 참고자료 구조에 맞춘다. 기본 자료 ID인 `spacing`, `passing`, `defense`, `basketball`, `volleyball`, `safety`를 사용한다. 교사가 답변을 승인해도 기본 참고자료 자체의 `draft` 상태를 자동 변경하지 않는다. 참고자료 원문 검토와 사례 답변 검토는 각각 수행한다.

실제 추가 학습에는 이 36개로 충분하다고 보장할 수 없다. 우선 설명 형식과 검토 절차를 확인하는 시작 묶음으로 쓰고, 검토된 다양한 사례를 보충한다. 모델 성능은 별도의 평가용 사례와 실제 수업 조건에서 확인한다. 앱의 서버 학습 예제 저장소에 이 초안을 자동 등록하거나 기존 모델을 변경하지 않았다. 추가 학습 준비는 [GPS·공유·로컬 LLM 안내](../../docs/S5.7-S5.8-connected-guide.md)를 따른다.

## 재생성과 검사

저장소 루트에서:

```sh
node scripts/build-tactics-review-pack.cjs
node tests/browser-tactics-review-pack.cjs
```

생성 시 48개 형식·앱 호환성·미검토 표시·분할·기하 중복을 검사한다. 브라우저 검사는 승인 전 내보내기 차단, 평가 사례의 학습 제외, 수정 시 승인 초기화, 검토 기록 불러오기/저장, 좁은 화면과 외부 요청 없음을 검사한다. 코칭 적합성 검증을 대신하지 않는다.

2026-11-12: 생성 검사와 브라우저 검사 통과. 이 묶음의 오프라인 검토 화면이 JSONL을 내보내는지 확인했다. 브라우저 검사에서 사용한 모의 승인 결과는 이 묶음에 저장하지 않았으며, 배포한 48개는 모두 검토 전이다. 실제 경기 사례 모델 추론·추가 학습과 실제 교사 검토는 실행하지 않았다.
